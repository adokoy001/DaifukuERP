# Workforce backend / 共通拠点権限と勤怠・給与

- 仕様: [workforce-backend-contract](../specs/workforce-backend-contract.md)、[ADR-0019](../adr/0019-workforce-access.md)
- 実装: `modules/workforce`、kernelのContext/DSL/会社所属/Repository共通拠点境界

## 変更

業界非依存の拠点と利用者に紐付く従業員、元打刻、日次勤怠と訂正承認、有給の付与・申請・消費/返還台帳、従業員経費、期間付き制度/賃金条件、給与明細と依存期間の凍結を13 entityで定義した。状態・金額・時刻・確認者はserverOwnedと非公開のwrite capabilityで守り、汎用CRUDから承認/精算/給与確定を作れない。

会社所属にsites/siteIdsを追加し、旧stores/storeIdsをそのまま維持する。新sitesでは両方の明示リストを併用でき、各entityの宣言に応じた集合を会社・本人ルールとANDする。空集合、未宣言entity/action、会社外参照は許可へフォールバックしない。所属移行は空siteIdsの追加のみで権限を広げない。

4つの労務ロールは従業員登録があれば本人の打刻・申請を利用できる。manager/hrの給与読取は本人の確定済明細に限定した。payrollの会社全体給与権限を持つ人も自分の給与確定・取消はできない。拠点承認・有給承認・経費精算は受益者本人を拒否する。

打刻時刻を丸めずに保存する。退勤時の休憩不足は事実保存を妨げず承認で検査し、24時間超の退勤忘れは元打刻を残して訂正申請から回復できる。隣接勤務の実時刻重複、全日/半日合算有給との競合、確定後の元データ変更を拒否する。

給与は日週時間外の重複を避け、月60時間超、法定休日、深夜の加算を分ける。月初週の前月勤怠も計算・凍結対象に含め、給与月の重複と依存日付の重複を区別する。通常賃金・割増賃金の合計を円単位で切り上げ、月給按分の除算は合計後に1回だけ行う。税社会保険など8控除名目の外部算定額・根拠・明示確認が揃わなければ確定しない。

確定期間の内容を変える制度・条件・在籍日変更を防ぎつつ、過去の適用範囲が同じ将来退職・制度終了日の短縮・新しい昇給条件は登録できる。JST暦日をまたぐ勤務の自動給与は暦日別休日モデル未対応を明示して止める。原本打刻と承認結果は保持する。

## 検証

- 独立したPostgreSQL 16専用DBで勤怠5件、給与7件、本人ロール/マスタ3件、有給/経費9件、kernelの新拠点境界3件を検証した。
- 純粋関数17件は独立レビューと期待値で確認。日週時間外、月60時間、前月週境界、深夜休憩、月給の入退社・改定・31日全額、時給有給、秒単位の金額集計、JST暦日境界を含む。
- 型検査、対象ESLint、依存境界検査を実施。全体API/MCP/UI/導入移行との統合結果は[全体仕様](../specs/workforce-platform.md)と統合検証記録に記載する。
- 新しい権限契約に合わせ、manager/hr給与の試験は操作自体の拒否から「本人以外の給与が0行」の検査へ変更した。未入力控除の確定拒否、自己承認拒否、所有フィールドの汎用書込拒否は維持した。

## 対象外

給与の自動税社保算定、年末調整・申告・銀行送信、法定休日をまたぐ勤務の自動給与、時間単位有給、変形/フレックス等の労働時間制は提供しない。国内通常制の適用・休日・雇用条件・年休資格/期限・外部控除の確認は会社側の明示作業とする。

## 画面検証からの追補

拠点管理者の会社切替でテンプレート一覧が必要なため、読取専用`pack.list`にsites/stores両scopeを明示した。公開カタログと選択中の会社の適用名/版/日時だけを返し、別会社の適用状態は混ぜない。`pack.apply`は公開せず、直接`applyPack`も非all scopeを入口で拒否する。

追加の専用PG16回帰2件で、拠点/店舗/空集合からの一覧、会社A/Bの適用状態分離、非allのadminロールを含む適用拒否を確認した。既存pack単体12件、型検査と対象ESLintも通過。

## 内部保存先の出力境界

証憑の保存先キーに対し、従来の`hidden`だけでは汎用API/監査から値が返る問題を確認した。既存hiddenの意味を変えず、SQL schema変更のないDSL option `outputHidden`を追加した。管理者を含む全ロールで公開JSON schema・metadata・汎用CRUD応答・明細・監査保存/読取から除去する。過去の監査snapshotも読取時に除去する。

内部Repositoryの取得値はdownload処理のため保持する。非公開項目のfilter/order/count条件/aggregate/groupと検索による推測は拒否または対象外とする。登録extの非公開項目、および非公開extを含むJSON全体の集計にも適用する。独自action/reportの別名投影や任意JSONは各moduleの公開DTO責任とし、[権限設計](../architecture/permissions.md)へ適用範囲を記録した。

専用PG16の`output-hidden.db.test.ts`5件で全CRUDと伝票ライフサイクル・明細・内部値保持・メタデータ・検索/集計・監査の新旧両snapshotを確認した。値の漏れを確認した既存hiddenは、そのまま公開されるという従来契約も併せて検証した。

関連する既存kernel単体47件とRepository・Document・permissions・extを含むDB5ファイルは再実行して通過した。型検査、対象ESLint、依存境界検査も通過した。
