## 決めたこと（と理由）

- **spec 批評の 15 件はすべて採用した**（spec の「spec 批評への対応」の表、決定事項 16〜24）。退けたものは無い。主なもの:
  - 受信箱の読取はホームで 1 つにした。`useInbox()` は `HomePage` で 1 回だけ呼び、結果を `InboxCardView`（`InboxCard` から表示部分を分けた）、店舗ビューの未提出カード、「更新」ボタンへ props で渡す。`INBOX_QUERY_OPTIONS` は `staleTime: 0` で `refetchOnMount` が既定の true のため、2 つ目の observer を後から mount すると全提供元を読み直すから。
  - 帳票の `meta.truncated`（`purchase.ap_aging`、`accounting.trial_balance`）と `sales.ar_aging` の件数超過（`INVALID_STATE`）は合計として出さず「件数が多いため帳票で確認してください」にした（再試行は出さない）。`ar_aging` がこの action で出す `INVALID_STATE` は件数超過だけであることをコードで確かめた（`modules/sales/src/actions/ar-aging.ts`）。
  - `general`（全体）は役割のビューに常に添える。役割が 1 つでも [役割, 全体] の切替が出る。全体を予備にして切替を出さない案は、経理・店長だけの利用者から「伝票の状況を確認」（ホームにしか無い）を奪うため採らなかった。
  - ログイン直後に従業員だけの利用者を `/me` へ送る既存の転送は変えない。AC-11 の「自動転送しない」はホームを開いたときの話。
  - UI キットの `Tabs` は自動選択のため、矢印キーで移るたびにビューが mount される。切替で選んだビューは選択が 300 ms 続いたときに読み（`SWITCH_SETTLE_MS`）、離れたビューの読取は TanStack Query の `signal` で中止する。最初の表示は待たない。
  - 「導入・管理」カードを B3（`/admin/health`）と B4（`/setup`）の差込口にした。カタログに入口があるときだけリンクが出るので、B3・B4 が `navigation-data.ts` に入口を足せばコードの変更なく現れる。B3・B4 のコードは import していない。
- **カードの状態は「読取の集まり」から決める**（`cardStateOf`）。1 枚に複数の読取がある（現金預金 = 科目の一覧 + 試算表、勤怠 = 分析カタログ + スナップショット、シフト = 拠点一覧 + 最大 3 件の shift_board）。どれかが失敗なら失敗（再試行は失敗した読取だけを読み直す）、読込中が残れば骨格、すべて揃えば本文。分析カタログはカードの有無（AC-19）を決めるため、店舗ビューの単位で読む。
- **403 の `/meta` 読み直しは `metaRecheckOnce` で 1 回に限った。** カードごとに 1 回ではなく、ホームを開いている間に 1 回（複数のカードが同時に拒否されても `/meta` は 1 回）。
- **金額の表示は会社通貨の桁**（`useCurrencyScale`）に、日本語で JPY なら「円」、それ以外は通貨コードを添える。会社通貨のコードを部品から読むため `api/company.tsx` に `useCompanyCurrency()` を足した（既存の context の値を返すだけ）。
- **画面の見出しの階層**: ホームの h1、受信箱と各ビューの見出しが h2（「経理の今日」「店舗・拠点の今日」「自分の仕事」「導入・管理」、全体は既存の「業務分野から始める」）、カードが h3。
- **help.ts は変えない。** ホーム `/` は新しい画面ではなく、`help.test.ts` が「章の無い画面」としてホームを固定しているため（ヘルプの導線は画面の位置表示が担い、ホームには出ない既存の扱い）。
- **ADR は作らない**（spec 決定事項 15）。kernel・DSL・API・port の変更は無い。

## 見つけた問題と修正（発見経路つき）

- 兼務者を拠点限定（`accessScope: 'sites'`）で作ろうとして API が拒否（経理は拠点に限定できないロール）— 発見: ブラウザ試験の準備、修正: 兼務者は会社全体の所属にした。
