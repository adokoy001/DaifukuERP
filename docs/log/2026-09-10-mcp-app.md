## 決めたこと（と理由）
- SDK は低レベル `Server`（`@modelcontextprotocol/sdk/server/index.js`）＋明示的な request handler。`McpServer` の高レベル API は zod スキーマを内部で JSON Schema 化するため、kernel 由来の `z.custom`/`transform` を含むスキーマの変換を自前で制御できない。
- zod → JSON Schema は `z.toJSONSchema(input, { io: 'input', unrepresentable: 'any', override })`。`override` で (a) union 内の `z.custom`（kernel の Decimal 入力 `string | Decimal`）を落として `string` にする（JSON では Decimal インスタンスは届かないので意味は変わらない）、(b) `z.coerce.date()` を `string/date-time` にする。変換不能・object でないスキーマは `{ type: 'object' }` にフォールバックし、対象アクション名を warn ログに出す。クライアント側 draft-07 バリデータ対策で `$schema` は除去。
- ツール名は `toolNameOf(action.name)`（`.`→`_`）。逆変換は推測せず、registry を走査して一致するアクションを探す（`_` を含むモジュール名でも壊れない）。
- description は spec 通り `${en}\n${ja}\nmutates: yes|no`、`annotations = { title: action.name, readOnlyHint: !mutates }`。title に REST 側の正規名（`partner.list`）を入れ、OpenAPI と突合できるようにした。
- ツール呼び出しは 1 回ごとに `withContext(app, { ...params, requestId: newId() })` でトランザクション。DaifukuError は `isError: true` ＋ `toBody()`、それ以外の例外は stack を stderr ログに出し、エージェントには `INTERNAL` ＋ `details.requestId` だけ返す（内部情報を漏らさない）。
- リソースは `daifuku://meta` と `daifuku://entities/<name>` を `resources/list` に列挙し、`resources/templates/list` に `daifuku://entities/{name}` を出す。未知のエンティティは `McpError(InvalidParams)`（SDK の McpServer と同じ流儀）に `{code:'NOT_FOUND', hint}` を添える。
- stdio のログは kernel の `consoleLogger`（stderr）。`StdioServerTransport` は stdin EOF を監視しないため、`process.stdin.on('end')` と SIGTERM/SIGINT で DB を閉じて exit(0)（ゾンビ化防止）。
- テストは modules/partner に依存せず、`apps/mcp/test/fixtures/entities.ts` の `mcp_test_item`（entity）/`mcp_test_order`（document）/`mcp_test.*`（action）で行う。spec AC-5 の `partner_list`/`partner_create` は名前を `mcp_test_item_list`/`mcp_test_item_create` に読み替えた（同じ generic CRUD 経路）。
- `src/modules.ts` の `import '@daifuku/mod-partner'` は、作業終了時点で `modules/partner/src/index.ts` が存在し tsc を通ったので有効化した。

## 見つけた問題と修正（発見経路つき）
- kernel: フィールド群（`fieldGroups`）でマスクされるロールで `<entity>.list/get` を呼ぶと、Repository がマスク列を**キーごと**落とすのに対し generic アクションの output（`entity.schemas.json`）は全列必須のため、`INTERNAL: action mcp_test_item.list returned an invalid result`（`items.0.secretNote: expected string, received undefined`）になる — 発見: 実測（viewer ロールのテスト）。修正: kernel は触れないので未修正。テストは `mcp_test.count_items` で read 許可を確認する形にし、コメントで理由を明記。提案: `kernel/src/dsl/entity.ts:48` で `buildSchemas(cfg.fields, { ext, document, maskable: new Set(Object.values(cfg.permissions.fieldGroups ?? {}).flatMap((g) => g.fields)) })` を渡し、`kernel/src/db/zod.ts#buildSchemas` で `maskable` に含まれる列の `json[name]` を `.optional()` にする。
- repo 設定: `.dependency-cruiser.cjs` の `no-cross-package-internals` が kernel の公開 export `@daifuku/kernel/testing`（package.json `exports['./testing']`）を内部 import と誤検知する — 発見: 実測（depcruise）。修正案: 同ルールの `pathNot` に `'^kernel/src/testing\\.ts$'` を追加（1 行）。modules/partner のテストも同じ import をしているので共通の問題。
- 自分の実装: `StdioServerTransport` が stdin EOF で close しない — 発見: レビュー（SDK ソース）。修正: main.ts で `stdin 'end'` を監視して終了。テスト `AC-1 exits cleanly when the client closes stdin` で実測。
