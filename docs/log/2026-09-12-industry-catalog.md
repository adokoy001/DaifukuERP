# 2026-09-12：15業界カタログの履行案件

担当範囲: `modules/industry-operations`、`packs/industry-catalog`、業界カタログ仕様・選定根拠・付録G、Webテンプレートの説明と絞り込み。

## 実装

- 既存5業界に、卸売・製造・建設・運輸物流・宿泊・クリニック一般運営・介護サービス一般運営・教育・専門サービス/IT受託・美容サロンを追加。技術用 example は業界数に数えない。
- 共通エンジンを使う10個の独立パック・伝票・40操作を登録。固有の実列、業界ごとの数量/証跡条件、固定単位、支払期日設定、下書きサンプルを持つ。パッケージの import だけでは全パックを登録しない。
- 完了案件をロックして既存の売上請求を一度だけ作成・確定する。税区分と税抜単価を明示し、会計・入金・在庫は既存モジュールを再利用する。
- 生成請求単独の取消は依存関係で拒否。案件からの取消は有効日を伝え、入金・締め期間などの下位制約を保つ。税計算前の履行実績を会計売上・利益と表示しない。
- UIに10業界の具体的説明と未対応範囲、業界検索・利用状況フィルタを追加。公的分類の選定根拠と各業界の金額まで追える台本を文書化した。

## 検証（担当範囲）

専用PostgreSQL 16の `daifuku_review_industry_catalog` のみを使用し、`vitest run --project db packs/industry-catalog/test` は **2ファイル・27件通過**。

10件は、通常の sample 適用（forceなし・core seed済み）→開始→証跡未入力拒否→正規完了→二並行請求の同一化→入金→入金済取消拒否/rollback→入金取消→案件と請求の同一有効日取消→取消前後の実績を確認する業界ごとの一連の試験。残り17件は固有数量不正10例、派生項目所有と設定保持、在庫不足rollback、stale version/汎用確定の必須条件、生成請求の単独取消拒否と改訂、10業界の会社/権限分離、501行の全件集計と基準日制約。

新2packageの型検査、担当TS/TSXのESLintおよびWeb全体型検査が通過した。統合途中のWeb型検査では作成前の勤務画面参照を検出したが、最新の検査では解消済み（`review/industry-web-typecheck.log`）。全体migration・gate・UI確認はrootの統合結果に従う。

途中で確認したサンプル顧客コード長（専門サービス）を既存20文字制約内に修正した。未適用パック拒否の期待コードは現在のPermissionDenied契約に合わせた。生成請求単独取消は既存kernelが既に拒否するため、その安全な挙動を回帰・仕様へ反映した。

## 対応範囲

製造原価/BOM、出来高会計、ロット在庫追跡、分割納品・請求、配車、客室や施術の予約枠、診療・保険請求、学籍・成績などは含まない。医療・介護サンプルの税区分は架空の演習値であり税務判断ではない。今回の追加は海外ERP・規制業務全体の適合宣言ではない。

工数・トークン使用は未測定。独立した人手の業務受入審査は未実施。

## 勤務基盤の独立検証への協力

担当外の勤務基盤に対し、計算・権限の独立レビューとテスト3ファイルを担当した。`time.test.ts`・`pay-calculation.test.ts` の17件、および同じ専用DBの `leave-expense.db.test.ts` の9件が通過した。日/週時間外の重複排除、月60時間の境界、深夜と休憩の実時間、月境界週、入退社・賃金条件の按分、31日全月の月給300,000円が厳密に維持されること、有給の期限/半日/並行承認、経費の重複要求/並行精算を検証した。日を跨ぐ勤怠は保存できる一方、暦日ごとの休日分割に未対応の給与自動計算は明示拒否する。検出したガードや権限の不整合は勤務基盤担当が修正し、管理者本人の有給申請が保存権限で止まる問題も修正後の9件再実行で確認した。全勤務基盤の受入をこの26件だけで宣言するものではない。
