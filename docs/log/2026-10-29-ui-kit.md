## 決めたこと（と理由）

- **部品は `apps/web/src/ui/` に置き、翻訳済みの文字列を受け取る。** `useLocale()` を呼ばないので、DOM ライブラリを足さずに `react-dom/server` の `renderToStaticMarkup` で role・aria・順序を検査できる。vitest の include（`**/src/**/*.test.ts`）は変えず、`.test.ts` から `createElement` で描画する。`.tsx` を import した `.test.ts` が JSX 変換されることを最初に実測で確かめた。
- **Button は既存の `.btn` / `.btn-primary` / `.btn-danger` に対応させ、`.btn-ghost` / `.btn-sm` だけ足した。** 既存の CSS と、ブラウザ試験の `getByRole('button', { name })` をそのまま保つため。
- **意味トークンは `:root` の CSS 変数にし、`@theme inline` で同名の Tailwind 色にした。** 名前は依頼どおり `--surface` / `--text-muted` など。ユーティリティは「接頭辞 + トークン名」（`text-text-muted`）で、読みにくさより規則の単純さを優先した。値は既存の hex と Tailwind 既定パレット（oklch）をそのまま写し、`styles.css` の `body` / `.input` / `.btn*` / `:focus-visible` もトークン参照に置き換えた（値は不変）。
- **キットの CSS は `@layer components`。** 専用画面の手書き CSS（layer 外）が常に勝つので、`PageHeader className="control-heading compact"` のように既存クラスを渡せば見た目が変わらない。レポート画面とアクション画面はこの方法で置き換えた。
- **分岐点は 480 / 768 / 1024 / 1280。** Tailwind の `sm` を 30rem に、`2xl` を `initial` にした。既存の `md:` 3 か所（768px）は影響なし。専用画面の CSS の分岐点は触っていない（スコープ外）。
- **一覧の骨格行は「初回」と「条件変更後の placeholder 表示中」だけ。** 同じ条件の再取得（保存後の invalidate など）で骨格に差し替えるとちらつくので、行を残して `aria-busy` と上端の帯にした。react-query の `isPlaceholderData` で区別する。
- **空状態の作成導線の名前は「<名前>を登録する」。** 既存試験（smoke・navigation）は `getByRole('link', { name: /新規/ })` で見出しのリンクを 1 つに特定しているため、同名のリンクを増やすと strict mode で壊れる。アクセシビリティ上も同じ名前のリンクが 2 つ並ぶより区別できる方がよい。
- **取得失敗時に「まだ記録がありません」と出さない。** 従来は失敗でも「該当するデータがありません」だった。失敗時は表内に「読み込みに失敗しました」と再試行（トーストと同時に `role="alert"` を増やさないよう、表内は alert にしない）。
- **MetaError は「題名 → コード別の説明 → サーバーのメッセージ → 閉じた技術情報 → 再試行」。** e2e はサーバーのメッセージ（例 `Synthetic refresh failure`）を `toContainText` や `filter({ hasText })` で探すので、メッセージは折りたたまず見える位置に残した。コード・HTTP・hint は `<details>` の中（textContent には残る）。
- **トーストは `toastFromError`（純粋関数）に移し、題名 = メッセージ、次行 = hint、最後 = コード。** 従来の `CODE: message` を題名にする形をやめた。e2e にコードの文字列を期待する箇所はなかった（grep で確認）。
- **`ActionConfirm` を `Dialog` の上に作り直した。** `Dialog` を実際の確定・取消・削除・アクション実行の全試験で検証できるため。DOM は題名の id が `useId()` になった以外は同じ（`#action-title` を参照する箇所は無い）。`WorkforceDialog` / `CommerceDialog` / `ControlDialog` は計画どおり置き換えていない。（当初「焦点の復帰は native」としたが誤りだった。下の「レビュー後の修正」参照）
- **並べ替えの `aria-sort` を `button` から `th` に移した。** ARIA では `aria-sort` は columnheader の属性で、A2 の axe 検査で `aria-allowed-attr` 違反になるため。矢印は `aria-hidden` にした（列名だけが名前になる。`getByRole('columnheader', { name: 'ランク' })` は部分一致で引き続き通る）。
- **一覧の表は `fill` で高さを `max(240px, 100dvh - 270px)` に抑え、見出しを固定した。** `.page-content` を flex にする案は専用画面の `margin: 0 auto` の幅を変えるので採らなかった。
- **`FieldRow` は作らなかった。** 計画の部品候補だが、使う画面（`record-form` / `fields`）は D3 で項目配置と一緒に変える。未使用の部品を先に置かない。

### 決めたこと（と理由）

- **キットの大きさを 14px 基準の rem にそろえた。** `html { font-size: 14px }` なのに、キットの CSS は 16px 基準の Tailwind の値を px で写していた（バッジ 12px ← 旧 `text-xs` = 10.5px、設定カードの余白 12px ← 旧 `p-3` = 10.5px など）。`--text-xs` / `--text-sm` / `--spacing` / `--radius-sm` の theme 変数で書き直し、置き換えたユーティリティと同じ計算値にした。px のまま残したのは元が px の規則（題名 22px、11px のリンク、高さ 40px）だけ。
- **色の 1 段のずれを直した。** バッジの文字は `-on-muted`（emerald-800 / red-800、旧と同じ）、トーストの枠は `--danger-border-strong` / `--success-border-strong`（red-300 / emerald-300、旧と同じ）を足した。通知（MetaError・権限の注意）は旧のまま `-border`（200）。情報トーストだけは、旧の「紫の背景に既定の青の枠と文字」が `@theme` の部分的な上書きによる偶然と判断し、紫の強調色にそろえた（spec の未決事項に記録）。
- **コントラストのために 3 か所だけ色を変えた（AC-2 の例外として spec に明記）。** `--focus-ring` を `#8f6cee` に（`--canvas` 上 2.92:1 → 3.54:1）、汎用の表見出しを `--text-muted` に（4.12:1 → 4.62:1）、技術名（`ui-code`）と記録のシステム情報のラベルを `--text-muted` に（`--text-subtle` は `--canvas` 上 3.00:1）。`--text-subtle` / `--text-faint` は装飾専用とし、unit テストで文字への使用を禁じた。値は WCAG 2 の相対輝度の式で計算した（作業用スクリプト）。
- **layer の外の汎用の表の規則（`.page-content th` / 縞 / hover）もトークンにした。** layer の外の規則はキットの `@layer components` に常に勝つため、キット側の見出しの規則も同じ値（`--text-muted` / `--surface-muted`）にそろえ、unit テストで両方を確かめる。縞と hover には `--row-stripe` / `--row-hover` を足した。
- **色のトークンはすべて `@theme inline` に出した**（24 → 53）。規約どおり `border-danger-border` などを書いても CSS が出ないことがないように、`:root` の色トークンと `@theme inline` の一致を unit テストで確かめる。
- **`PageHeader` はアイコンと文字を折り返さない 1 行（`ui-page-header-main`）にし、`actions` だけが折り返す。** アクション画面とレポート画面の専用 CSS（`.business-action-heading` / `.control-heading`）には `flex-wrap: nowrap` を足した。レポートの飾りのアイコンは 390px で旧 20px 幅に潰れていたが、今は 32px のまま題名の横に並ぶ（`Icon` は元から `aria-hidden`）。
- **アクション・レポート・report-ready の見た目を専用 CSS 側で旧に戻した。** アクションの題名の色（`color: inherit`、旧 `#24324b`）、report-ready の題名の色・太さ・行の高さと説明の文字の大きさ、`gap: 0`。題名の `letter-spacing` は base の `h1, h2, h3 { -0.025em }` が元から効いているので、キットでは指定しない。
- **`Dialog` が焦点を戻す。** 呼び出し側は閉じるときに部品を外す（unmount）ため、開いたままの `<dialog>` が DOM から外れ、ブラウザの焦点復帰が走らなかった（レビューの推論を、下記の改変試験で実測で確かめた）。`useLayoutEffect` の後始末（React が DOM から外す前に走る）で `close()` し、焦点がダイアログ内か `<body>` にあれば開いた要素へ戻す。あわせて、React の `autoFocus` はダイアログが開く前に走るため効いていなかった（最初の焦点は「×」だった）ので、`data-autofocus` の要素を開いた直後に focus するようにした。StrictMode の再マウントでは後始末の `close()` による遅れた close イベントが開き直した後に届くため、`onClose` は閉じた状態のときだけ呼ぶ。
- **`Dialog` に `aria-describedby`（説明文）を付けた。** `role="alertdialog"` にはしない（15 本以上の e2e が `getByRole('dialog')` で探しており、説明文は describedby で読まれる）。
- **空状態は表の後ろ（枠の中）に出す。** `colSpan` のセルに入れると、列が多い表では表の全幅の中央に置かれ、390px では案内と「登録する」が枠の外へ出ていた（レビューの推論。改変試験で実測で確かめた）。枠の直下のブロックは見えている枠の幅になる。
- **読込中の文字を busy の外の `aria-live="polite"` にした。** 一覧の骨格行の間は表の枠の外の live region が「読み込み中…」と言い、`LoadingView` は骨格の容器だけを `aria-busy` にした。`role="status"` にしないのは、トーストを `getByRole('status')`（strict）で探す既存の e2e（account-security、enterprise-identity）と重ならないため。
- **「検索をクリア」「再試行」の後は焦点を検索欄へ移す。** 押したボタンが再読込で消え、焦点が `<body>` に落ちていた。
- **`FormSection` の既定を `role="group"` にした。** 名前付きの `<section>` は region landmark になり、設定画面ではフォーム landmark と同名の region が設定ごとに重なっていた。`landmark` 指定のときだけ `<section>`。`as="fieldset"` では `legend` を最初の子にし、冗長な `aria-labelledby` を外した。
- **`aria-sort` は並べ替え中の列だけ**（`ariaSortFor`）。`NotFoundView` / `EntityMissing` は `EmptyState titleAs="h1"`（画面全体の内容なので）。`Card` の props は `as` で分け、フォーム専用の属性は `as="form"` のときだけ型が通る（unit テストの `@ts-expect-error` で確かめる）。`Tabs` の焦点の枠は、横スクロールのタブ列に切られないよう内側（`outline-offset: -3px`）に描く。
- 設定画面の権限の注意に旧の `m-4` を戻した。
