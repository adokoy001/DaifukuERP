## 決めたこと（と理由）
- **sales/purchase を import しない**（spec・ADR-0008）。override 名は定数 `EXEMPT_SUPPLIER_CREDIT_RATIO_OVERRIDE = 'purchase.exempt_supplier_credit_ratio'` / `INVOICE_HTML_OVERRIDE = 'sales.invoice_html'` として export。`InvoiceRenderData` は docs/specs/sales.md の契約を `services/invoice-render-data.ts` に**逐語コピー**し、zod スキーマ（金額は `Decimal.isDecimalString`、日付は `isLocalDate`）で**実行時に検証**する。契約違反は `ValidationError`（`issues[].path` に `invoice.date` 等）。オーケストレータが sales 側の型と突き合わせる前提。
- **経過措置の控除率は「率×有効期間」の連続テーブル**（`EXEMPT_SUPPLIER_CREDIT_RATIOS`、6 行）。spec の 4 段階（0.8/0.7/0.5/0.3）に加え、**2023-09-30 以前は 1**（区分記載請求書等保存方式では免税事業者からの仕入れも全額控除。国税庁 No.6497）、**2031-10-01 以降は 0** を明示行にした。理由: 「任意の日付で必ず 1 行に当たる」性質をテストで守れる（隙間・重複なし、比率は単調減少）。spec 文面「0.8 until 2026-09-30」は開始日を書いていないため、開始日はインボイス制度開始日 2023-10-01（Q&A 問113）とした。→ 判断待ち。
- **1 億円上限（Q&A 問113）は未実装**。override の入力 `{ supplierTaxStatus, date }` に年間累計が無い（purchase spec もスコープ外と明記）。コメントに残した。
- **和暦の元年は「元年」表記**（公文書の慣行）。`toWareki('2019-05-01') = '令和元年5月1日'`。元号表 `ERAS` は明治〜令和の 5 行で、第 2 引数で差し替え可能（新元号はデータ追加のみ、テスト済）。明治以前は `ValidationError`。
- **`formatJpy` は丸めない**（`'1234567.5'` → `'¥1,234,567.5'`）。丸めは税計算側の責務（問57）。負数は `-¥1,000`。
- **勘定科目の `taxCategoryDefault`**: spec が指定した 4000/5000 = standard、6100/6700/6800 = out_of_scope、6200 = non_taxable に加え、**指定のない販管費（通信費・消耗品費・旅費交通費・支払手数料・雑費・水道光熱費・広告宣伝費・接待交際費・外注費）は standard** とした。理由: purchase の経費明細は「勘定科目の既定税区分」から税区分を引く（purchase.md AC-1）ので、null だと入力のたびに指定が要る。資産・負債・純資産・雑収入は null。subtype は `販売費及び一般管理費`（フル表記）。→ 判断待ち。
- **既定設定は「未設定のときだけ書く」**: `getCompany` で生の `settings[key]` を見て `undefined` のときのみ `setSetting`。運用者が先に入れた値（テストでは `tax.price_includes_tax = true`）は保持。`tax.rounding` は `{ mode: 'down', unit: 'invoice' }`（問57）。税率シードは `seedTaxRates`（mod-tax）へ委譲。
- **軽減税率の判定は category === 'reduced'**（率 8% ではない）。2014〜2019 の標準 8% を軽減と誤表示しないため。
- **HTML は 1 文書・inline CSS のみ・A4**（`@page { size: A4 }`）。ラベルは `{ja, en}` を持ち `locale` で切替（en でも和暦は括弧内に残す）。ユーザ文字列は全て `escapeHtml`（`& < > " '`）を通す。
