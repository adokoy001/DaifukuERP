## 決めたこと（と理由）
- **1 ファイル・台本順の `it` 10 本**（vitest はファイル内の `it` を宣言順に直列実行。`describe` 1 つ、状態はモジュール変数で持ち回す）。金額系の比較は `expect.soft` にして 1 ステップ内の差異を全部出す。構造的な前提（200 / 行の存在）は通常の `expect`。
- **セットアップは `apps/api/src/db/reset.ts` と同じ**: `../src/modules.ts` を import（`registerCrudActions` 込み）→ `freshDb()` → 各モジュールの `seed(ctx)` を system context（`withContext(db.owner, systemParams(...))`）でモジュール順に実行。実行されたシードは partner / product / tax / accounting / l10n_jp の 5 つ（attachment / sales / purchase / payment はシード無し）。
- **会計年度は `accounting.open_fiscal_year { startDate: '2026-01-01' }` をシードの前に呼ぶ**。accounting のシードは「年度が無いときだけ今年を開設」なので、先に開けばシードは no-op、後に呼ぶと CONFLICT になる。「全シードを流す」と「アクションで年度を開く」の両方を満たす順序はこれだけ。年度 1 件・期間 12 件を実測で確認。
- **"today" は 2026-10-31 12:00 JST に固定**（`FIXED_NOW`、台本の締め日）。日付は全部明示するので既定値には依存しないが、シードの年度決定（今年 = 2026）を決定論にするため。
- **INV1 だけ HTTP 経由**（fastify `inject`: `POST /auth/login` → `POST /api/sales_invoice`（lines 付き）→ `POST /api/sales_invoice/:id/submit` → `GET /api/sales_invoice/:id`）。`GET` の JSON と in-process `sales_invoice.get` の結果が `toEqual` で一致することで REST 経路 = in-process 経路を示す。さらに試算表（`POST /actions/accounting.trial_balance`）・年齢表・請求書 HTML も HTTP 側の結果が in-process と完全一致することを確認。
- **消費税集計は仕訳明細の集計で行う**。期間の消費税集計アクションは存在しない（tax モジュールのアクションは resolve / summarize（伝票 1 枚分）/ get_settings / set_settings のみ）。転記済み `journal_line` を aggregate ポートで 2200（仮受）/ 1500（仮払）× taxCategory × taxRate で集計。
- 台本に無い属性は入れない: 取引先の登録番号（台本は「登録事業者」とだけ）、品目の isPurchased など。C3（登録 —）は taxStatus 既定（registered）のまま — 顧客側では計算に影響しない。
