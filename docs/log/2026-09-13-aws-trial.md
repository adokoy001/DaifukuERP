# 作業記録: 2026-09-13 AWS の独立した試用環境

## 決めたこと（と理由）

- 既存ゲームの Terraform state やリソースを使わず、新規 CloudFormation stack `daifuku-trial` に専用資源を作る。DNS は未使用名の新規 record だけを追加する。
- 東京の `t3.small`、Ubuntu 24.04、暗号化30 GiB gp3、専用 EIP と private S3 を使う。NAT Gateway・ALB は置かず、単一ホストの試用として費用と可用性の限界を示す。
- 公開入口は HTTPS、管理は SSM とする。API/DB は loopback、SSH service/socket は停止し、API/Caddy から metadata を取得できないようにする。
- 公開 template と運用文書に、実 DNS、AWS account/resource ID、秘密、私有 path、生の AWS 出力を保存しない。実接続先・hash・操作証跡は私有 runbook で管理する。
- 検証済みアプリ bundle `69e5846` を固定して導入し、ホスト上で依存を再解決しない。core seed と合成資料だけを使い、業界テンプレートを自動適用しない。
- DB dump だけでなく、添付、runtime.env と認証鍵、role の復旧情報、TLS ファイル、配布版の対応を保全する。S3 往復、同一ホストの別 DB 復元、別ホストでの完全復旧を区別する。

## やったこと

- [CloudFormation template](../../deploy/aws/trial.cloudformation.json)、[操作入口](../../deploy/aws/README.md)、[運用手順](../operations/aws-trial.md)、[仕様](../specs/aws-trial.md) と5件の template 境界回帰を整備した。
- AWS の template 検証後、初期16資源が全件 Add の change set を実行し、CREATE_COMPLETE を確認した。
- 後続更新は `ArtifactsPolicy` の `DeletionPolicy` / `UpdateReplacePolicy` の2属性だけと照合した。Replacement=False、UPDATE_COMPLETE、取得 template の一致を確認した。既存ゲームの変更は含まない。
- Node.js 22.23.2、PostgreSQL 16.15、Caddy 2.11.4 を導入し、hash を照合したアプリ bundle と専用 DB、非 root の常駐設定、公開 HTTPS を構成した。
- [共通配備手順](../operations/deployment.md) の認証設定例に、`PUBLIC_WEB_URL` と同時に必須の `IDENTITY_ENCRYPTION_KEY` を追記した。JWT と別の32バイト乱数を標準 Base64 にし、既存の鍵を更新・復元時に維持する契約を明示した。
- ブラウザで初回管理者のログイン・会社選択・合成取引先作成を行い、正規 API で合成添付を保存・取得した。秘密を含まない再確認用 metadata とログイン後の画面証跡を私有保存した。
- backup を S3 に保存し、operator の実行文脈で再取得して照合した。新規の復元確認 DB に復元し、稼働 DB を切り替えず元の状態を保持した。
- API/Caddy の停止・開始と EC2 再起動を実行した。新しい boot ID、3サービスの自動起動、HTTPS と保存内容の回復を確認した。
- 毎日 JST 04:00＋最大5分のランダム遅延の backup timer と、7日試用の一回限りの停止 timer を設定した。backup handler と backup service をそれぞれ手動実行して成功を確認した。

## 見つけた問題と修正（発見経路つき）

- Ubuntu の対象 apt repository では `awscli` を導入できなかった — 発見: ホスト構築の実行。運用処理を配布の `python3-boto3` で実行するよう修正した。
- Caddy の導入版を明確に固定する必要があった — 発見: 現行配布の確認。2.11.4 を選び、検証版として記録した。
- 秘密用の umask を公開 asset 展開に引き継ぐと Caddy が読めない — 発見: 配布生成後のファイル権限検査。公開 asset 生成・展開は umask022 とし、秘密ファイルは所有者限定の権限を維持した。
- 運用 subprocess の PATH に `/usr/sbin` がなく、管理用コマンドを解決できなかった — 発見: ホスト構築の実行。運用処理の固定 PATH を修正した。
- `pg_restore` が正常終了して入力を早期に閉じる場合、送信側の stdin close だけで失敗と扱っていた — 発見: 復元の実測。終了コード0を確認した場合は件数・security の照合へ進めるよう修正した。非0の復元失敗を無視する処理にはしていない。
- 公開 URL の例だけでは認証 config が成立しなかった — 発見: `identity/config.ts` と鍵検査のレビュー。共通配備文書へ同時に必要な認証鍵と保持条件を追記した。
- シフト画面の hero に低コントラストの文字がある — 発見: ログイン後のスマホ画面を視覚確認。淡色背景に既存の白い文字が残る課題で、今回の固定アプリ bundle は変更していない。未修正として残す。
