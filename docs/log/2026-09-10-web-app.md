## 決めたこと（と理由）
- **kernel を import しない。** ブラウザバンドルに drizzle/postgres が混入するため、`FieldMeta` / `EntityMeta` / `AppMeta` / `ErrorBody` / `AuditEntry` 等の型は `apps/web/src/api/types.ts` に手で複製した（ファイル冒頭に同期の注意を明記）。
- **TanStack Table は v9**（インストール済みが 9.2.4）。v8 の `useReactTable` ではなく `useTable` + `tableFeatures({ rowSortingFeature })`。ソート・ページングはサーバ側（`manualSorting`、`orderBy`/`limit`/`offset`）。
- **ルーティングはコードベース**（`createRootRoute`/`createRoute`）。file-based routing 用の vite プラグインは未インストールのため。ページは `useParams({ strict: false })` で循環 import を避けた。
- **一覧の ref 列は表示値を解決する**（`where={"id":{"$in":[...]}}` を ref 先に1回投げる、`useQueries`）。id をそのまま出す業務画面は使い物にならないため。
- **更新は差分のみ送る**（`diffPatch`）。immutable フィールドを未変更のまま patch に含めると拒否されるため。decimal は正規化文字列同士で比較（`"10.000000"` と `"10"` を同一視）。
- **decimal は最後まで文字列**（ADR-0010）。入力は text input（`inputMode=decimal`）、表示の桁区切りも文字列操作。`parseFloat` は使わない。
- **CONFLICT の扱い**: 編集中（update）の CONFLICT は「再読み込み」バナー（AC-7）。作成時の CONFLICT は一意制約なので hint をトーストするだけ。
- ファイル名は kebab-case（code-style.md 優先。指示の `Sidebar.tsx` 等は採らなかった）。
- 401 は `api/client.ts` がセッションを消して `/login?reason=expired` に遷移（ハンドラを main.tsx で登録）。

## 見つけた問題と修正（発見経路つき）
- CONFLICT の「再読み込み」でバナーが消えない — 発見: モック E2E。原因: サーバ側が未変更だと TanStack Query の structural sharing でレコード参照が変わらず reset effect が走らない。修正: reload で refetch 後に明示的に form state を初期化（record-form.tsx）。
- 作成時の CONFLICT（一意制約）が版競合バナーになる — 発見: モック E2E。修正: update 時のみバナー、create はトーストのみ。
- Playwright 1.63 が期待する Chromium (1243) が `/opt/pw-browsers` に無く 1194 のみ — 発見: モック E2E 起動失敗。修正: playwright.config.ts が `PLAYWRIGHT_BROWSERS_PATH` から `chromium-*/chrome-linux/chrome` を探して `launchOptions.executablePath` に渡す（`PLAYWRIGHT_CHROMIUM_EXECUTABLE` で明示も可）。
- `e2e/*.ts` で `process` 型が無く tsc 失敗 — 発見: 実測。修正: tsconfig `types` に `node` を追加。
- decimal の form 初期値が `"100.000000"` — 発見: 目視。修正: 正規化して `"100"` を表示（差分比較は正規化済みなので無駄な patch は出ない）。
