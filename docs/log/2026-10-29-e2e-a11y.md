## 決めたこと（と理由）

- **`@axe-core/playwright` は 4.13.0 に固定した。** 最新の 4.14.0 は 2026-10-15 公開で 2 週間しか経っていない。4.13.0（2026-08-11）は `axe-core ~4.13.0` に依存し、lockfile では `axe-core@4.13.0` に解決された。peer の `playwright-core` は既存の 1.63.0 のまま。`pnpm add` が `apps/web/package.json` の依存の並びを並べ替えたため、並びは元に戻して 1 行だけ足した（並行作業との衝突を減らす）。
- **判定規則は `apps/web/e2e/a11y-policy.ts` の純粋関数に分けた。** Playwright を import しないので、Web unit（`apps/web/src/a11y-policy.test.ts`）が規則とチェックイン済みの例外ファイルを `gate:quick` で検査できる。Playwright の `testDir` は `e2e/` で `*.test.ts` も拾うため、unit は `src/` に置き、同じ package 内の相対 import で読む。
- **例外は実行（画面 × 言語 × 幅）ごとに照合する。** spec の下書きは「使われなかった例外を失敗にする」だったが、ファイル全体で判定すると `--grep @smoke` など一部だけ実行したときに誤って古い例外と判定する。各実行で「適用される例外が 1 件も一致しなければ、その実行が失敗」とし、条件の違いは `locales` / `widths` で例外を絞って表す。spec の AC-2 / AC-3 にこの規則を書いた。
- **target は axe の node target の完全一致。** 前方一致やワイルドカードは、関係ない要素まで黙らせる危険があるので入れない。
- **影響度の無い違反は失敗扱い。** axe は違反に必ず影響度を付けるので実際には起きないが、黙って「出力だけ」に落とさない。
- **WCAG タグだけを対象にした。** best-practice の rule（`region`、`landmark-*` など）は spec のスコープ外。32 件の実行で WCAG タグの moderate / minor は 0 件だった。
- **ログインは API で 1 回だけ行い、ログイン画面と同じ `sessionStorage`（`daifuku.token` / `daifuku.user`）を `addInitScript` で入れる。** 28 件の画面ごとにログインフォームを操作しない。言語は `localStorage` の `daifuku.locale`。`<html lang>` が言語と一致することも確かめる。
- **検査の前に「画面の内容が出た」ことを待つ。** `h1` の表示、`meta-error`・`aria-busy="true"`・`loading-view` が無いこと、`networkidle`。読込失敗や骨格表示を検査して成功にならないようにした。
- **違反はすべて直した（例外 0 件）。** 色はすべて既存トークン（`--text-muted`、`--accent`）に置き換え、新しい色は足していない。会社設定画面の違反は共有の上部バー（利用者名）だけで、`settings-page.tsx`（B1 が並行で書き換え中）は触らずに解消したため、B1 を追跡先とする例外も不要になった。
- **明細表（`line-grid.tsx`）の横スクロール枠は、中に焦点を受ける要素が無いとき（0 行、または読取専用）だけ `tabIndex={0}`・`role="region"`・`aria-label`（「<明細名>の表」）を付けた。** 編集できる行があるときは入力欄で横に送れるので、Tab の止まりを増やさない。既存の `analytics-result.tsx` の集計表と同じ形。
- **`@smoke` の件数検査は分けた。** A1 の `scripts/test/gate.test.ts` は `test('… @smoke'` を直書きした代表試験（6〜8 件、現在 7 件）を数え、ループで作る a11y の試験名は数えない。a11y の 8 件は Web unit が数える。並行で `scripts/` を触る項目（A3）との衝突を避けるため `gate.test.ts` は変えていない。
