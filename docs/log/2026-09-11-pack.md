## 決めたこと（と理由）
- **definePack は全部検査してから登録**（名前・接頭辞・ラベル項目 → ValidationError、depends 不足・対象エンティティが depends から辿れない → DependencyError、名前／所有／ext キー／ラベルの重複 → Conflict）。ext は複数エンティティ分を `checkExtFields` で先に全部検査してから `registerExt` する（1 つ目だけ登録されて 2 つ目で落ちる半端な状態を作らない。unit テストで確認）。
- **ext / labels の対象エンティティの module は depends の推移閉包に含まれること**を定義時に要求した（spec には無い）。registerExt の既存 hint が「depends に書け」と言っており、書かなくても import 順で偶然動く状態をエージェントが見抜けないため。kernel fixture のように module を持たないエンティティは対象外。
- **ラベル上書きの重複は Conflict**（後勝ちにしない）。apps は全 pack を常時ロードするので、小売と不動産が同じ partner を別名にすると片方が黙って負ける。ext キー重複を Conflict にした ADR-0014 と揃えた。Phase 2T で 2 つの pack が同じエンティティを改名したくなったら、この制約（ADR-0015 帰結）が最初に当たる。
- **settings のキー検査は適用時**（spec どおり）。pack 自身の `hooks` で宣言した設定もあるため、定義時には検査しない。値も適用時に schema で全部検査してから書く。
- **example の設定は pack 自身が宣言した `example.default_customer_rank`（A/B/C、既定 B）にした（spec からの逸脱）**。spec 案の `sales.issuer` は構造体（`name` だけを持つ設定キーは無い）で、`packs/example/package.json` の依存（partner / product / accounting）はどれも設定を宣言していない。`tax.price_includes_tax`（boolean）は mod-tax への依存追加が要るので避けた。sample の 2 件目がこの設定からランクを取る（設定 → seed → sample の順で動くことの確認を兼ねる）。
- **ext キーは `customerRank` / `note2`（spec の `customer_rank` から変更）**。ADR-0014 の ext キー規則（camelCase）に合わせた。
- **`packs.applied` に `sampledAt?` を足した**（spec の `{ at, version }` に追加）。適用済みの会社に後から `--sample` したとき 1 回だけ流すため、sample を実行したかの記録が要る。`at`/`version` は設定・seed を最後に流した時刻と版。
- **2 回目の適用は `packs.applied` も書き換えない**（`at` を更新しない）。spec の「no-op（versions unchanged）」を、行の version・設定・監査件数の全部が不変、として実装・テストした。
- **version が変わっても force なしでは再適用しない**（spec どおり）。設定は未設定キーのみ・seed は冪等なので安全に再実行はできるが、spec を優先し判断待ちに回した。
- **applyPack の権限は `admin` のみ**（`settings` ロールは不可）。seed がマスタを書くため。`setSetting` 自体は admin/settings を許すが、その手前で止める。
- **`AppMeta.modules` の後ろに pack も並べた**（spec は `AppMeta.packs` のみ）。web のサイドバーは `meta.modules[].menus`、ダッシュボードは `modules` の名前でエンティティをグループ化するので、pack のメニュー（example_tag）を web 無改修で出すため。`AppMeta.packs[].applied` は同期関数の `appMeta` が DB を読めないので `MetaOptions.appliedPacks` で受け取る（`currency` と同じ流儀）。
- **apps/api/src/routes/meta.ts を 2 行編集**（編集範囲の指示の外）。`/meta` の `packs[].applied` を会社ごとに正しくするのに必要（`appliedPacksOf(company.settings)` を渡すだけ）。kernel-phase15 の通貨と同じ箇所。
- **`pack.apply` / `pack.list` は `registerPackActions()` を apps が呼ぶ**（registerCrudActions に混ぜない）。他パッケージのテストが registerCrudActions だけでアクション数を数えている箇所があり、意味を変えないため。`apps/api/src/packs.ts`（import 時）と `apps/mcp/src/modules.ts`（`loadModules`）で呼ぶ。`packs.applied` の registerSetting もここ（と applyPack）で冪等に行う。
- **dependency-cruiser `only-apps-depend-on-packs` は pack → pack を許した**。AC-2 が「depends は module または pack」を認めており、pack を depends に書くには import が要るため。kernel/modules/l10n → packs は既存の層ルールでも落ちる（新ルールはメッセージを pack 向けにしたもの）。一時ファイルで発火を確認（下記）。
- **CLI は owner 接続で会社を解決し、適用は app 接続（RLS）＋ `systemParams`**。`db:reset` の seed は owner 接続だが、pack.apply アクションと同じ経路で動かす方を選んだ。既定の会社は「デモ管理者（DEMO_TENANT.adminEmail）のテナントの最初（created_at, code 順）の会社」。
- **packs/example の `package.json` の依存 mod-product / mod-accounting は使っていない**（削除していない。pnpm install をしない指示のため）。
