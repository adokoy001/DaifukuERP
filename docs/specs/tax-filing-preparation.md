# 申告準備と財務諸表の取込ファイル

状態: 実装・対象回帰検証済み。公式 checker の形式受理はメンテナンスにより未検証。検証日 2026-09-13。根拠は [国内申告の設計](../domain/japan-tax-filing.md)。実申告・納付・受付確認は本機能の状態に含めない。

## 対応する境界

汎用 `modules/tax-filing` は会計・給与の根拠採取、検算、版管理、確認・取消、出力を所有する。`l10n/jp` は公開された profile port に国内様式・適用期間・コード表・formatter を登録する。相互逆依存、SQL直書き、金額の浮動小数点演算を用いない。

初版の公式取込は e-Tax 財務諸表 HOT010 Ver.3.0、一般商工業、単体・円単位の貸借対照表と損益計算書。株主資本等変動計算書・注記・法人税の別表や税額計算を含む申告一式ではない。会計年度単位・期末締め済み・当期損益振替前、年度開始前の収益費用残高ゼロに限定する。公式の科目分類を確認した account→category 対応を全科目に設定する。

給与は既存の通常年末調整が扱う2026年を対象とし、確定月次給与の支払年と確定年調・本人申告・不足する住所/カナ等の補足から準備表を作る。CSVは Daifuku の確認用資料であり、公式375・eLTAXファイルではない。マイナンバーを取得・保存・出力しない。

## 受入条件

- TF1: 会計担当は会社全体の会計準備、給与担当は会社全体の給与準備だけを操作できる。店舗限定/本人/機械principalから会社一式を生成できず、給与データを会計権限だけに開示しない。汎用CRUD・delete・直接状態変更は禁止する。
- TF2: 準備時に元資料のID/version・金額・年度・期間・制度/形式版・補足条件を保存し、正規化JSONのUTF-8 SHA-256を根拠hashとする。hashは署名ではない。上限到達/ページ欠落で部分集計を保存しない。
- TF3: 準備はdraft、別確認者が根拠を再採取し一致を確認するとconfirmed、理由付き取消でcancelledとなる。確認済み内容は不変で再作成は新IDと前版参照を持つ。操作はexpectedVersionを確認し、通信再試行はidempotencyKeyで重複作成しない。
- TF4: 確認・出力時は共有会計期間/給与社員lockの下でソースhashを照合する。新規転記、再開、年調取消、補足更新等で現在資料が違えば出力を拒否し、保存済みの根拠を消さず再準備を案内する。
- TF5: 会計は全仕訳の借貸と転記snapshot、年度範囲、期首/期末残高、損益、BS一致をDecimalで検算する。未対応分類・不足mapping・不正期間・簿価不一致は公式出力不可。未分類消費税は警告と根拠確認を必須にする。帳簿の仮受−仮払は申告納付税額ではなく、法定申告税額は未算定と明示する。
- TF6: 国内formatterはHOT010 Ver.3.0の5列、A/B/C1/C2/財務諸表名、日付、行区分、階層、コード、金額桁数、SHIFT-JIS、末尾空欄、負数を検証する。非対応文字を?に変換せず拒否する。明示されたゼロ合計と金額不要タイトルを区別する。公式CSVは確認済み準備からのみ出す。
- TF7: 給与は給与期間と支払年を区別する。確定前/取消後/支払証跡なし/年調なし等は社員別の未解決事項とし、ゼロ税額や計算完了へ置換しない。前職込み年調合計と社内給与合計を混同しない。住所等の補足は担当者の根拠を保存し、公式様式に必要な未対応項目を残す。
- TF8: 公式制度の年度・適用期間・資料URL・原本SHA-256・形式版を固定する。対応外の給与年度、国内profile外の年度日付・通貨・事業者種別では拒否し、公式申告書XMLや未確認eLTAX形式を生成しない。

## 検証

純粋テスト: 公式HOT010標準フォームとの5列/コード/階層照合、合計・ゼロ・赤字・整数桁・全角/文字コード・欠損mapping、期首損益残高/振替前条件。DB: 会計/給与role・会社/店舗境界、CRUD拒否、source変更、version競合、確認者分離、取消と再作成履歴、支払年境界と未確定社員。合成ファイルの公式チェックは実施結果を別記し、送信や受理の証拠にしない。
