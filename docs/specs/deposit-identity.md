# 敷金の契約・入居者・部屋の一貫性

## 受入条件 (EARS)
- WHEN 敷金を作成する THEN 入居者と部屋は契約に一致し、省略値は契約から補う。明示された別の入居者・部屋・不一致の null は拒否する。
- WHEN 敷金が存在する THEN 契約・入居者・部屋の付替えを拒否し、受領後は金額も変更できない。
- WHEN 敷金を受領/返還する THEN 同じ敷金行をロックした後に最新の状態を確認し、一度だけ転記する。受領/返還の仕訳は同じ保存済みの入居者を保持する。
- WHEN 公開APIから受領日/返還日/返還額/控除額/仕訳参照を変更しようとする THEN serverOwned と private write capability で拒否し、正規アクションだけが台帳と仕訳を更新する。
- WHEN 二重受領/返還する THEN 未実装の訂正方法や単独逆仕訳を案内しない。

## 範囲外
敷金の取消/再受領という新しい業務アクション、既存不整合データの自動修復。既存不一致を受領時に発見した場合は操作を止め、データ確認を求める。

## 検証
新規DB回帰テストで不一致create、受領後partner/unit/amount変更、公開system field変更、正規返還時の仕訳取引先一致、同時二重返還を検証する。専用隔離DBを使用し、既存不動産台本も実行する。
