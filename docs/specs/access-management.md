# 会社所属・店舗担当と利用者管理

## 契約

テナント管理者と会社の業務ロールを区別する。会社所属は明示的に保存し、API/MCPは呼出しごとに有効な利用者・会社所属を読み直す。店舗限定担当者は自店の入力・本部提出を行い、本部が承認・確定して会計と在庫へ転記する。店舗担当者へ共通会計・在庫台帳の全社読取を与えない。

## 受入条件

- WHEN 所属のない会社を指定する THEN 読取・書込・参照検索・集計・CSVを拒否する。
- WHEN 店舗限定利用者が操作する THEN 明示された台帳と操作だけを認め、店舗と親伝票による制約を全Repository経路へ適用する。空の担当集合は全件不可とする。
- WHEN 他店へ参照を変更、明細を付け替え、新規作成する THEN 保存前に拒否する。共有マスタは宣言された読取のみとする。
- WHEN ロール・所属が失効する THEN 次のAPI/MCP呼出しから失効する。無効化・パスワード変更後の古いセッションは、再有効化しても復活しない。
- WHEN 利用者・所属を変更する THEN テナント管理者権限と最新versionを検証し、最後の有効なテナント管理者の除去、自己昇格、自己無効化を拒否する。認証情報を監査へ保存しない。
- WHEN レポートCSVを要求する THEN 元入力で再実行し、全参照台帳のexport権限を再検証する。
- WHEN 旧DBを移行する THEN 旧ロールを既存各会社の所属へ明示移行し、旧adminをテナント管理者にする。実行時に旧ロールを代用しない。
- WHEN 管理画面が最新情報を再取得する THEN 未保存の利用者・所属入力と編集開始時versionを保持し、競合時は明示的な再読込を案内する。
- WHEN 未保存の管理設定がある状態で利用者・所属先会社・ページを切り替える THEN 破棄確認を行い、保存処理中は切替を止める。
- WHEN 管理者が利用者を選択する THEN その利用者の管理監査を会社横断で表示し、変更前後を確認できる。

## 範囲外

店舗担当者による共通会計・在庫の転記、複数会社を跨ぐ一括トランザクション、SSO/MFA、給与権限、取得済み画面情報の手動コピー防止。権限変更より先に開始された処理の強制中断は扱わず、次の呼出しに反映する。

## 検証

専用PostgreSQLで所属外/他テナント/他店舗/親明細付替え、集計/CSV/監査、空集合、即時失効、再有効化、最後の管理者の同時降格、パスワード非記録を試験する。既存権限試験は旧users.rolesの直接変更を新所属の操作へ置き換え、期待する拒否は維持する。移行と全体gateは統合担当が実施する。
