# レポーティングとブラウザ・ピボット

## 目的

権限のある業務記録を、期間・状態とともに読み取り、ブラウザで行と列の階層、指標、グラフを切り替える。既存の正式帳票を補う探索分析であり、確定帳票や仕訳を書き換えない。

## 受入条件

1. 分析対象はサーバーの許可リストから選び、会社・拠点・本人・項目権限を既存の Context / Repository で適用する。対象、業務日付、初期状態、単位、1行の粒度を説明する。自由SQLや任意entityの取得は提供しない。
2. 対象期間には今月・先月・直近12か月・直近24か月・固定期間を用意する。初期値は直近12か月、確定または承認済みを基本とし、対象変更時には整合する軸と指標へ初期化する。入力変更後の旧結果は新条件の結果と表示しない。
3. 一度の読み取りは上限付きで、取得の完全性と件数を表示する。上限超過時は期間の絞込みを要求し、部分行の総計を全体の値として返さない。ブラウザの計算と表示にも明示的な件数・セル上限を設ける。
4. 行・列それぞれ最大3段階の軸を選び、順序変更、削除、軸反転、展開・折り畳みをキーボードで操作できる。日付は年・四半期・年月・日を区別し、複数年の同じ月を混ぜない。
5. 指標は合計・平均・最小・最大・有効値件数・レコード件数を区別する。金額は十進文字列/BigIntで集計する。小計と総計は元レコードから計算し、平均の平均にしない。欠測を0に置き換えない。異単位の数量を無条件に足さない。
6. 集計はWeb Workerで実行し、古いリクエスト結果を破棄する。表はページングし、棒/折れ線グラフは表示範囲と指標を明示する。グラフの描画だけ数値近似を許し、表の値を正本とする。
7. 推奨テンプレートを売上・購買・在庫移動・勤怠・休暇・経費・給与・店舗・銀行など、実際に利用可能な対象に用意する。元データの粒度に合わない帳票名・指標を付けない。
8. 名前付き設定はこのブラウザの利用者・tenant・会社別に保存/呼出し/更新/削除する。保存対象は検証した設定のみで、取得データ・トークン・計算結果は含めない。相対期間は呼出し時に再解決する。権限を再確認して取得し、権限のない対象は使えない。ストレージ不能・破損・旧版を説明し、画面を壊さない。
9. 既存レポートに妥当な期間初期値と期間ショートカット、結果の検索・並替え・ページングを加える。Repositoryの同値並替えはidを最終キーとして安定させる。
10. 数値精度、階層小計、平均、欠測、日付境界、上限、設定隔離、権限・会社境界を試験する。デスクトップ/スマートフォンの実ブラウザで操作を確認する。

## 参考調査

行・列・指標と展開状態の保存は [Odoo Reporting](https://www.odoo.com/documentation/18.0/applications/essentials/reporting.html)、[Metabase Pivot tables](https://www.metabase.com/docs/latest/questions/visualizations/pivot-table)、[Power BI Matrix](https://learn.microsoft.com/en-us/power-bi/visuals/power-bi-visualization-matrix-visual) を参考にする。帳票分類は [ERPNext Sales analytics](https://docs.frappe.io/erpnext/sales-analytics)、[Accounting reports](https://docs.frappe.io/erpnext/accounting-reports)、[Banking](https://docs.frappe.io/erpnext/banking-in-erpnext) を参照した。本仕様の具体的な対象・初期値は大福帳のデータ構造に合わせた設計判断である。
