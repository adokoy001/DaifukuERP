# Spec: form-ergonomics（フォームのセクション・エラー要約・ショートカット・モバイル操作バー）

- 状態: implemented（2026-10-30）
- モジュール: `kernel`（`views.form` のラベル付きグループ、`FieldMeta.restricted`）、`apps/web`（汎用フォーム・明細グリッド・一覧からの前後移動） ／ 依存: [ui-kit](ui-kit.md)、[list-workbench](list-workbench.md)、[document-links](document-links.md)、[navigation-assist](navigation-assist.md)
- ADR: [ADR-0002](../adr/0002-declarative-entity-dsl.md) への追補（`views.form` の後方互換な拡張）。新しい ADR 番号は使わない
- 作成: 2026-10-29 ／ 作成者: agent（計画セッション）。設計の元は [完成度向上の実装計画](../completion-plan.md) D3。2026-10-30 に実装担当が実装に合わせて改訂（末尾「改訂の記録」）

## 目的（1段落）

汎用フォームは `views.form` のグループを見出しの無い枠で並べ、保存に失敗すると各項目の下にだけエラーが出る。長い伝票では、どこが間違っているかを探してスクロールする必要があり、保存・確定はマウス操作が前提で、スマートフォンでは操作ボタンが画面外に出る。フォームに見出し付きの節、エラーの要約と焦点移動、保存と確定のショートカット、明細グリッドのキーボード操作、狭い画面の操作バー、入力の一時退避、一覧からの前後移動を加える。

## 受入基準（EARS）

- AC-1 THE SYSTEM SHALL `views.form` の各グループに、従来の field 名の配列に加えて `{ label: Label; fields: string[] }` の形を受け付け、`/meta` でラベルを返す（ラベル付きは `{ label, fields }`、従来の形は `string[]` のまま）。従来の形は変更なく動く。定義時に、未知の field・同じ field の重複・日英どちらかが空のラベル・field の無いラベル付きグループを拒否する。
- AC-2 WHEN グループにラベルがある THE SYSTEM SHALL グループを見出し付きの節（`fieldset` と `legend`、UI キットの `FormSection as="fieldset"`）で表示する。768px 未満の幅でラベル付きの節（追加項目を含む）が 4 つ以上ある場合は、節を UI キットの `Tabs` で切り替えて表示し、エラーのある節のタブにその件数を示す。
- AC-3 WHEN 保存が検証エラー（画面での必須・形式の検査、または API の VALIDATION、配分超過）で失敗した THE SYSTEM SHALL フォームの先頭に要約（件数と、各項目へのリンク）を表示し、試行ごとに 1 つの `role="alert"`（その試行の件数と、焦点で伝えられない項目のない文）で知らせ、最初の不正な項目へ焦点を移す（狭い画面ではその項目のタブを開く）。同じ記録の画面で保存の成功や退避の復元を挟んでも、次の失敗で再び焦点を移す。明細のエラーは明細名・行番号・列名で示す。項目のない文（配分超過など）はリンクなしで示す。各項目の下のエラーは `role="alert"` にせず `aria-describedby` で入力欄に関連付ける。要約に出る失敗ではエラーの通知（toast）を重ねない。
- AC-4 THE SYSTEM SHALL 入力が必要な項目（必須・既定値なし・編集可能）に視覚的な印と支援技術向けの `required`（`aria-required`）を付け、field の説明を補助文として常に表示して `aria-describedby` で関連付ける。
- AC-5 WHEN 記録の画面で `Ctrl+S`（macOS は `⌘+S`）を押した THE SYSTEM SHALL ブラウザの保存ダイアログを開かずに保存を実行する（保存できない状態では何もしない）。WHEN フォームに焦点がある状態で `Ctrl+Enter`（`⌘+Enter`）を押した THE SYSTEM SHALL 未保存の変更がある・新規・確定できない記録では保存し、未保存の変更が無い確定可能な下書き document では確定の確認ダイアログ（見出しの「確定」と同じ）を開く。保存中・未保存の変更がある場合の既存の制限は維持し、モーダルが開いている間はどちらも実行しない（`Ctrl+S` はその間もブラウザの保存ダイアログだけは止める）。IME の変換中のキーには反応しない。
- AC-6 WHEN 明細グリッドのセルで `Enter` を押した THE SYSTEM SHALL 同じ行の次の入力セルへ、行の最後の入力セルなら次の行の先頭の入力セルへ移り、最終行の最後の入力セルでは編集可能な場合に新しい行を追加してその先頭へ移る。`Alt+↑` / `Alt+↓`（macOS は `⌥↑` / `⌥↓`）で行を移動し、焦点は同じセルに残る。何も入力していない参照欄（焦点で開いただけの候補一覧）では `Enter` が候補を選ばず次へ進む。IME の変換を確定する `Enter` は IME に任せる（移動も行の追加もしない）。明細の外の参照欄では `Alt+↓` で候補一覧を開く。
- AC-7 WHILE 画面幅が 768px 未満 THE SYSTEM SHALL 保存・確定などの主操作をフォーム下部の固定バー（スクロール領域の下端に貼り付く sticky）に表示し、見出しの「確定」はバーへ移す。入力欄を隠さない（スクロール領域の下端に、測ったバーの高さ分の余白 `scroll-padding-bottom` を確保する。バーが 2 段に折り返しても同じ）。画面の通知（toast）はバーの上に出し、保存・確定を覆わない。
- AC-8 WHEN 未保存の入力がある状態で画面を離れた、または再読込した THE SYSTEM SHALL 入力値を利用者・テナント・会社・entity・id（新規は `new`、複製・クイック操作の新規は `new:<seed>`）ごとにタブ内（`sessionStorage`）へ退避し、同じ画面を開き直したときに「前回の入力を復元しますか」と提案する。退避するのは変更した値と変更した明細の行だけで、読取専用・サーバー所有・非表示・`restricted`（権限の field group に属する）項目と、利用者に見えない（マスクされた・出力しない）項目は保存も復元もしない。個人情報の entity（`workforce_`・`filing_payroll_`）は退避しない。保存に成功したら退避を消す。版が変わった既存記録には復元を提案せず、退避を消してその旨を示す。明示的なログアウト（認証設定の変更で全端末がログアウトする場合を含む）でタブ内の退避をすべて消す（期限切れの後に同じ利用者が再ログインした場合は残し、別の利用者がログインした場合は前の利用者の退避を消す）。記録が 403/404 で読めなくなったらその記録の退避を、entity 自体が見えなくなったらその entity の退避を消す。読み戻せない大きさの入力は退避せず（離脱の確認は「破棄して移動」になる）、期限切れ・読めない退避はタブに残さない。
- AC-9 WHEN 一覧から記録を開いた THE SYSTEM SHALL 一覧と同じ条件（検索・絞り込み・並べ替え・ページ）の前後の記録へ移動する「前の記録」「次の記録」と位置（例 `2 / 3 件`）を表示する。ページの端では同じ条件の隣のページを読んで移る。未保存の変更がある場合は既存の破棄確認を通す。一覧へ戻るリンクは元の条件の一覧を開く。一覧を経由しない（直接開いた・別の利用者や会社の）記録には表示しない。
- AC-10 THE SYSTEM SHALL 文言を日本語と英語で持ち、ショートカットの一覧をフォームのバーの `?` ボタンで表示する。

## 改訂の記録（2026-10-30、実装担当）

- AC-2: 草案は「768px 未満で 4 節以上なら節の目次（ページ内リンク）」だったが、計画 D3 と統合担当の指示はタブ。タブを採用した。タブは他の節を隠すため、エラーのある節のタブに件数を出し、要約のリンクと保存失敗時の焦点移動でその節のタブを開く（AC-3 に追記）。追加項目（ext）も 1 つのラベル付きの節として数える。ラベルの無いグループはタブ上で「その他」。
- AC-3: 各項目の下のエラーを `role="alert"` から外した（要約と同時に複数の alert が読まれるため）。フォーム以外（設定・レポート入力）の項目は従来どおり alert のまま。
- AC-5: `Ctrl+Enter` は従来「保存」だった。確定できる下書き document で未保存の変更が無いときだけ確定の確認を開き、それ以外は従来どおり保存する（既存の利用者の操作を壊さないため）。`Ctrl+S` はフォームの外（見出しなど）に焦点があっても記録の画面ならブラウザの保存を止めて保存する。
- AC-6: `Ctrl+Delete`（確認付きの行削除）は初版から外した。入力欄での「次の単語を削除」と衝突し、`Ctrl+Shift+Delete` はブラウザの閲覧履歴削除に使われているため。行の「×」ボタンは従来どおり。旧来の「Enter で同じ列の下の行へ」は「同じ行の次の欄へ」に変わる（最終行の最後の欄で行を追加する点は同じ）。
- AC-7: 固定バーは `position: fixed` ではなく既存の sticky バーを使う。761〜767px ではサイドバーが表示されるため fixed のバーはサイドバーに重なる。sticky はスクロール領域の中に収まり、フォームの末尾では本来の位置に戻るので入力欄を隠さない。途中の入力欄は `scroll-padding-bottom` で隠れないようにした。
- AC-8: 退避するのは変更した値だけ（記録の全値をタブに複製しない）。権限の field group に属する項目は利用者が見えても退避しないため、`/meta` に `FieldMeta.restricted` を加えた（現在の module に field group を使う entity は無い。テストの entity で確認）。提案中に入力を始めたら提案を取り下げ、新しい入力で退避を置き換える。退避は 12 時間で無効。離脱の確認文は、退避できたときは「入力はこのタブに一時保存され、この画面に戻ると復元できます」に変わる。
- AC-9: 一覧のページの端では同じ条件で隣のページを読む（計画の「一覧の id 列」だけでは 50 件ごとに止まるため）。router state は複製の seed と同じくセッション（テナント・利用者・会社）に結び付け、違うセッションでは使わない。移動は履歴を置き換える（戻るで一覧へ戻る）。
- ラベル付きグループは 取引先・売上請求書・仕入請求書・入出金・契約 の 5 entity に付けた。売上請求書は `currency`・`taxSummary`・`controlAccountId` を節に含め、末尾の「その他」の枠を無くした。

## 改訂の記録（2026-10-30、レビュー指摘の修正）

- AC-3: 要約全体を `role="alert"` にすると、直すたびに縮む要約が丸ごと読み直され、同じ問題での 2 回目の失敗は読まれず、エラーの toast（alert）と同時に読まれていた。要約は live region にせず、試行ごとに 1 つの alert（試行時点の件数を「…件ありました」と過去の出来事として述べ、焦点で伝えられない項目のない文を含む。`key` を試行にして毎回読ませる）を要約の中に置く。要約に出る失敗では toast を出さない（項目に対応しない VALIDATION だけ toast）。保存の成功・復元で試行の数が 0 に戻った後も次の失敗で焦点を移す（以前は動かなかった）。
- AC-5: モーダル中の `Ctrl+S` はブラウザの保存ダイアログだけ止める（以前は止めていなかった）。`event.code === 'KeyS'` の代替は、配列がラテン文字を打たないとき（キリル文字など）だけに限る（Dvorak の `Ctrl+O` を取らない）。
- AC-6: React の合成イベントには `isComposing` が無いため、明細と参照欄の IME 判定はネイティブのイベント（と keyCode 229）で行う。`Alt+↑/↓` を参照欄がグリッドへ渡すのは明細の中だけにし、ヘッダの参照欄では `Alt+↓` で一覧を開く。明細の選択欄（`<select>`）では `Alt+↓` は行の移動を優先する（一覧はクリックか F4、macOS は ↓ で開く。ui.md と manual 02 に記載）。
- AC-7: 余白を固定の 96px から、測ったバーの高さ（`--form-bar-h`）に変えた。390px で「未保存の変更」が出るとバーが 2 段（111px）になり入力欄が最大 15px 隠れていたため。768px 未満では表示を「未保存」に縮めて 1 段に保つ。toast を 768px 未満でバーの上に出す。
- AC-8: 退避の版は、入力の元になった版（フォームの状態の記録）にする。以前は props の記録の版で、未保存のまま再取得されると新しい版で書かれ、古い入力が復元・上書き保存できた。ログイン時に別の利用者・テナントの退避と期限切れ・読めない退避を消す。SSO の紐付け（全端末ログアウト）と、ログイン中のタブでのパスワード再設定でも消す。entity が meta から消えたらその entity の退避を消す。書込み時に読込と同じ上限で検査し、読み戻せない退避は書かない（以前の退避も消す）。
- AC-1（kernel）: field がすべて見えないラベル付きグループは、ラベルを付けずに `[]` で返す（隠れた節の名前を知らせない）。
