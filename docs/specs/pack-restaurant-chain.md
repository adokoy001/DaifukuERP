# 飲食店チェーンの導入テンプレート

## 目的・範囲
1法人が複数店舗を持つ飲食店で、店内・持帰りの日次売上と材料在庫をつなぐ。店舗ごとに厨房倉庫・現金勘定・店頭客を持ち、メニューはサービス品目、材料は物品品目として既存販売・入出金・在庫・会計を再利用する。

初版は1食分レシピ、店内/持帰りの税込単価、現金・カード・QRの内訳、販売数からの材料消費、材料廃棄、店舗別日次集計。カード・QR分は請求書の売掛残とし、後日の銀行入金を既存入出金で消し込む。材料の原価は在庫台帳の移動平均原価であり、日次締め自体では原価の会計仕訳を追加しない。

## 受入条件（EARS）
- WHEN packを適用する THEN 会社に固有の店頭客を冪等作成し、sampleでは2店舗・厨房倉庫・食品材料・メニューと確定レシピを作る。再適用・force再実行は既存取引とマスタを上書きしない。
- WHEN レシピを確定する THEN サービス品目のメニュー、1件以上の物品材料、正の基準単位数量を検証する。確定後は数量・材料・メニューを変更できず、使用済みレシピを単独取消できない。
- WHEN 日次締めを保存する THEN 提供方法とレシピの酒類指定から税区分を決め、既存taxの日付別率・会社の端数設定で税込金額を集計する。計算済金額・税区分・生成先参照・原価はserverOwnedである。
- WHEN 店舗の日次締めを確定する THEN 同じ店舗・営業日の有効な締めは1件とし、同時確定も直列化する。売上・現金入金・材料消費・廃棄を同一取引で作成し、不足在庫や不正金額なら全体をロールバックする。
- WHEN 現金+カード+QRが税込合計に一致しない、販売数が正でない、レシピ未確定、材料が物品でない THEN 確定を拒否する。返品・負数の売上は初版では受け付けない。
- WHEN 材料を消費する THEN レシピの1食分数量×販売数を店舗厨房倉庫から出庫し、廃棄は別の出庫に記録する。基準単位以外への換算や丸めによる数量の暗黙補正はしない。
- WHEN 日次締めを取消する THEN 現金入金、請求書、材料消費・廃棄を正規の取消経路で打ち消し、指定した訂正日を子文書へ伝える。親が有効な間、子文書だけを取り消せない。
- WHEN 日次集計を実行する THEN 店舗・営業日別の売上・税・決済内訳・材料消費原価・廃棄原価を表示する。取消は取消有効日に反映し、未来の取消で過去期間を書き換えない。読取上限では無言の欠落を起こさない。
- WHEN 未適用会社・別会社の参照・権限不足で操作する THEN 通常のkernel権限・会社分離で拒否する。内部書込capabilityは参照と計算値の必要な操作だけに限定する。

## 範囲外
別法人の連結会計、フランチャイズ精算、予約、モバイル注文、POS実機連携、勤怠・給与、加盟店手数料の自動計算、半製品の仕込製造、歩留まり・単位換算、個別注文・割引・返品、レシート発行、日次の原価会計仕訳。提供時点の店内/持帰りの意思確認は店舗が行う。

## 検証
手計算台本 `docs/domain/scenario-restaurant-chain.md` と専用PG16 DBで、2店舗・混合税率・材料と廃棄・現金/売掛の照合、再適用、並行二重締め、凍結、材料不足の全体巻戻し、会社分離、閉期の訂正日伝播、日次報告を回帰検証する。runtime登録・workspace install・migration生成と全体gateは統合担当が実行する。

## 運営管理の拡張

2026-09-12の追加仕様は [restaurant-operations.md](restaurant-operations.md)。営業予定・目標、売上ゼロ/休業、店舗提出/店長確認/本部確定、店舗範囲とBI根拠を追加した。通常sampleは引き続きマスタと確定レシピだけを作り、営業実績や目標を勝手に作らない。
