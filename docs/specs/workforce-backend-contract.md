# Spec: workforce backend / 権限・勤怠・休暇・経費・給与契約

- 作成: 2026-09-12
- 状態: implemented
- 関連: [全体仕様](workforce-platform.md) AC-2〜6/9、[ADR-0019](../adr/0019-workforce-access.md)、[日本の制度と計算境界](../domain/japan-workforce.md)

## 境界

会社所属に新しいsites scopeとsiteIdsを追加する。既存stores scopeは変更せず、新sites scopeでは明示したstoreIdsとの併用を認める。siteAccess宣言にはsiteIds、旧storeAccess宣言にはstoreIdsを使用し、会社と拠点と本人rowRulesをANDする。宣言のないentity/actionは拒否する。新scopeへの変更は管理者の明示操作で行い、既存データに権限を自動付与しない。

ロールはworkforce_employee（本人）、workforce_manager（指定拠点）、workforce_hr（人事本部）、workforce_payroll（給与・精算本部）。sites所属はemployee/manager/chain_staff/chain_managerだけを許可し、hr/payroll/adminは許可しない。会社全体でemployeeロールを付けても本人rowRulesは残る。申請者・受益者本人の承認、給与確定、経費精算は禁止する。会社所属のない/無効な利用者は従業員へ紐付けられない。

## 公開契約

`modules/workforce/src/contract.ts` が操作input、応答、ポータルの安定契約。public indexはWorkforceModule、全entity、action schemaを公開する。private write capabilityは公開しない。汎用CRUDからは状態、時刻、残高、計算結果、確認者を設定できない。内部actionもRepositoryの同じ本人・会社・拠点境界を通る。

主要entity: workforce_site、workforce_employee、workforce_attendance、workforce_punch、workforce_attendance_correction、workforce_leave_grant、workforce_leave_request、workforce_leave_usage、workforce_expense、workforce_pay_policy、workforce_pay_terms、workforce_payroll、workforce_period_lock。

本人操作は4ロールすべてで本人の従業員登録があれば利用できる。manager/hrの給与閲覧は本人の確定済明細に限り、部下の給与額は含めない。payrollは会社全体の給与処理を担当できるが、自分の確定・取消は別担当者に依頼する。通常の拠点管理者はsites所属とし、会社全体の所属を管理者が明示した場合だけその会社の拠点管理範囲となる。

`workforce.initialize_policy` は入力 `{}`、応答 `{id,version,status:'ready'}`。会社全体のadmin/hr/payrollが既存制度を保全して初期制度を準備できる。新規導入ではmodule seedも同じ処理を使い、従業員・賃金・外部控除は自動作成しない。

## 受入条件

- WB-1: REST/MCP/generic CRUD/aggregate/export/参照/監査で、社員本人・管理者拠点・給与本人の確定済明細だけという同一境界を強制する。旧チェーンと新sitesの併用と各空集合の拒否を回帰で測る。
- WB-2: 打刻はctx.nowから日本時間の勤務日を決め、秒・ミリ秒を保持する。開始/休憩開始/休憩終了/終了の不正順序、二重勤務、逆転、24時間超、古いversionを拒否。打刻keyを保存して同一入力再送を冪等化する。退勤忘れで24時間を過ぎた場合も、元の打刻を保持して未退勤から訂正申請→別人承認→勤務終了に回復できる。訂正は理由・提出者・承認者を残し、隣接勤務との重複と実休憩区間を検査する。休憩不足でも退勤事実は保存し、承認段階で確認を要求する。
- WB-3: 勤怠は日次提出→他者承認、差戻し→再提出。申請中/承認後の直接入力を凍結し、訂正承認でのみ変更する。給与確定済の期間は訂正承認・追加勤怠・有給変更を拒否。勤務日は通常日/法定休日を承認者が明示確認する。
- WB-4: 有給付与はHRが資格確認・根拠・有効期間を明示し、日数はDecimal。有給は全日または本人希望と使用者同意の半日のみで、時間単位は提供しない。重複申請と期限外を拒否し、従業員単位の同一lock内で期限順に引当・承認する。使用履歴はappend-only。却下/取消で残数と状態を整合させる。全日有給（半日2件を含む）はJST暦日ごとの実勤務と重複できず、有給・勤怠・確定済勤怠の訂正の各承認方向で検査する。記録済み休憩は実勤務から除外し、翌00:00終了は翌日の実勤務と数えない。未退勤は現在時刻までの実勤務を調べ、未知の将来時間へ延長して休暇を拒否しない。
- WB-5: 経費は本人の下書き→提出→他者拠点承認→他者本部精算。申請後金額を凍結し、差戻し時だけ本人が訂正できる。精算日/参照番号/確認者を保存し二重精算を拒否。証憑は安全な参照説明を保持し、銀行送信・会計自動仕訳の実装を装わない。
- WB-6: 給与は対象月終了後に、有効期間付き条件/制度と承認済勤怠/有給から計算する。日8h・週40hの時間外を二重計上せず、月60h超、休日、深夜を別区分に分ける。週境界は前月の同じ週の勤務も読み、月60hの累計は当月だけとする。率/基準は期間付きpolicy行とsnapshotに保存する。通常時間制・JPY以外は拒否する。JST暦日をまたぐ勤務は保存・承認できるが、暦日別の休日区分モデルを持たないため自動給与計算を理由付きで拒否する。終了が翌00:00ちょうどなら当日区間だけとして許可する。
- WB-7: 所得税/住民税/健康保険/介護保険/厚生年金/雇用保険/子ども・子育て支援金/その他控除は8名目ごとの外部算定額、根拠、明示確認が揃わない限り給与確定しない。ゼロも確認・根拠必須。端数、賃金条件、勤務明細、計算versionをsnapshotへ保存する。未承認勤怠・休暇/訂正申請がある期間、集計後にsourceが変わった給与は確定拒否。確定後は取消理由を伴う他者取消と再計算に分け、直接変更しない。
- WB-8: schema追加で既存会社所属とチェーンのデータを保持し、siteIdsは空で移行する。給与明細/賃金条件/申請/打刻の権限と並行承認・二重精算・再送をPostgreSQL 16で検証する。

## 確定と将来の条件変更

給与の重複は社員・給与月・有効な確定状態で判定する。workforce_period_lockは給与額を持たず、対象月に加えて週40hの計算元となった前月の週境界まで凍結する。隣接月の依存区間は重なってよい。ある月の給与を取り消しても、別の確定月が依存する勤怠は訂正できない。

確定した計算内容・適用範囲を変える賃金/制度/在籍日の変更は拒否する。過去の確定期間へ切り詰めた適用範囲が同じなら、将来の退職日登録や既存条件の終了日短縮、新期間の昇給条件追加を認める。未完了の勤怠・申請・経費を残した異動/無効化は先に解消を求め、元のsiteIdを持つ履歴を移し替えない。

拠点変更後の本人履歴・有給引継ぎには未対応のため、変更先と異なる拠点に有給付与台帳または有効な確定給与期間がある従業員の拠点変更は理由付きで拒否する。本日の残高がゼロでも将来付与・過去台帳を失わないよう付与履歴を検査し、給与額を読まず確定期間の最小情報で判定する。該当履歴がなく未完了業務もない異動、同じ拠点での氏名修正や将来の退職日登録は継続して認める。拠点履歴を複製・削除したり、権限を広げてこの制約を迂回しない。

月給の入退社・途中改定は対象月の暦日で按分する。月給の欠勤控除は自動推定せず、外部確認した控除に明記する。時給の有給は条件に記録した1日換算分を使い、月給の有給を二重加算しない。金額はDecimalで合計し、通常賃金・割増賃金の各合計だけを円単位で切り上げる。外部入力の手当・控除は整数円とする。

## 初期対象と制度上の限界

国内JPY・Asia/Tokyo・通常の労働時間制。就業規則/休日区分、勤怠の網羅性、HR付与資格と有効期限、税社保の外部算定を管理者が確認する。変形/フレックス/裁量、時間単位年休、複雑な複数事業所雇用、自動税社保表、年末調整/届出、振込送信は提供しない。制度の根拠と適用範囲は[日本の制度と計算境界](../domain/japan-workforce.md)を参照する。
