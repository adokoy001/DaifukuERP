# 社員管理とブラウザー内シフト推薦

状態: verified locally。日付: 2026-09-12。対象: 単一会社・拠点の月曜始まり7日間。親仕様は [従業員基盤](workforce-platform.md)。

## 目的と設計

社員の雇用期間・在籍・勤務条件・対応スキル、本人の勤務希望、拠点の必要人数をつなぎ、ブラウザー内で推薦案を計算する。実績勤怠・給与とは別の勤務計画であり、自動打刻/自動給与/法令適合認証は行わない。

外部ライブラリを追加しない純粋TypeScriptの制約検査と、seed付き貪欲初期解＋焼きなまし探索を使う。充足人数を最優先し、希望と個人目標に対する負担の偏りを改善する。最適解保証や学習済み需要予測はうたわない。Web Workerを使ってUIから分離し、停止・再実行・手直しを可能にする。制約検査はサーバーでも共有し、クライアントの推薦を信用して確定しない。

## 受入基準（EARS）

- AC1: 本部/担当管理者が社員名簿を開いたとき、検索・在籍・拠点で選び、雇用期間とシフト条件（雇用区分、スキル、目標/上限時間、勤務日数、連勤、勤務間隔）を確認/設定できる。基本社員情報は既存の人事権限を保つ。本人は他人の条件を変更できない。
- AC2: 本人が週を選んだとき、日ごとの勤務可能時間・希望・勤務不可をまとめて提出/更新できる。未提出は勤務可能と推定しない。会社/拠点/本人、expectedVersionをサーバーで確認する。
- AC3: 担当管理者が拠点/週を選んだとき、日内の勤務枠・休憩分・必要人数・必要スキルを編集でき、最小限の社員/希望/休暇/近接週の確定勤務/会社制度snapshotを取得する。給与・経費・有給理由は推薦用DTOへ含めない。
- AC4: 推薦を実行したとき、在籍期間、希望提出、勤務可能時間、有給申請日、スキル、重複、日/週の時間上限、週勤務日数、連勤、勤務間隔、休憩条件を満たす候補だけ割り当てる。半日有給も時刻境界モデルがないため当日を除外し、理由を表示する。隣接週の公開勤務も連勤/勤務間隔に含める。
- AC5: 推薦結果を表示したとき、必要/割当/不足、候補除外理由、希望一致率、社員別時間/目標、負担の偏りを表示する。欠員を隠さず、手修正・固定・再推薦できる。固定割当が違反なら黙って変更せず問題として返す。同じ入力とseed/反復数で同じ結果を返す。
- AC6: 保存/公開したとき、会社/拠点権限・社員ロック・最新snapshotの版と全制約を再確認し、古い希望や休暇を基にした案を拒否する。不足を伴う公開は理由と明示確認を要求する。下書きの社員公開は禁止する。
- AC7: 公開済み計画を改訂するとき、新しい下書きを作り、確認公開時に旧版をsupersededにして監査履歴を保つ。公開済み割当の直接編集/汎用CRUDは禁止する。本人には現在公開版の自分の勤務だけを返す。後から休暇/条件が変わったら管理画面へ要調整の根拠を示す。
- AC8: 推薦中の停止/拠点・週・会社変更/離脱が起きたらworkerを終了し、古い結果を新画面へ適用しない。375pxで横溢れなく入力/希望提出できる。一時障害では入力を保持し、401/403/404/会社変更では機密表示を撤去する。
- AC9: 100人・7日・最大42枠の合成ケースを実測し、規定反復の時間、workerサイズ、実ブラウザーの操作応答を記録する。計算上限と非対応ブラウザー/worker失敗を明示する。

## 境界と制約

初版は100人/拠点、7日、42勤務枠、1枠20人、1人1日1つの希望可能時間帯。日内勤務のみで日跨ぎ・複数拠点応援・自動需要予測・複雑な資格配置比率・休憩の時刻割当は未対応。勤務分/人数は離散整数、金銭計算を行わない。週の開始が月曜の通常制会社policyを上限・休憩条件に使うが、36協定・法定休日・変形労働時間制などの全適合性は判定しない。最小勤務間隔と連勤上限は運用条件であって一律の法定値ではない。

## 保存・履歴の契約

勤務条件は社員を親とする拠点スコープで保持し、将来入社/現在無効な社員にも管理者が設定できる。割当時の在籍・雇用期間は別途検査する。本人希望は選択週と雇用期間が重なる場合に提出でき、勤務不可の日のみ0分の区間を許可する。プロフィール未設定や希望未提出の社員を自動補完しない。

拠点/週につき下書きと公開版は各1件。社員ID順のロックと会社制度・拠点更新に共通のロックを使い、保存/公開時に再読取する。sourceRevisionは関連行の種類とID/versionをソートした正規JSONであり、下書き自身は含めずexpectedVersionで保護する。同週の公開版/割当は版に含めるが、全面改訂対象なので周辺勤務の制約には含めない。公開の改訂案はplanIdを省略しexpectedVersion=0で作り、旧公開版は新案の公開と同一トランザクションで終了する。

勤務希望/公開割当の履歴がある社員の拠点変更は、本人や新拠点から履歴を失わない異動方式を設けるまで拒否する。履歴がなければ勤務条件を保持して異動できる。将来の有効な公開割当がある社員/拠点の無効化、公開勤務日を雇用期間から除外する変更は、先に計画を改訂・取消する。休暇/条件変更は申請を妨げず、公開計画の再評価で要調整として示す。公開計画の保存データから勤怠や給与は作らない。

実測結果と未検証範囲は [作業記録](../log/2026-09-12-employee-shift-planner.md) に残す。
