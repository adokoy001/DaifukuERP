# 業務基盤の整合性と履歴契約

対象は現行の販売・購買・会計・在庫・入出金・契約および小売/不動産パック。全世界・全業種の完成を意味しない。

## 受入条件

1. WHEN 確定済み文書のシステム所有項目を汎用 CRUD から書く THEN 拒否し、残高・出所・仕訳は正規業務操作だけが更新する。内部更新でも通常の権限・監査を維持する。
2. WHEN 入出金・取消・棚卸・契約・期間締めを並行実行する THEN 最初の業務読取から集約/系列をロックし、残高と台帳が一致する。競合した操作は原子的に失敗するか再読取後に正しく成立する。
3. WHEN 明細件数が対応上限を超える THEN 全入口で明示拒否し、一部だけで検証・転記・取消しない。確定明細の移動は新旧親を検証する。
4. WHEN 出所文書から生まれた仕訳を訂正する THEN 出所業務の取消と一体で逆仕訳する。逆仕訳は一度だけ、拡張分析項目も引き継ぐ。
5. WHEN 請求を確定/取消する THEN 発行時の表示データ・統制勘定・通貨/単位・税区分を保持する。再表示は現在のマスタ変更に影響されず、取消状態が分かる。
6. WHEN 過日時点を指定した残高帳票を出す THEN 有効日のある消込事実から計算し、後日の支払によって過去の値を変えない。履歴不足がある旧データは黙って推定しない。
7. WHEN 会計期間を登録する THEN 会社内重複・年度外期間を拒否する。締めと転記は同一系列で直列化する。
8. WHEN 通貨/数量/税丸めを指定する THEN 現行の JPY・数値精度・請求単位の契約を明示し、未対応の通貨や丸め方式を対応済みとして選択させない。取引の単位はマスタ変更に追随しない。
9. WHEN 入居契約を確定する THEN 部屋の有効期間重複を排他制御込みで拒否する。敷金は契約・相手・部屋と一致し、受領後に付け替えできない。
10. WHEN 小売月締めを行う THEN 会社の月締め系列を直列化し、隣接月の期首振替と在庫評価の連続性を保持する。

## 範囲と非対応

新規の製造・工事・多通貨決済・為替評価・複数税法・倉庫ロット/シリアル機能は作らない。現行の請求連動在庫は設定可能な簡易運用として残す。将来拡張で変更すべき契約を作業記録に明記する。既存データの追加列はアプリ担当の migration に統合する。

## 今回固定する業務契約

- **金額・数量**: 請求と入出金は JPY。数量と単価の小数は保持するが、最終請求額・消込額の小数円は確定時に拒否する。端数を無断で捨てず、合意した価格/数量に修正する。通貨換算・換算差額・複数精度の通貨は未実装。汎用仕訳は Decimal 精度を保持する。
- **単位**: 商品の在庫単位と goods/service 区分は作成後に変更しない。請求明細に単位IDとコードを保存する。goods の暗黙換算を拒否し、単位無しの自由明細は `unit` を保存する。サービスの時間等は別 UOM で表現可能。単位換算マスタ・梱包換算・工程単位は次段階。
- **履行と請求**: 現在の自動入出庫は単純な請求即履行を前提とする設定。受注/発注、分納、受入検査、検収、役務の出来高、BOM/工程は専用の履行文書を追加し、その事実を出所として既存の転記ポートへ渡す。請求をそれらの代用にはしない。
- **履歴と取消**: sales/purchase settlement に有効日と符号付き額を追記し、過日時点の残高を再計算する。追記前には有効日順の累積額が常に 0..請求総額の範囲かを検証し、過去時点だけの過消込も拒否する。正規の取消だけが逆の消込と逆仕訳を同一トランザクションで作る。取消日の省略は従来どおり元の日付、`correctionDate` の指定はそれ以後の開いている日を使う。締め済み会計・在庫期間の元日に戻す操作は拒否する。
- **在庫時系列**: 移動平均は商品×倉庫の登録順に計算し、同じ系列の最新有効日より過去への転記・取消・棚卸を拒否する。同日の順番は台帳 seq。小売月締めは会社の在庫系列と同じロックを取得し、締め日以前の追加移動を拒否する。取消は当初原価の符号反転。負在庫を明示許可する旧機能では原価は暫定で、負在庫解消時の再評価/原価差額仕訳はまだない。確定原価が必要な運用は負在庫禁止を維持する。
- **勘定・表示**: 請求に確定時の統制勘定を保存し、その後の入出金設定変更に追随させない。仕訳明細には転記時の accountType/accountTaxRole を保存する。発行表示データ（発行者・受取人・明細・税・振込先）を請求確定時に保存し、再表示はその値を使う。取消表示は現在状態に応じて加える。
- **税・地域**: 税丸め単位は現状の `invoice` だけを選択可能とし、未実装の `delivery_note` は拒否する。日本の制度・税率・帳票は l10n/jp が担当する現状を維持する。共通の分類・計算ポートはあるが、日本以外の制度対応や法令適合を宣言しない。
- **分析項目・契約条件**: source/target 双方で同名に登録された ext を転記対象とする。勘定・税バケットが同じでも分析項目が異なる購買明細は分け、逆仕訳にも元の値をコピーする。税込販売の同一税区分で分析項目を一意に配賦できない場合は拒否する。契約の確定済み条件と明細は固定し、終了→後継契約で将来分を表現する。条件改定の有効日付き版管理、既発行分の自動精算は次段階。入居日は開始/終了とも含み、同じ部屋の重複する確定契約を拒否する。

### 旧データの扱い

`settlementHistory=false` は支払済額がゼロでも履歴不明を意味し、次の消込と時点残高帳票を拒否する。移行担当が元の正規入出金明細と残高を突合し、完全と判断できた記録だけ true にする。発行時 snapshot や仕訳明細の分類履歴が欠落する場合も、現在のマスタで過去を捏造せず、元資料からの復元を求める。移行 SQL と受入試験は API の migration に統合する。

請求取消も消込履歴が完全であることを前提とし、現在の支払済額ゼロだけでは許可しない。日別に相殺した消込額が最後に変動する日より前の請求取消を拒否する。同日に入金と取消が完全相殺される場合は元日の請求取消を維持する。小売締めの `correctionDate` は入金・請求・在庫の取消へ引き継ぎ、会計/在庫の締め後でも開いている翌期に正しく訂正できる。

この仕様は旧モジュール仕様に残る「システム項目改変を無視して正規化」「過去日帳票に現在残高を表示」「現在マスタで過去帳票を再描画」の記述に優先する。文書は最大 500 明細とし、既存の超過データを途中まで扱わず明示エラーとする。

## 検証

既存 unit/property/DB シナリオを維持し、レビューで再現した改変・競合・501 行・敷金付替え・重複入居・過去帳票の回帰試験を追加する。DB はレビュー専用 DB を使用し、実行環境/未検証事項を作業記録に残す。最終 gate は統合担当が実施する。
