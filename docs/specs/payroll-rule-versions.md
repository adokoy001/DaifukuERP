# Spec: payroll-rule-versions

- 状態: completed（AC-1〜10検証済み）
- 作成: 2026-09-13
- 対象: 給与・税保険・年末調整の制度データ、版選択、導入、既存証跡互換

## 目的

2026年の法定値を算定コードへ直接埋め込む構成を解消し、会社に導入した期間付き制度データと明示的な計算方式で算定する。既存の制度行、給与、課税証跡、年末調整、申告準備資料を保持する。

## 受入基準

- AC-1 WHEN 制度を計算する THE SYSTEM SHALL 会社のRepositoryから取得した検証済みpayloadと、対応するalgorithmVersionを算定器へ渡す。国別の資料・算定方式はl10nに置き、workforceは公開portを通して利用する。
- AC-2 WHEN 月次給与の制度を選ぶ THE SYSTEM SHALL 支払日、保険対象月、賃金締日を別々の適用期間で検査し、対象のない期間、競合する版、未知の算定方式、破損した資料を拒否する。最新年度や前年への暗黙fallbackをしない。
- AC-3 WHEN 年末調整の制度を選ぶ THE SYSTEM SHALL 税年と実施日を別々に検査し、年内支払資料・年齢判定日・通常年調の最終支払条件を選択した制度から導く。
- AC-4 WHEN 担当者が制度を導入する THE SYSTEM SHALL 出典・期間・方式・内容hashを提示し、会社内の給与本部権限と明示確認を再検査して不変の版情報を保存する。同版再導入は重複を作らず、競合は説明付きで拒否する。
- AC-5 WHEN 既存2026制度を読み込む THE SYSTEM SHALL 既知内容の完全一致を検査して旧形式として解決する。旧制度テーブルの列・既存行・version・更新日時を変更せず、新しい版情報は別entityへ保存する。
- AC-6 WHEN 旧形式の給与または年末調整を確定する THE SYSTEM SHALL 旧serializerと算定方式で再検査し、元資料が同じなら再計算なしで確定できる。元資料の変更・不正なsnapshotは従来どおり拒否する。確定済みの金額・JSON・課税証跡を自動変更しない。
- AC-7 WHEN 新しい計算を保存する THE SYSTEM SHALL 制度snapshotの形式版、package、hash、適用期間、algorithmVersionを保存し、確定時に資料と選択版を再検査する。
- AC-8 WHEN 利用者が給与画面を開く THE SYSTEM SHALL 対応する年度と導入済み制度を表示し、未対応年度を計算可能と表示しない。一般従業員に導入操作を見せず、会社・本人の境界をAPIで検査する。
- AC-9 WHEN 新年度データを追加する THE SYSTEM SHALL 同一方式なら算定器の年度定数を書き換えず扱える。未知年度を扱えることはproductionに登録しない合成fixtureで検証し、未検証の法定値は出荷しない。
- AC-10 WHEN 更新を公開する THE SYSTEM SHALL 旧HEADで生成した給与・年調fixtureからの互換、新migration、全gate、関連ブラウザ、出典・操作・構造文書を検証する。

## 設計上の制約

制度の導入単位は対応範囲を揃えた年間の通常給与bundle。国・通貨・税年・資料schema・方式版・複数の適用期間・確認日・出典・内容hashを持つ。任意JavaScriptや未知JSONをアップロードして実行する機能は設けない。hashは内容識別であり、発行元の署名や法令監修の証明ではない。

既存 `workforce_payroll_rules` は保持し、immutable companion entityを追加する。新旧snapshotの区別は勤怠計算の既存 `calculation.version` と別に置く。制度の訂正は上書きせず、明示的に旧版を置換する関係がある場合だけ新規算定の対象を切り替える。既存draftには必要な再計算を知らせ、確定済み記録は残す。

既存の2026制度導入actionは互換経路として保持する。対応がない年度の手動確認済み課税証跡の保存・過去結果の閲覧と、自動算定ができることは区別する。給与申告準備の対応年度・CSV仕様は独立した契約として維持する。

## 検証

旧2026payload/hashの完全一致、既存の金額境界試験、合成の将来年度と変更料率が結果へ反映する試験、期間の前日/初日/末日/翌日、欠落・競合・未知方式・hash改変の拒否を検査する。旧HEADの全migrationと合成給与資料を用意し、月次draft/confirmed、年調draft/confirmed、課税証跡・申告準備の旧結果を比較する。

会社/tenant/ロール分離、導入の重複と競合、不変性、移行で旧行を書き換えないことをDBで確認する。Webは給与本部の資料確認と導入、対応年度、一般社員の表示、390px、会社切替を確認する。全gateとsetup/復元を通してから公開する。実データの配備は独立バックアップ・復元確認と保護対象の比較を行う。

受入結果は [作業記録](../log/2026-09-13-payroll-rule-versions.md) に記載した。全gateは単体1,003件・DB668件・配備13件、通常ブラウザー72件と追加障害ケース1件が成功した。旧実装からの独立復元・更新・旧下書き確定と出力一致も確認した。

## スコープ外

未検証の2027年以降の法定値、賞与・乙欄など対応範囲の新設、税申告の直接送信、制度データの外部自動収集、任意ファイルの実行、旧業務行の再計算や更新、業界テンプレートの追加。
