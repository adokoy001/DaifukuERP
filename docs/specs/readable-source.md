# Spec: readable-source

- 状態: planned
- 作成: 2026-09-13
- 対象: 管理対象のソース整形、サイズ警告の緩和、lintと開発文書

## 目的

長い1行への圧縮で行数制限を満たす書き方を解消し、人とAIが変更・差分確認できるコードにする。業務の挙動、公開契約、制度値、既存データ、migrationの履歴を保持する。

## 受入基準

- AC-1 WHEN 開発者が整形またはCIを実行する THE SYSTEM SHALL 固定版の同じformatterと設定で管理対象のTS/TSX/JS/MJS/CJS/CSSを検査し、不整形を失敗として返す。
- AC-2 WHEN ソースを変更する THE SYSTEM SHALL 自動整形後のファイル1,000行・関数300行を空行とコメントを除いて検査し、超過を警告する。超過だけでCIを失敗させず、行の圧縮や広域lint無効化で隠さない。
- AC-3 WHEN 整形で大きい処理が顕在化する THE SYSTEM SHALL 行数だけのために分割せず、既存の型・公開export・権限・取引境界を保持する。分割は読みやすさや責務の独立性が改善する場合に限る。
- AC-4 WHEN 管理対象を整形する THE SYSTEM SHALL 生成物、配布物、依存、migration、固定fixtureのバイト契約を明示的に扱い、既存migrationを変更しない。
- AC-5 WHEN 履歴を調べる THE SYSTEM SHALL 純粋な機械整形commitを他の変更と区別できるよう記録し、git blameの除外設定と利用方法を提供する。
- AC-6 WHEN 実装を完了する THE SYSTEM SHALL 全gate、API/Web/edgeの検査、既存ブラウザ回帰を実行し、整形前後の長行・違反数と実測結果を記録する。

## 範囲

Prettierの固定依存・120文字の目安・LF、formatとformat:check、CI gateへの組込、従来の400/80制約を1,000/300の警告へ緩和。空行・コメントは読みやすさのため保持する。制度版管理の挙動変更は別仕様・branch・PRで実装する。

## 検証

整形を二度実行して差分が増えないこと、formatter checkが不整形を拒否すること、依存境界・関数/ファイル長を検査する。全既存試験とブラウザ導線を確認し、UIの代表画面を目視する。結果は対応する作業ログへ記録する。

## スコープ外

業界テンプレートの機能追加・名称変更、法定値変更、業務計算やDBスキーマの変更、過去のmigration再整形。
