# Spec: 15業界カタログと履行案件

- 作成: 2026-09-12 / approved / feat/workforce-platform
- 上位仕様: workforce-platform.md AC-8。既存5業界を維持し、10業界を追加する。

## 契約

共通の履行案件エンジンを modules/industry-operations に置く。業界ごとの伝票は10個の独立した pack に属し、固有の実列・完了条件・数量単位・請求期日の既定値・サンプルを持つ。pack-industry-catalog パッケージは指定された pack だけを遅延登録する。適用していない会社や店舗限定権限からのアクセスは kernel の既存境界で拒否する。

対象は一案件・一請求品目・一回完了・一回請求。受付下書き→開始→実績と証跡を記録して完了確定→既存売上請求を作成確定→既存入金で消込。部分請求・分割納品・返品・工程原価・複数予約資源の割当は追加しない。案件の単価と税区分を明示入力し、税率・丸め・会計転記は既存 sales/tax/accounting に任せる。税込価格の暗黙推定はしない。

- AC-1: WHEN packを適用する THE SYSTEM SHALL 業界固有の設定・品目と任意のサンプルを作り、再適用/forceでも既存伝票の状態・金額・請求先を上書きしない。
- AC-2: WHEN 案件を操作する THE SYSTEM SHALL 会社/権限/適用packを照合し、数量をDecimalで検査し、種別・単位・有効な顧客/品目を確認する。派生額・状態・請求参照を一般CRUDから変更できない。
- AC-3: WHEN 完了する THE SYSTEM SHALL 開始済み下書きであること、受付日以降の有効日、正の実績数量、受注数量以内、報告と業界別の証跡/整合条件を検証する。必須の完了条件は汎用submitでも同じhookで守る。
- AC-4: WHEN 請求する THE SYSTEM SHALL 案件を最初にロックして一度だけ既存請求を作成確定する。並行再実行も同じ請求へ収束する。請求日が完了日より前なら拒否し、下位処理失敗時は案件/請求/会計/在庫の変更を全てロールバックする。
- AC-5: WHEN 案件を取消する THE SYSTEM SHALL 取消有効日を連動請求へ伝播し、入金済みや締め期間など下位の取消制約を保つ。生成請求の単独取消は kernel の確定依存検査で拒否する。履歴不整合などで取消済み請求を参照していた場合も再請求は拒否し、案件の取消・改訂を案内する。確定案件の直接修正/削除を禁止する。
- AC-6: WHEN 集計/CSVを実行する THE SYSTEM SHALL 全対象を上限付きページ読取し、期間と取消基準日を明示する。異なる単位を合算しない。履行金額（税計算前・未丸め）は会計売上/利益と呼ばない。
- AC-7: WHEN 15業界を閲覧する THE SYSTEM SHALL 入口・一連の台本・未対応範囲を示し、10個の新業界で実DBの一業務と再適用、会社分離、権限、完了条件、並行請求、取消連動の回帰を通す。

## 固有の最初の業務

| pack | 実行する業務 | 固有の整合条件 |
| --- | --- | --- |
| wholesale | 単一品目の受注・納品実績→請求→既存自動出庫 | 注文番号・納入先・ロット・納品証跡、物品のみ、正の整数数量 |
| manufacturing | 受託加工のロット実績→合格数に応じた加工料請求 | 図面版・ロット、合格＋不良＝受注数。BOM/製造原価ではない |
| construction | 工事の独立した検収単位→検収後請求 | 現場・工区・契約参照・検収番号、完了率100% |
| logistics | 一配送便の実績→運賃請求 | 発地・着地・荷物/重量・荷数一致・受領証跡 |
| hospitality | 完了した宿泊の実績→泊数請求 | 部屋参照・到着/出発日、泊数＝日差。客室予約台帳ではない |
| clinic | 団体健診の事務受付→実施人数の請求 | 団体契約参照・会場・事務確認。診断/患者記録/レセプトを扱わない |
| care_service | 保険外生活支援の実績→時間請求 | 同意参照・支援内容/場所・確認者、15分単位。保険請求を扱わない |
| education | 団体向け講座の実施→参加人数請求 | 講座・会場・定員・出席確認、人数<=定員 |
| professional_service | 受託成果物/工数の検収→請求 | 案件コード・成果物・検収参照、15分単位の受入工数 |
| beauty_salon | 施術実績→サービス料金請求 | メニュー・担当者・施術確認、1施術単位。予約枠競合は対象外 |

卸売の在庫は既存 inventory.auto_issue_on_sales に従う。サンプルには明示した架空入庫原価による入庫下書きを一度だけ用意する。利用者がその伝票を確認・確定するまでは在庫を増やさない。自動出庫を無効化した会社では在庫を自動移動せず、その設定を勝手に変更しない。

## 選定根拠・境界

日本標準産業分類（2023年7月改定）の主要区分に対応する実用入口を選ぶ。統計分類の網羅や事業所数による上位15業種ではない。分類対応と一次資料は docs/domain/industry-catalog.md、操作台本は docs/manual/appendix-g-industry-catalog.md に記載する。給与/勤怠は workforce-platform の別機能であり、この業界の定型案件だけで法令業務全体に適合すると表示しない。

## 検証

新規専用DBだけで10業界の適用/実績/請求/入金を試す。再適用の無変更、未適用拒否、別会社参照拒否、閲覧者書込拒否、serverOwned拒否、確定freeze、数量・固有証跡エラー、同時請求の一意性、入金済み取消拒否、入金取消後の案件取消と会計/在庫復元、期間/取消日集計を確認する。rootがmigrationと全体gateを統合する。
