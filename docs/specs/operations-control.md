# Spec: 安全な導入とチェーン運営・権限・BI

- 状態: approved（利用者の導入・運営管理・権限・BIを磨き上げる指示）
- 作成: 2026-09-12
- branch: feat/operations-control
- 起点: cfa1826

## 目的と今回の境界

初期導入から本部/店舗の日次運営、利用者への権限付与、根拠を確認できる分析までを一続きで操作できる状態にする。既存の会社単位・円建て業務に、会社所属と店舗スコープ、本部確定を加える。初版のテンプレートを実務に近い台本で検証する。

## 受入基準

- AC-1: WHEN セットアップを起動する THE SYSTEM SHALL 既定で対象と変更計画だけを表示し、明示実行前はDB/設定を変更しない。対象の識別、接続権限、既知migration、空の復元検証先を検査する。
- AC-2: WHEN 導入・更新を実行する THE SYSTEM SHALL 変更前バックアップと明示した別DBでの復元検証を済ませ、秘密をログへ出さず、既存設定・資格情報・会社データを上書きしない。再実行・途中失敗からの再開を検証する。自動reset・OS/DBロールや管理権限の自動変更はしない。移行内で必要なアプリ用テーブル権限・RLSは再設定する。
- AC-3: WHEN 管理者が利用者と会社所属を操作する THE SYSTEM SHALL テナント管理者と会社業務ロールを区別し、版照合・自己昇格防止・最後の有効管理者保護・監査を実行する。無効化/権限変更をREST/MCPで再検証する。
- AC-4: WHEN 店舗限定利用者が検索・参照・更新・集計・CSVを使う THE SYSTEM SHALL 許可店舗の明示対応機能だけを利用でき、未宣言の機能・他店舗・他会社・他テナントへアクセスできない。金融/在庫への最終転記は本部が行う。
- AC-5: WHEN 日次運営を行う THE SYSTEM SHALL 店舗/営業日計画、明示したゼロ売上/休業、提出・確認・差戻し・本部確定の状態を扱い、提出中の内容と確定伝票を保護し、理由・操作担当を追える。
- AC-6: WHEN 本部や店舗が運営画面を開く THE SYSTEM SHALL 可視店舗に限定した提出状況、目標/実績、時系列、店舗比較、決済区分/未入金、在庫消費/廃棄を表示し、根拠伝票へ遷移できる。数値はサーバのDecimal計算値と一致する。
- AC-7: WHEN 再集計/CSV出力する THE SYSTEM SHALL 実行時点の条件とデータ取得時刻を表示し、古い結果・失敗後の結果・権限失効後の結果を新しい結果として出さない。同じ条件での再集計も売上と入金残高の両方を再取得する。CSVは改めてサーバが権限を検証する。
- AC-8: WHEN 既存DBを移行する THE SYSTEM SHALL 旧テナント権限の所属を明示移行し、通常実行の暗黙fallbackを残さない。元の伝票と既存テンプレートを維持し、過去の取消有効日や金額を改変しない。

## 実装と検証

権限/セットアップ/チェーン業務は個別仕様とADRへ分ける。UIは利用者管理、運営分析、レポートセンターと既存レポートを改善する。バックアップ/復元・移行・権限悪用・同時処理・取消・期間境界・CSV・PC/スマホの実操作を専用DBとブラウザで検証する。変更後に全pnpm gate、Web型/buildとE2Eを通す。

## 今回含めないもの

外部環境への本番導入、端末/POS連携、通知送信、会社間連結、多通貨/海外制度、勤怠給与、会計損益としての未実装原価配賦、任意SQLや外部データを取り込むBI基盤、SSO/MFAサービス連携。利用者へ自動メールを送らず、管理者が作成情報を管理する。既存ログイン情報のまま実運用可能という認定は行わない。
