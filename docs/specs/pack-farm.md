# 農家テンプレート（作物栽培 v1）

作物栽培の圃場・作期・農作業・資材投入・収穫を記録し、既存の在庫・購買・販売・入出金につなぐ。pack は `farm`、package は `@daifuku/pack-farm`。会社に適用した場合のみ固有画面と操作を利用する。

## 契約と受入条件（EARS）

- AC-1: 圃場を登録するとき、システムは会社内で一意なコード、名称、面積（m²）を保持する。作物は既存の物品品目と固定の在庫単位に紐付く。サービス品目は拒否する。圃場の同時栽培・間作は許容し、作期の重複を一律には禁止しない。
- AC-2: 作期を確定するとき、システムは圃場・作物・開始日・終了日の計画を固定する。作業と収穫の確定は確定済みで未終了の作期だけに許可し、作期内の日付だけを受け付ける。未確定の作期には計画用の下書きを作成できる。将来の作業・収穫は下書きにとどめ、実施日前の確定は拒否する。作期は現在状態を持つ計画文書であり、終了日は期間内の将来予約ではない。
- AC-3: 農作業を確定するとき、システムは延べ作業時間（人時）と、任意の資材明細を固定する。作業時間または資材投入が必要。資材明細がある場合、指定倉庫から既存 stock_entry の出庫を1件だけ作成・確定する。品目は物品、数量は正、単位は品目の在庫単位を使用し、暗黙の単位換算は行わない。
- AC-4: 収穫を確定するとき、システムは作期の作物品目・在庫単位、数量、利用者が明示入力した評価単価（0以上、円/在庫単位）を固定し、指定倉庫に既存 stock_entry の入庫を1件だけ作成・確定する。評価額は数量×評価単価を既存在庫と同じ小数6桁四捨五入で固定する。収穫評価は在庫評価であり、生産原価・利益・会計仕訳を自動算定しない。
- AC-5: 在庫生成が失敗したとき、システムは農作業・収穫の確定を含めて同じトランザクションで取り消す。確定伝票の直接変更、生成在庫参照の偽装、生成在庫だけの取消を拒否する。農作業・収穫を取り消すとき、訂正日を子在庫伝票へ引き渡し、逆在庫が失敗すれば親取消もロールバックする。数量不足・在庫締め・遡及禁止は既存在庫基盤に従う。
- AC-6: `farm.close_season(seasonId, closedDate)` を実行するとき、システムは作期をロックし、下書きの作業・収穫が残る場合、最新確定日より前の場合、作期外または将来日を拒否する。終了後は新規作業・収穫を受け付けない。訂正の取消は許容し、終了の再開は v1 対象外。作業・収穫の新規作成と確定も同じ作期ロックで終了操作と直列化する。
- AC-7: `farm.season_summary(from,to,asOf)` を実行するとき、システムは期間内の作業人時、収穫数量・評価額を圃場／作期／作物単位で集計する。取消有効日が asOf より後の記録は含め、取消有効日以前を含めた当日以降は除く。異なる在庫単位の数量は合計しない。500件ページを全件読み、上限超過は明示拒否して部分集計を返さない。資材消費金額は生産原価として配賦しない。
- AC-8: seed は農業用単位とデモ用倉庫の不足分のみを追加する。sample は識別コードで既存を維持し、圃場・作物・作期計画、下書きの作業／収穫、販売先／仕入先を追加する。繰り返しても重複せず、サンプル適用だけで在庫や仕訳を計上しない。サンプル作期は未確定で、利用者が確認して確定する。
- AC-9: 権限・会社・tenant 分離は Repository/Context に従う。農業操作は inventory、閲覧は viewer/accounting/sales/purchasing に許可する。品目参照を含む通常の担当者は inventory + viewer、販売・入金は対応する既存ロールを併用する。serverOwned は private capability の正規内部更新だけ許可する。

## 実装の範囲

固有エンティティ: `farm_field`, `farm_crop`, `farm_season`, `farm_work`, `farm_material_line`, `farm_harvest`。在庫生成は通常の stock_entry を正規APIで作り、親の serverOwned `stockEntryId` 参照で依存保護する。既存モジュールの polymorphic source を拡張しない。

依存: partner/product/tax/accounting/sales/purchase/payment/inventory/l10n_jp。販売時の自動出庫は既存の会社既定倉庫から行うため、収穫倉庫を既定にするか販売前に在庫移動する。既定設定を pack 適用で勝手に置き換えない。現基盤の財務通貨は JPY、在庫数量・単価は小数6桁。日付は会社のローカル日付。在庫評価単価0は明示的な利用者判断で許容する。

未対応: 農薬の法定使用台帳・使用基準判定、肥料成分・散布濃度計算、補助金申請、JA/市場連携、栽培予測、畜産、農機保守、労務給与、ロット・個体・食品トレーサビリティ、等級別選果変換、複合単位換算、原価配賦・仕掛品・農業固有の決算仕訳。適用可能性の説明であり法令適合を保証するパックではない。
