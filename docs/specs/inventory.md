# Spec: inventory（在庫 — 薄く: 倉庫・入出庫伝票・在庫台帳・棚卸・移動平均）

- 状態: approved ／ モジュール: modules/inventory（`@daifuku/mod-inventory`、module name `inventory`）／ 依存: product, partner, sales, purchase, accounting（読み取り: 勘定科目コードの解決のみ）
- ADR: 0005（append-only 台帳）, 0006（docstatus）, 0010（Decimal）, 0013, 0014 ／ 作成: 2026-09-11 ／ 作成者: orchestrator
- 出典: 移動平均法・三分法は docs/domain/inventory.md（新設。国税庁「棚卸資産の評価方法」タックスアンサー No.5602 等、URL と確認日を書く。WebFetch できなければ【未確認】と明記）

## 目的
小売テンプレート（Phase 2T）の前提。数量と移動平均原価を追い、在庫照会・棚卸差異・在庫金額（期末商品棚卸高の仕訳の元）を出す。**仕訳は切らない**（三分法: 仕入は purchase が 仕入高 に、売上は sales が 売上高 に転記済み。期末の商品棚卸高は accounting の仕訳を手で／pack のアクションで切る）。

## 受入基準（EARS）
- AC-1 Entities: `warehouse` (code unique, name, isDefault bool; seed 1 件 `MAIN` 本店/主倉庫 isDefault=true), `stock_ledger` (**append-only**: date, warehouseId ref, productId ref, qtyDelta quantity, unitCost money (移動平均後の単価), costDelta money, balanceQty quantity (after), balanceCost money (after), sourceEntity text, sourceId uuid, seq int; permissions: read for inventory/sales/purchasing/accounting/viewer; create only through module code (no generic create/update/delete: declare `ops` or a guard that rejects non-system writes — check how attachments/audit forbid deletes and follow it), `stock_balance` (productId×warehouseId unique; qty, avgCost, value = qty×avgCost, updatedAt) maintained by the module.
- AC-2 Document `stock_entry` (naming `{ prefix: 'STK-', period: 'year' }`): type enum `receipt | issue | transfer | adjustment`, date, warehouseId (from), toWarehouseId (transfer only), partnerId nullable, note, sourceEntity/sourceId nullable (set by hooks when created from an invoice); lines `stock_entry_line`: productId ref required (goods only — service → ValidationError with hint), quantity (> 0), unitCost money (receipt/adjustment-in: required; issue/transfer: computed from avgCost at submit), amount computed.
- AC-3 WHEN a stock_entry is submitted THE SYSTEM SHALL append stock_ledger rows and update stock_balance with **移動平均法**: receipt → newAvg = (qty×avg + inQty×inCost) / (qty+inQty) (Decimal, keep 6 decimals for avgCost; ledger costDelta = inQty×inCost); issue → costDelta = −outQty×avg (avg unchanged); transfer → issue at from + receipt at to with the same unit cost; adjustment → signed quantity (lines carry `direction` in/out via type `adjustment` + line field `sign` enum in/out). Negative stock: allowed only when setting `inventory.allow_negative_stock` (default false) → else StateError with hint showing available qty.
- AC-4 WHEN a submitted stock_entry is cancelled THE SYSTEM SHALL append the reverse ledger rows (never delete) and update balances (avgCost recomputed the same way; if the reversal would produce negative stock and negative is not allowed → StateError).
- AC-5 Hooks on other modules' documents (registered in inventory's `hooks()` — inventory depends on sales/purchase, not the reverse): WHEN a `purchase_invoice` is submitted and setting `inventory.auto_receipt_on_purchase` (default true) THE SYSTEM SHALL create+submit a `stock_entry` receipt into the default warehouse for its goods lines (unitCost = line 税抜 unit price), sourceEntity='purchase_invoice'; WHEN a `sales_invoice` is submitted and `inventory.auto_issue_on_sales` (default true) → issue from the default warehouse for goods lines; WHEN those invoices are cancelled → cancel the linked stock_entry (find by sourceEntity/sourceId). Lines whose product is a service are skipped. If no goods lines → no stock_entry.
- AC-6 Document `stock_count` (棚卸, naming `CNT-`): warehouseId, date, lines `stock_count_line` (productId, countedQty, systemQty (filled at validate from stock_balance), varianceQty computed). WHEN submitted THE SYSTEM SHALL create+submit an `adjustment` stock_entry for the non-zero variances (in/out at current avgCost), sourceEntity='stock_count'.
- AC-7 Reports (TableResult from `@daifuku/kernel`): `inventory.stock_on_hand { warehouseId?, asOf? }` (per product×warehouse: qty, avgCost, value; totals value; asOf → replay ledger up to date), `inventory.ledger { productId, warehouseId?, from, to }` (movements with running balance), `inventory.valuation { asOf }` (per product: qty, avgCost, value; total = 期末商品棚卸高 の元), `inventory.count_variance { countId }`.
- AC-8 Settings (registerSetting): `inventory.allow_negative_stock` bool, `inventory.auto_receipt_on_purchase` bool, `inventory.auto_issue_on_sales` bool, `inventory.default_warehouse` text (code; default 'MAIN').
- AC-9 Permissions: role `inventory` all ops on warehouse/stock_entry/stock_count; `purchasing` create/submit receipt; `sales` read; `accounting` read; `viewer` read; admin all. Menus: 在庫（倉庫、入出庫、棚卸、在庫照会、在庫台帳、在庫評価）.
- AC-10 Tests: unit (pure moving-average service with fast-check property: value == ΣcostDelta; avgCost never negative; receipt then full issue leaves qty 0 and value 0 within 1e-6), db tests per AC (`daifuku_test_inventory`): receipt/issue/transfer/adjustment, cancel reversal, negative-stock refusal, auto receipt/issue from purchase/sales invoices (submit a purchase invoice with 1 goods + 1 service line → 1 stock_entry with 1 line), stocktake variance → adjustment, reports.
- AC-11 Golden: `test/golden/moving-average.json`: receipts 10 @100, 10 @120 → avg 110; issue 5 → value 1,650; receipt 5 @ 130 → avg 120 (=(15×110+5×130)/20=2,300/20... **compute it yourself and show the derivation in the log**).
