# POS受信・グループ連結精算・FC精算

状態: 実装済み・統合受入済み（[検証記録](../log/2026-09-12-enterprise-operations.md)）。2026-09-12。親仕様: [enterprise-operations](enterprise-operations.md)。根拠: [POSとグループ会計](../domain/pos-group-accounting.md)。

## 境界

POSはSquareの完了決済/完了返金を署名付きWebhookから受信し、会社・加盟merchant・locationの対応を確認して決済仮勘定へ自動転記する。支払総額から商品・税率・税額・在庫を推測しない。raw本文は署名/ハッシュ確認だけに用い、永続資料は外部ID・完了状態・金額・日時・SHA256などの最小正規化値とする。顧客氏名・カード情報・emailを保存/ログ出力しない。実サービスの秘密/接続先がない状態を接続成功と呼ばない。

連結は同一tenant・JPY・同一期の許可会社の試算表を、完全な勘定マッピングと会社別snapshotに固定し、貸借一致した消去/調整を加える独立した連結精算表。単体仕訳を変更しない。連結範囲、資本連結、持分法、のれん、税効果、外貨換算、法定開示を自動判定/作成するものではない。初版の換算はJPY同士の1:1のみで他通貨を拒否する。

FCは契約の有効期間・請求/支払の立場・税込/税抜売上基準・率と定額・端数/税区分を固定し、根拠資料付き月次売上を確認して既存請求と入出金へ接続する。初版は同一会社内の本部請求または加盟店支払を記録し、相手会社帳簿への自動記帳や全オープンアカウント相殺は行わない。売上申告資料は担当者が承認済み資料と照合した確認値と資料番号・説明。既存伝票番号も説明に記録できるが、その伝票の自動照合・集計機能は含まない。POS決済額を税抜売上に推定変換しない。

## 受入基準

- P1: Square署名を検証するとき、設定済みの正規通知URL+raw bodyをHMAC-SHA256/定時間比較で検査し、改変・不一致・未設定・別merchant/locationを拒否する。
- P2: 完了決済/返金を受けたとき、eventIDと外部取引IDを別々に一意化し、同一ID異内容、異通貨、未知状態を成功扱いしない。未完了通知は受信履歴だけ、完了通知は一度だけ仕訳にする。
- P3: 返金が先着したとき、先行決済待ちを記録して再試行でき、累積返金は元決済額を超えない。順序逆転・重複・同時受信でも借貸/残額が変わらない。
- P4: 転記が期間締めなどで失敗したとき、inboxと失敗状態を保持し、副作用はsavepointでrollbackする。手動再試行は元資料の内容を変更しない。訂正取消は有効日と理由を記録し元仕訳を反転する。
- G1: 連結資料を作成/表示/確定/出力するとき、含まれる会社全ての最新所属・会計閲覧権限を再確認する。通常generic CRUD/履歴経由に許可外のsnapshotを出さない。
- G2: 対象期間の試算表と使用勘定全件を読み、欠落mapping・重複会社・非JPY・不一致期間・上限超過を拒否する。ゼロ会社も明示的snapshotを持つ。
- G3: 元帳のversion集合とmappingをsnapshot化し、最新でない下書きの確定を拒否する。確定には全会社の対象期間締めと借貸一致、消去・調整の説明を要求する。
- G4: 確定取消/改訂は履歴を保持し、単体帳簿を変更しない。会社間取引は人が確認した消去明細に限定し、自動的に債権債務を一致とみなさない。
- F1: 契約/月次資料を保存するとき、有効期間・JPY・売上基準・率/定額・税込税抜整合と版を検証する。確定後に契約条件・売上資料をすり替えない。
- F2: 精算を確定するとき、確認済み売上基準×率+定額をDecimalで算定し、既存税計算と請求書へ転記する。同じ契約・月の同時操作/再試行で二重請求しない。
- F3: 入金/支払は確認画面のexpectedBalanceとロック後の請求残額が一致する場合に既存paymentを一度だけ作成し、取消は支払→請求の順で同一transactionに反映する。別経路の入出金が残る請求の取消は拒否する。
- F4: 失敗時は資料と履歴を壊さず、取消後は新しい資料として改訂できる。生成請求・paymentの独立取消は所有元actionへ誘導する。

## 初版の運用契約と上限

- Squareの原資料日はtransaction `created_at`のAsia/Tokyo営業日。受信日や更新日で後から動かさない。遅延完了・締め済み原資料日の取扱いは担当者が確認して再処理する。通知受信後の処理は同期で、失敗をinboxへ記録できれば202と状態を返す。基盤DB障害で受信自体ができない場合は非2xxでproviderの再送対象となる。Webhookの最大24時間の配信期間を超えた未受信資料の回収（Events API/polling）は未実装。
- 初版は内部POS連携店舗を会社ごとに管理し、同一merchant/locationをサーバの接続設定で重複登録できない。既存の飲食店店舗・商品・在庫との自動対応付けや、決済手数料・銀行振込額との自動照合は行わない。店舗の仮勘定変更は以後の決済だけへ適用し、返金は元決済の科目snapshotを使う。先行返金の自動再処理は1受信につき500件、残りは明示保留のまま手動再試行できる。
- 連結の上限は20会社、各社2000勘定/240会計期間/対象終了日以前のposted明細20000件、mapping合計10000件、調整200組・各100行。上限超過は部分集計せず拒否。確定には期首残高に寄与する過去期間も締め済みであることが必要。ゼロ残高勘定もmappingする。
- FC契約が月途中で開始・終了する場合の定額按分や例外料率は未対応。月全体が契約内の正の精算料だけを請求生成する。ゼロ額月は請求を生成せず明示拒否する。契約変更は使用前のみ、使用後は新しい契約コードで将来期間を登録する。取消後に同じ契約/月で作成すると別の精算IDと請求書となる。
- FC操作のaccounting権限に加え、請求生成・取消には既存のsalesまたはpurchasing権限が必要。権限の内部昇格は行わない。外部で作成した部分入出金があるとき、残額をFC操作で入出金できるが、精算取消は残存する外部入出金を整理するまで拒否される。
- Web専用画面: `/commerce/pos`, `/commerce/group`, `/commerce/franchise`。入力は同一identityの一時的な取得失敗では保持し、401/403/404・会社変更では資料を撤去する。確定/取消のversionは操作画面を開いた時点の値に固定する。
