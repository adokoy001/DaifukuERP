# 銀行明細・確認消込・支払ファイル

商流拡張の銀行部分。銀行との API 契約、銀行への接続・送信・実送金は対象外。

## 受入基準

1. WHEN 全社範囲の accounting / admin が操作する THEN 現在の tenant/company 内だけで処理する。店舗・拠点限定、viewer、relay は明細、口座、出力を取得できない。
2. WHEN UTF-8 正規 CSV を選ぶ THEN プレビューで全行の形式、重複、件数・入出金額を確認し、内容 hash を再確認してから一括取込する。上限 500 行 / 500 KB。エラー時は全行を取り込まない。
3. WHEN 同じ口座・externalId が再到着する THEN 同じ内容は再作成せず、異なる内容は競合とする。externalId は銀行問い合わせ番号だけから推定しない。取込事実は変更・削除できない。
4. WHEN 照合候補を表示する THEN 金額、方向、日付、取引先名の根拠を示し、自動確定しない。候補と確認の間の版・残高変更を再検証する。
5. WHEN 明細を既存の確定済み入出金伝票へ確認する THEN 同額・同方向・同預金科目だけを関連づける。追加仕訳・二重入金を作らない。
6. WHEN 明細から請求書への入出金を作成する THEN 未決済残高以内の明細全額を既存 Payment 経路で確定する。伝票、残高、仕訳、関連は同一トランザクション。二重確認は既存結果を返し、応答喪失時も再作成しない。記帳日は既定で明細日。後日の訂正取消後に再照合する場合は利用者が明細日・請求日以降、本日以前の記帳日を明示し、既存の過去残高保護を維持する。明細の実日付は変えない。
7. WHEN 消込を取り消す THEN 履歴と理由を残す。銀行起点の伝票は既存取消経路で反対仕訳・請求残高を戻す。既存伝票への関連だけなら関連だけ解除する。取消済み照合の再送が新しい照合を取り消さない。
8. WHEN 汎用 CRUD / MCP から取込、照合、支払バッチを変更する THEN 拒否する。関連中の Payment は銀行の取消操作を通す。
9. WHEN 支払バッチを準備する THEN 未払請求書、残高、受取人・依頼人口座の版と内容を凍結する。同じ未払請求書の重複バッチを防ぐ。出力直前にも初回だけ現状を再検証する。
10. WHEN ファイルを出力する THEN 作成・再取得のみであり送金済み、支払済み、仕訳済みにはしない。出力済みデータの再取得は同じ bytes とする。取消は銀行側依頼を取り消さず、確認理由を必須にする。
11. WHEN 120 byte 総合振込 profile を選ぶ THEN 公式配置、許可文字、桁数、件数・金額合計を検査し、切り捨てや文字の推定置換をしない。改行なし / CRLF を明示指定する。
12. WHEN 機微情報を表示する THEN 一覧口座は末尾だけを表示する。口座全桁と出力 snapshot は専用 accounting 操作だけで返し、汎用公開 DTO / 監査の隠し項目から除く。生 CSV 全文は保存・監査しない。

## 正規 CSV

ヘッダーは `externalId,bookedOn,direction,amount,description`。日付は `YYYY-MM-DD`、方向は `receive` / `pay`、金額は符号・区切り・小数のない正整数 JPY。摘要は任意の文字列。UTF-8 BOM、CRLF/LF、CSV 引用符に対応。取込時に文字コードの自動推定をしない。

## 検証

純粋 CSV / 固定長 bytes 試験、DB で会社・権限境界、二重取込・消込、競合、取消、汎用操作拒否、出力で残高・仕訳不変を確認する。実銀行サービスへのアップロード、送金、金融機関別受入は未検証。一次資料は [銀行連携の根拠](../domain/japan-bank-integration.md)。
