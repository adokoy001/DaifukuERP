# UI refresh — 操作を確かめながら進められる業務画面

## 目的
白いパール調の背景、藍色のナビゲーションと紫・シアン・コーラルのアクセントで、大福帳を読みやすく親しみやすい業務アプリにする。見た目と同時に、メタデータ駆動フォームの所有権・初期値・未保存状態を整合させる。

## 受入条件 (EARS)
- WHEN 利用者がホームを開く THEN 会社の業務領域、伝票の状態別件数、次の操作、レポートへの入口を日本語/英語で提示する。架空の業績や増減率を表示しない。
- WHEN 画面幅が狭い THEN ナビゲーションを開閉でき、本文を妨げず、表のみ必要に応じ横スクロールできる。
- WHEN モバイル幅で概況カードを表示する THEN ラベルと数値を別の列、補足を次の行に配置し、文字が重ならない。
- WHEN キーボードや動きを抑える設定を利用する THEN 明瞭なフォーカス表示、ラベル、コントラスト、reduced-motion を保つ。
- WHEN メタデータが serverOwned を指定する THEN 入力・必須検証・送信対象から除外する。リテラル defaultValue を持つ入力は同じ初期値を表示する。
- WHEN 商品を明細で選ぶ THEN 商品名・単位・税区分・標準価格を利用可能な列に設定し、利用者がその後編集できる。参照は検索で選び、表示名を使う。
- WHEN 利用者に更新権限がない THEN ヘッダ・明細を編集させず、保存ボタンを表示しない。
- WHILE 未保存の変更または保存中の処理がある THEN 確定・取消・削除など競合する操作を無効化し、その理由を表示する。ページを離れる際に変更消失を確認する。再取得は未保存入力を上書きしない。
- WHEN フォームと JSON 入力を切り替える THEN 現在の入力を相互に引き継ぐ。変換できない入力では切替を止めエラーを表示する。
- WHEN CSV を出力する THEN テキスト列の数式開始文字を無害化し、負の数値列は数値として維持する。
- WHEN 入力検証に失敗する THEN 関連項目またはフォームの明瞭なメッセージで修正箇所を示す。
- WHEN 明細を一時的に無効化する THEN 保存中・処理中・競合・権限・確定後の理由を区別して表示する。
- WHEN 読み取り専用の taxSummary を表示する THEN 保存された区分・税率・税抜・税額・税込を表で読みやすく示し、金額を再計算しない。不明な形式は確認できる原文を保持する。
- WHEN 取消を確認する THEN その時点の訂正日入力値を送信し、空欄の場合だけ省略する。画面からの請求書作成・商品補完・保存・未保存時確定阻止・確定・日付指定取消を一連の回帰で検証する。
- WHEN 新UIの操作を案内する THEN 旧版スクリーンショットであることを明記し、不要になった回避手順を更新して、操作変更の補遺をマニュアルから参照できるようにする。

## 範囲外
業務データの変更、独自権限判定、追加フレームワーク、ダッシュボード専用集計 API、新しい業界機能、未実装の業務フロー。サーバ側の所有権・権限検証は別担当の kernel/API 変更で担保する。

## 検証
純粋関数の回帰テストで初期値・送信除外・商品補完・JSON同期・CSV安全性を検証。typecheck、Web build、既存 Web unit を実行する。ルート担当が承認済みの隔離環境で画面を起動し、desktop/mobile、明細追加、未保存確定阻止、閲覧権限、スクリーンショットを確認する。未実行は作業ログに明記する。
