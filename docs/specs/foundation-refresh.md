# Spec: foundation-refresh

- 状態: approved
- 対象: apps/api、apps/mcp、共通 runtime、移行・起動・検証、計画の整合
- 作成: 2026-09-12
- 授権: 利用者の「共通基盤の補強と、不具合の解消と、UIの改善」

## 目的

2026-09-12 の全体レビューで確認した不整合を解消し、現行の日本向け業務を安全に拡張できる共通契約へ整える。kernel、業務側、UI の個別受入基準は foundation-kernel、foundation-domain、ui-refresh に分ける。

## 受入基準

- AC-1: WHEN MCP から操作・リソース参照する THE SYSTEM SHALL 現在の利用者・権限・テナント・会社を検証し、失効後の操作を拒否する。
- AC-2: WHEN .env または環境変数でパックを選ぶ THE SYSTEM SHALL 登録前に設定を解決し、REST と MCP で同じ定義集合を公開する。
- AC-3: WHEN 実行時にパックを無効にする THE SYSTEM SHALL データ構造を保持し、移行生成は導入済みスキーマ全体を用いる。暗黙の表・列削除は拒否する。
- AC-4: WHEN 添付を取得する THE SYSTEM SHALL 現在の会社・テナントの保護された参照から格納キーを検証し、不整合なキー・内容を拒否する。
- AC-5: WHEN 既存データ入り DB を新スキーマへ移行する THE SYSTEM SHALL 既存の業務データを保持し、再適用可能である。
- AC-6: WHEN 変更を完了と報告する THE SYSTEM SHALL 型・lint・unit・DB・主要画面操作の実行結果と、未実施の範囲を記録する。

## 方針

- 同一リポジトリ内の作業ブランチで実装。元の main は保持する。
- API/MCP のモジュール・パック一覧は共通のアプリ用 runtime に集約する。スキーマの所有と機能の利用設定を分離する。
- 認証の identity と、その時点の authorization を分離する。業務 DB 操作は app role の Context を通す。
- データベースは専用のローカル検証環境を使い、既存の開発データを初期化しない。
- 製造・海外制度などの業種機能を新規に作り切ることは含めない。共通契約と現行の不具合を対象にする。
- 公開・外部サービスへの移行は今回の対象外。

## 検証

1. 現行レビューの再現例を対応する回帰テストにする。
2. pnpm gate、実データ入り移行、API/MCP の権限・構成試験を実行する。
3. 新しい UI から起票・保存・確定・入金・訂正と、モバイル幅を確認する。
4. docs/log、STATUS、HANDOFF、PLAN に実測した結果と残る適用範囲を記載する。
