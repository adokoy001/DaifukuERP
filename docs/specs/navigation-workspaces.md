# Spec: navigation-workspaces

- 状態: verified（全gateと、再試験を含む69件の個別ブラウザ確認が完了）
- 対象: `apps/web` のナビゲーション、ホーム、業務分野入口、操作文書
- 依存: 既存 `/meta`、本人・会社情報、entity/action/report の公開契約
- 作成: 2026-09-13 ／ 作成者: agent

## 目的

利用できる画面が増えても、左メニューを長くスクロールせずに業務の目的から画面を選べるようにする。ホーム・業務分野入口・全画面検索を共通の画面カタログから構成し、開いた画面では現在位置と上位への戻り先を示す。既存の業務URL、API認可、入力保護を維持する。

## 現行導線の確認

変更前のサイドバーは、専用業務画面、moduleのメニュー、折り畳みのレポート、すべてのentityを個別に並べている。画面が複数の経路に重複し、未知の業種を追加するたびに縦方向へ増える。ホームも全moduleの伝票・マスターを展開し、伝票件数を取得している。マニュアル02、03、06、07、付録C/D/Eにはこの旧配置を直接指定した手順がある。

## 入口の構成

| ID | 業務分野 | 主な用途 |
| --- | --- | --- |
| `sales` | 販売・仕入 | 取引先、見積、受発注、請求、契約 |
| `inventory` | 在庫・商品 | 品目、倉庫、入出庫、棚卸 |
| `workforce` | 人事・労務 | 従業員、勤怠、シフト、給与、勤務制度 |
| `finance` | 会計・資金 | 会計、入出金、銀行、連結、FC精算、申告準備 |
| `operations` | 店舗・連携 | 店舗運営、業界別の業務、POS、機器連携 |
| `reports` | 分析・レポート | レポートセンター、ピボット分析 |
| `admin` | 設定・管理 | 会社設定、利用者と権限、業界テンプレート |
| `other` | その他 | 未分類のmoduleが公開する画面 |

`/` はホーム、`/workspaces` は全画面の一覧・検索、`/workspaces/<workspace>` は業務分野ごとの入口とする。分野内は目的別の専用画面とマスター・記録・レポートを選べる。個別のtable帳票は「分析・レポート」に集約し、元のmoduleを検索情報に残す。分類は表示の整理であり、moduleの所有関係や会社・拠点・本人の権限を変更しない。

## 受入基準（EARS）

- **AC-1** WHEN メニューを表示する THE SYSTEM SHALL ホーム、自分の勤怠・申請（利用可能な場合）、全画面を探す、空でない業務分野を入口として示し、全entity・全report・全moduleメニューをサイドバーへ展開しない。
- **AC-2** WHEN 画面カタログを構築する THE SYSTEM SHALL 閲覧可能なmetadataと専用画面の利用条件を使い、同一URLを一度だけ掲載し、伝票の従属明細を独立した入口から除く。未分類moduleの公開画面は「その他」で探せるようにする。
- **AC-3** IF 会社・role・action・entityの利用条件を満たさない THEN THE SYSTEM SHALL 該当する入口を掲載しない。入口の表示条件はAPIの認可を代替せず、既存の直URL・取得・保存の認可を保持する。
- **AC-4** WHEN `/workspaces` または業務分野入口で画面名を検索する THE SYSTEM SHALL 日本語・英語の名称、別名、説明、module、URLから対象を絞り込み、業務画面・マスターと記録・帳票・操作・設定の種別と組み合わせて探せるようにする。全角・半角、大文字・小文字、カタカナ・ひらがなを正規化し、空白区切りは全語一致とする。一致件数と該当なしを示し、24件のページ移動ですべての一致結果へ到達できるようにする。検索語・種別・ページをURLに保持する。業務記録の中身を検索するAPIは追加しない。
- **AC-5** WHEN 専用画面カード・entity・report・actionを開く THE SYSTEM SHALL カタログで許可した既存のアプリ内URLへ遷移し、module menuに含まれる未知の外部URLや未対応routeをそのままリンクにしない。
- **AC-6** WHEN entityの一覧・新規・詳細または専用画面を開く THE SYSTEM SHALL ホームから業務分野・一覧・現在画面へ辿れるパンくずを示し、現在項目はリンクと区別する。直接開いたURLでも閲覧可能なmetadataから位置を解決する。
- **AC-7** WHILE 入力画面に未保存の変更がある WHEN ホーム・業務分野・パンくず・メニューから離れようとする THE SYSTEM SHALL 既存の変更破棄確認を通し、取消した場合は現在の入力を保持する。
- **AC-8** WHEN 小画面でメニューを開く THE SYSTEM SHALL キーボードで操作できるdrawerを示し、Escapeと閉じる操作を扱い、閉じた後は開いたボタンへフォーカスを戻す。メニューを開いていない時に非表示リンクへフォーカスしない。
- **AC-9** WHEN ホームを開く THE SYSTEM SHALL 業務分野の選択を主な入口とし、全伝票・全マスター・全帳票を繰り返し展開しない。「伝票の状況を確認」を開いた場合に、選択中のmoduleの伝票件数だけを取得する。初期選択は販売、利用できなければ先頭の伝票module、それもなければ先頭moduleとする。初回表示や画面を探す操作で全entityの件数を取得しない。
- **AC-10** WHEN 会社・権限情報の読み込み中または取得エラーになる THE SYSTEM SHALL 既存の読み込み・再取得・会社アクセスエラー処理を維持し、他社の画面構成や未許可の対象を新しい会社の入口として残さない。
- **AC-11** WHEN 表示言語を切り替える THE SYSTEM SHALL 入口・分類・検索・パンくずの日本語と英語を切り替え、同じURLへの対応と安定した分類を維持する。
- **AC-12** WHEN 操作説明を読む THE SYSTEM SHALL 新しい入口から既存機能へ辿れる手順を示し、旧サイドバーのスクリーンショットと現在の配置を区別する。検証結果は実施した証拠に限定する。

## 変更範囲

画面カタログ・分類・検索・現在位置の純粋helperは `lib/navigation.ts` を入口とし、`buildNavigation`、`searchNavigation`、`findNavigationEntry`、`findNavigationWorkspace`、`workspaceForModule` を共有する。`sidebar.tsx`、`home-page.tsx`、共通layout、業務分野入口、専用のUI部品とスタイル、関連試験、設計書・マニュアル・索引を更新する。具体的なhelperの配置は実装後に [アーキテクチャ](../architecture/navigation-workspaces.md) へ記録する。

## スコープ外

- お気に入り・最近使った画面・個人設定の保存、利用者別の自由なメニュー編集。
- 業務データを横断する全文検索、承認件数などの新しい集計API。
- module/packの業務契約、DBスキーマ、税・給与・会計ロジックの変更。
- 既存URLの改名、閲覧条件や認可の緩和。

## 検証手順

1. カタログのunitで全分野・未知module・URL重複・明細除外・許可されない専用画面・検索正規化・安定順序・パンくずを確認する。
2. デスクトップでホーム→分野→一覧→新規/詳細、全画面検索→専用画面、レポートを開き、既存URLが保たれることを確認する。
3. 権限を絞ったfixtureと会社切替で、利用不可の入口と空分野が出ないことを確認する。
4. 未保存フォームからパンくず・分野へ移動し、破棄確認の取消で入力が残ることを確認する。
5. 390px幅とキーボード操作でメニュー開閉、Escape、フォーカス、リンク遷移、横はみ出しを確認する。
6. 日本語・英語と該当なしの検索結果を確認する。既存のフォーム・帳票・従業員導線の回帰試験を行う。
7. `pnpm gate` と文書リンク検査を実行し、実行結果を `docs/log/` に記録する。この仕様書の検証手順は実行済みの証拠ではない。

## 未決事項

なし。文言・カードの順序・表示の分割は受入基準の範囲で実装時に調整する。
