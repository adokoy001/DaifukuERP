# Spec: contract（継続契約と定期請求 — 薄く）

- 状態: approved ／ モジュール: modules/contract（`@daifuku/mod-contract`、module name `contract`）／ 依存: partner, product, tax, sales
- ADR: 0006, 0010, 0013, 0014 ／ 作成: 2026-09-11 ／ 作成者: orchestrator

## 目的
不動産（賃貸管理）テンプレートの前提であり、保守契約・サブスクにも使える汎用の「継続契約→毎月の売上請求書」。日割り（按分）と冪等な月次生成を持つ。

## 受入基準（EARS）
- AC-1 Document `contract` (naming `{ prefix: 'CTR-', period: 'year' }`): partnerId ref required, title text required, startDate date required, endDate date nullable, billingDay int 1..31 (31 = 月末; default 1) — the invoice **date**, billingTiming enum `advance | arrears` (default advance: 当月分を当月請求; arrears: 当月分を翌月請求), intervalMonths int default 1, prorationRule enum `daily | none` (default daily; `daily` = 当月の実日数で按分, `none` = 開始月/終了月も満額), roundingMode enum half_up/down/up (default down), status enum draft/active/ended/cancelled (allowOnSubmit), nextPeriod text `YYYY-MM` (allowOnSubmit; computed), note; lines `contract_line`: productId ref nullable, description required, quantity default 1, unitPrice money required, taxCategory enum required (from product when omitted), amount computed.
- AC-2 WHEN a contract is submitted THE SYSTEM SHALL require ≥1 line, set status active, nextPeriod = month of startDate. WHEN cancelled → status cancelled. Action `contract.end { id, endDate }` (allowOnSubmit update; endDate ≥ startDate) sets endDate and, if endDate < today's period start, status ended.
- AC-3 Action `contract.generate_invoices { period: 'YYYY-MM', contractId?, submit?: boolean }` (permission: sales create on sales_invoice; mutates) SHALL, for every active contract whose period is due (nextPeriod ≤ period, respecting intervalMonths, and startDate ≤ period end, and (endDate null or endDate ≥ period start)), create one `sales_invoice` via the sales module's public API (`ctx.repo` generic create with lines, then `runAction('sales_invoice.submit')` when `submit`): date = billing date of the period (billingDay clamped to month length; for `arrears` the following month), lines copied from contract lines with **quantity × proration factor** where factor = (days covered in the period) / (days in month) under `daily` (first month: from startDate; last month: to endDate; both inclusive), 1 under `none`; unitPrice unchanged; taxCategory copied; note `契約 CTR-… ${period} 分`. Amount rounding: sales computes amounts unrounded; the contract sets `quantity` to the exact factor (up to 6 decimals) — so a 100,000 円 rent for 10 days of a 31-day month gives amount 32,258.064516 → the **pack/sales rounding** decides the displayed yen. Because that is unsatisfying for rent, the contract line SHALL instead pre-round: `unitPrice = round(unitPrice × factor, roundingMode, 0 decimals when currency scale is 0)`, quantity kept — record the choice in the log and cover with a unit test (100,000 × 10/31 = 32,258.06… → down → 32,258).
- AC-4 Idempotency: entity `contract_billing` (contractId, period, invoiceId, unique (contractId, period)). A second call for the same period returns the existing invoice ids and creates nothing. After generation, contract.nextPeriod advances by intervalMonths. Output: `{ created: [{ contractId, invoiceId, number, total }], skipped: [{ contractId, reason }] }`.
- AC-5 Report `contract.schedule { period }` (TableResult): per active contract: partner, title, billing date, expected amount (税抜, prorated), status (`due | generated | not_due`).
- AC-6 Permissions: role `sales` all ops; `accounting` read; `viewer` read; admin all. Menus: 契約（契約一覧、請求予定）. Settings: `contract.default_proration` enum daily/none, `contract.auto_submit` bool (default false).
- AC-7 Tests: unit (proration factor with fast-check: factor ∈ (0,1], full month = 1, sum of factors over consecutive months from start to end equals total days/… (state the property you actually check); rounding cases), db (`daifuku_test_contract`): submit → active; generate for start month (proration), full month, end month; idempotent second call; arrears timing date; schedule report; sales invoice totals correct (tax via sales recalculation, e.g. 100,000 standard → tax 10,000; a `non_taxable` line has tax 0).
