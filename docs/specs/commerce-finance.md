# 商流・銀行照合・申告準備

状態: 実装・ローカル統合受入済み（2026-09-13）。検証結果は [作業記録](../log/2026-09-13-commerce-finance.md)、対応範囲と制約はこの文書を正本にする。

## 目的

見積/受発注から出荷/入荷、請求、銀行明細の照合、会計資料と申告準備まで、同じ会社の根拠伝票を追跡できるようにする。既存の請求・入出金・在庫・給与・会計機能を再利用し、実際に確認していない送金・申告を完了表示しない。

## 受入基準

- AC1: 利用者が見積/受発注を確定したとき、システムは会社、取引先、品目、数量、金額、税区分を検証して根拠を固定する。分納・分割請求では元明細と既処理数量を再検査し、超過/重複と在庫の二重転記を拒否する。
- AC2: 取引に後続伝票があるとき、システムは不整合になる直接取消を拒否する。正規の取消では既存の会計・在庫の反対処理と関連残数が同じトランザクションで整合する。
- AC3: 銀行明細を取り込むとき、システムは形式/日付/JPY金額/重複識別子を検査する。照合候補を利用者が確認するまで、入出金や消込を自動確定しない。再実行・並行実行で同じ明細を二重記帳しない。
- AC4: 支払用データを出力したとき、システムは対象と内容を固定し、出力と実送金を区別する。既存の入出金と照合する経路も持ち、二重記帳を避ける。
- AC5: 申告準備資料を作るとき、システムは対象期間/会社/根拠の版と未確認事項を記録する。対応年度/形式/計算条件を満たさない資料を公式取込用または申告完了と表示しない。再作成・訂正の履歴を残す。
- AC6: すべての入口（Web、REST、MCP、一覧、出力、関連参照）でRepository/Contextによる権限と会社境界を守る。銀行や申告の機微データを一般閲覧者へ追加公開しない。権限/会社変更後の画面から変更前の操作を実行しない。
- AC7: Webから新機能の開始、確認、原資料への移動、出力ができる。日本語/英語に対応し、狭い画面、入力保持、連打、通信失敗後の再確認に対処する。
- AC8: 既存業務データを保持する追加migrationを生成し、全gate、API/Webの型とビルド、主要Webシナリオ、既存版からの更新/復元を検証する。実測結果・未検証範囲を作業記録と操作マニュアルへ残す。

## 実装境界

商流、銀行、申告は各moduleの公開契約で結び、依存の循環を作らない。金額/数量はDecimal、確定資料は不変、監査と副作用は同一トランザクションとする。銀行資格情報のスクレイピング、実送金、実e-Tax/eLTAX送信は行わない。銀行APIは接続事業者/契約/認証方式を選定してから別途実接続を受け入れる。

今回の申告対応は公式仕様を確認できた形式に限定する。法人税別表・所得税申告の全自動計算、全銀行の固有CSV、全業種固有の取引、外貨/ロット/シリアルなどはこの追加だけで網羅したと扱わない。

## 検証

各領域の境界値・取消・重複・並行実行・別会社/役割の拒否を単体/DB試験に追加する。画面試験は合成データと専用DBで行う。実銀行や行政にデータを送信しない。資料の適合と実際の行政受理は別々に記録する。
