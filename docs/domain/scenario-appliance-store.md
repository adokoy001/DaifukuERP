# 電器店の実行台本：大福でんき（架空）

検証日: 2026-09-12。業務日: 2026-12-10〜11。販売・設置・修理を行う地域の電器店を想定する。名称、商品、製造番号、顧客はすべてサンプル。法令対応の検証ではない。

## 準備

会社のcore module/l10n seed実行後、`pack.apply { name: 'appliance_store', sample: true }`。Webの業界テンプレートから「電器店」を適用しても同じ。販売担当はsales、入金取消を行う担当はsales+accountingまたはadmin。閲覧だけならviewer。

サンプルは適用日の受付として、次の2件を用意する。自動試験はctx.nowを2026-12-10に固定する。既存の実データに上書きせず、同じコードがあれば作成を省略する。

| 種類 | コード | 内容 | 税抜販売単価 |
| --- | --- | --- | ---: |
| サービス | APP-REPAIR | 家電修理技術料 | 8,000円 |
| サービス | APP-INSTALL | 家電設置作業料 | 15,000円 |
| 商品 | APP-AIR | DF-AC26 エアコン | 90,000円 |
| 商品 | APP-FRIDGE | DF-RF26 冷蔵庫 | 70,000円 |
| 顧客 | APP-C001 | 山田 花子 | — |
| 仕入先 | APP-S001 | 大福家電卸 | — |

商品にメーカー・型番・保証月数、顧客機器にモデル・製造番号・設置場所がある。保証期限は自動推測しない。実物・保証書を確認して入力する。保守契約を参照させる場合は顧客が一致する必要がある。

## 1. 受付と作業

1. 「未完了・請求待ち」で修理と設置の2件を確認する。12-11を判定日にすると12-10予定の未完了受付は予定超過になる。
2. 修理受付を開き、症状、担当、予定日、作業・部品明細を確認する。`appliance_store.start_service { serviceId }`で作業中にする。
3. `appliance_store.complete_service { serviceId, completedDate: '2026-12-10', workReport: '点検・調整・試運転を実施し正常動作を確認。' }`。作業報告・完了日を保存して受付を確定する。先に作業を開始していない場合、空の作業報告、受付日より前の完了日では拒否される。
4. 未完了一覧では修理が「請求待ち」に変わる。確定した作業と明細は直接編集できない。

## 2. 請求と入金

1. `appliance_store.invoice_service { serviceId }`。完了日を請求日に使い、coreの売上請求書を作成・確定する。任意の`date`は完了日以降を指定できる。
2. 修理技術料8,000円の期待値は税抜8,000円、税800円、税込8,800円、未入金残8,800円。税率は既存tax seedの当日有効データで決まる。
3. 同じ受付の請求操作を再実行、または同時実行しても同じ請求書を返す。売上請求書・その仕訳は1件ずつ。
4. 設置料だけの受付は税抜15,000円、税1,500円、税込16,500円。同じ顧客の入金伝票をcore `payment.create/submit`で作り、`payment_allocation`に請求書と16,500円を指定して消し込む。

請求済受付を直接取り消すと、その請求を同じtransactionで取り消す。入金済みの場合は請求取消が拒否され、受付も完了のまま残る。入金を正規の訂正日で取り消してから受付を取り消す。請求書だけの単独取消は受付の依存関係が拒否する。

訂正例: `appliance_store_service.cancel { id: serviceId, correctionDate: '2026-12-11' }`。売上取消・逆仕訳・自動在庫戻しへ同じ日付を引き継ぐ。その後`appliance_store_service.amend { id: serviceId }`で新しい下書きを作る。受付状態は受付、請求紐付けは空になり、再開・完了・再請求する。

## 3. 本体販売と設置、仕入・在庫

在庫の自動入出庫を利用する場合、会社設定`inventory.auto_receipt_on_purchase`と`inventory.auto_issue_on_sales`を明示的にtrueにする。pack通常適用は保存済設定を保持する。試験では専用サンプル会社に`pack.apply { name: 'appliance_store', force: true }`でpackの3つの在庫既定値を明示適用する。

1. core仕入請求書にAPP-S001、APP-AIR×2、税抜単価60,000円を登録して確定する。税抜120,000円、税12,000円、税込132,000円。自動入庫2台、在庫評価120,000円。
2. 設置受付の明細に、既存の設置料15,000円に加え、本体APP-AIR×1、90,000円を登録する。
3. 作業開始→完了→請求。税抜105,000円、税10,500円、税込115,500円。物品だけが1台出庫され、サービス行は在庫を動かさない。残在庫1台、評価60,000円。
4. 未入金の受付を12-11有効で取り消す。在庫は2台へ戻る。仕入請求書と仕入債務はそのまま残る。

## 4. 無償・保証対応

同じ機器で新しい受付を作り、請求区分を「無償・保証対応」にする。請求明細は入れず、開始→報告→完了と進める。請求操作は拒否され、売掛金は作られず、未完了一覧から外れる。保証かどうかは受付担当が確認して判断する。無償部品の消費はcore在庫伝票で別途記録する。

## 回帰で確認する失敗経路

- 別のお客様の機器・保守契約、別会社の顧客への参照、未適用会社の固有actionを拒否。
- 公開経路から状態・請求ID・明細計算額を書き換えられない。数量ゼロ、古いversionでの開始、確定明細更新を拒否。
- 転記先売上科目を存在しないコードにした場合、請求作成全体をrollbackし、作業完了・未請求を保持。設定修正後は再実行可能。
- 何度sample/seedを適用しても既存商品・機器・受付の件数とversionを変えない。

実行: `TEST_DATABASE_URL_OWNER=... TEST_DATABASE_URL=... pnpm exec vitest run --project db packs/appliance-store/test`。専用検証DBだけを指定する。

## 今回扱わないもの

家電リサイクル券、電子申請、法令台帳、廃棄処理、メーカー保証の査定や請求、巡回経路、製造番号別の在庫、代替機貸出、分割請求。保証情報の入力は制度適合を保証しない。海外通貨・税制はcoreの現行範囲外。
