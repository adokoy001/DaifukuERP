# 日本の申告準備 — 根拠と対応境界

検証日: 2026-09-13。現行情報は以下の一次資料に固定する。

## 財務諸表

- [e-Tax 財務諸表CSVの作成方法](https://www.e-tax.nta.go.jp/hojin/gimuka/csv_jyoho4.htm): HOT010 Ver.3.0、2020-04-01以後提出分。CSVはe-Taxソフト等へ組み込む財務諸表で、申告書本体ではない。
- [レコード仕様9ページ](https://www.e-tax.nta.go.jp/hojin/gimuka/csv_jyoho4_5_1.pdf): 5列、必須冒頭行、整数金額15桁まで（符号込み16文字）、階層2以上で前行より2以上上げない、タイトル金額空欄、既存コードの重複禁止。独自科目は親の公式コードに正整数枝番を付せる。
- [一般商工業BS標準](https://www.e-tax.nta.go.jp/hojin/gimuka/csv_jyoho3/1/HOT010_3.0_BS_10.xlsx)、[PL標準](https://www.e-tax.nta.go.jp/hojin/gimuka/csv_jyoho3/2/HOT010_3.0_PL_10.xlsx)。国内formatterはこの一般商工業の限定分類を利用する。
- [財務諸表の送信方法](https://www.e-tax.nta.go.jp/hojin/financial_statements.htm): PDF添付を財務諸表電子提出形式の代わりにはしない。

初版は単体法人、JPY、税抜帳簿、損益振替前・期首損益残高ゼロの年度試算表を対象とする。仕訳から財務科目への分類は税理士/会計担当が確認する。資産と負債純資産に当期利益を含めた貸借一致、税引前/税引後損益を検算する。未対応の連結、業種固有の様式、注記・資本変動・法人税別表の不足を申告完了とは表示しない。

## 消費税

[国税庁No.6351](https://www.nta.go.jp/taxes/shiraberu/taxanswer/shohi/6351.htm)、[No.6383](https://www.nta.go.jp/taxes/shiraberu/taxanswer/shohi/6383.htm)、[No.6391](https://www.nta.go.jp/taxes/shiraberu/taxanswer/shohi/6391.htm)の令和7年4月1日現在法令等を参照した準備表。帳簿の仮受/仮払差額だけでは、割戻し/積上げ・課税売上割合・用途・調整・中間納付を反映した法定納付税額とはならない。本機能では税区分別帳簿集計と未分類検査を保存し、法定納付税額は未算定のままとする。原資料を欠く数字を補完しない。

## 給与の2026年分

- [令和8年分法定調書手引 第2章](https://www.nta.go.jp/publication/pamph/hotei/tebiki2026/PDF/02.pdf): 住所・カナ・未払給与・未徴収税額・前職・住宅等の記載規則。受給者交付用には個人番号を記載しない。
- [みなし提出特設ページ](https://www.nta.go.jp/users/gensen/hotei/index/minashi.htm): 2027-01-01以後の市区町村への給与支払報告書提出を源泉徴収票の税務署提出とみなす。旧eLTAX電子的一元化機能は2026年9月で終了。受給者交付は継続する。
- [公式375 CSV](https://www.e-tax.nta.go.jp/e-taxsoftweb/hoteichosho/csv2/web_375.pdf)、[標準フォーム](https://www.e-tax.nta.go.jp/e-taxsoftweb/hoteichosho/csv1/web_375.xlsx)は135項目を持つ。既存給与計算にない個人番号・家族氏名等を推定して埋めない。本版はこの公式取込ファイルを出力しない。
- [eLTAXの新特設ページ](https://www.eltax.lta.go.jp/news/01124)は調査環境では取得できず、2026年分の正式レイアウトを未検証。旧一元化CSVを新年度対応として使わない。

給与準備CSVはDaifuku固有の照合資料。支払証跡の暦年合計・確定年末調整・前職額・補足住所等と不足情報を保存し、公式申告を行う担当者へ渡す。全社員を実提出できること、源泉徴収票受給者交付用の正式帳票であることを保証しない。マイナンバーの収集/保管機能を含まない。

## 入力と出力の扱い

会計設定は会社全体の会計権限で保存する。法人名、単体・法人・税抜の確認、帳簿科目ごとの分類と出力名、根拠を入力する。対象年度の全会計期間が連続して存在し、締め済みであること、各転記仕訳の明細合計とヘッダー合計が一致することも検査する。作成者と別の会計担当が資料を確認した後に BS/PL の二つを出力できる。元資料変更後の再利用は拒否し、取消理由と前版参照を残して再作成する。期首損益科目残高ゼロと当期損益振替前の確認を要し、利益を根拠なく貸借差額の埋め合わせに使わない。

一般商工業の分類は、流動資産、有形固定資産、無形固定資産、投資その他の資産、繰延資産、流動負債、固定負債、資本金、資本剰余金、利益剰余金、自己株式、評価・換算差額等、新株予約権、売上高、売上原価、販売費及び一般管理費、営業外収益、営業外費用、特別利益、特別損失、法人税等の21種類。資産控除等は帳簿残高の符号を保ち、各分類の最終合計へ集約する。独自科目はその分類の先行する公式タイトル又は合計行の枝番として出す。出力名はこの限定 profile では全角 JIS 第1・第2水準、法人名50字、科目名100字まで。外字・半角・独立した濁点等は自動で置換せず修正を求める。

給与設定は給与本部権限で保存する。支払者所在地・連絡先、社員別カナ・住所・生年月日・自治体コード、未払給与と未徴収税額の有無/額、その確認根拠を補足できる。未確認は空欄で保存し、ゼロと区別する。準備 CSV にも支払者情報・社員別数値・共通/本人の未解決事項を含める。確定給与の支払証跡を暦年で抽出するため、前年12月勤務の当年1月支払を含み、当年12月勤務の翌年1月支払を除く。当年給与に支払証跡が欠ければ、分かる月だけの合計を年間金額とはせず未算定にする。正式申告の給与額をこの支払合計だけから決めず、未払額・支払期日・前職・年調資料を担当者が照合する。

## 資料版と検証記録

[形式データ](../../l10n/jp/src/filing/data.ts) に公式レコード PDF、BS/PL 標準 XLSX、2026年給与手引 PDF の URL・SHA-256・検証日を固定した。元ファイルの hash は資料の同一性を検出するためのもので、電子署名ではない。準備 snapshot に形式版とこの資料参照も保存する。

公式 XLSX の57コードを独立した [照合 fixture](../../l10n/jp/test/fixtures/hot010-v3-general.json) に抽出し、出力する全ての標準コード・行区分・階層を照合した。5列、タイトルの金額空欄、ゼロ合計、赤字、文字コード、桁、独自枝番、科目型、未分類、借貸と期間被覆を純粋テストで確認する。DB 試験では保存と別担当確認、source 変更、古い version、再試行重複、取消/再作成、権限分離、給与支払年境界、不足資料の null を確認する。

2026-09-13 03:05 JST、headless Chromium で公式 CSV ファイルチェックコーナーへ接続したところ「メンテナンス中」と表示された。ファイル選択画面に到達できず、公式チェックの形式受理は未検証。実申告・認証・送信は行っていない。実運用前に生成した財務諸表を公式チェックコーナーで確認し、不足する財務諸表・申告書を公式ソフト等で完成させる。
