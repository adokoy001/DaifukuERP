## 実製品比較で使う「ひっかけ」
1. **税込価格の税率ごと丸め**: レジ締めは税込で入力し、税額は「税率グループの税込合計 × 税率 ÷ (1 + 税率)」を締め（= 請求書）ごと・税率ごとに 1 回丸める。明細ごとに割り戻して丸めると差が出る（例: 税込 100 × 3 @8% → 22、行ごと 7 × 3 = 21）。製品が税込の明細ごとに丸めていないか。
2. **レジ締め 1 本で 売上 ＋ 在庫 ＋ 現金入金**: 1 回の submit で売上請求書（転記）・在庫の出庫・現金入金（消込と転記）がすべて起き、カード分だけが売掛金に残る。取消は 入金 → 請求書 の順に戻る（請求書・入金を単独で取消そうとすると「締めが参照している」で拒否）。製品で 1 操作になるか、3 伝票を手で作るか。
3. **返品の在庫戻し（Daifuku は未対応）**: REG3 の P4 −1 は売上・消費税からは差し引かれるが、在庫には戻らない（inventory は数量 ≤ 0 の行を出庫も入庫もしない）。棚卸で +1 の差異として吸収する。製品が返品で自動入庫するか。
4. **棚卸減耗**: P1 の 1 個紛失（−300）。Daifuku は棚卸の調整伝票で在庫を実地に合わせ、期末商品棚卸高は**実地の評価額**（7,700）で振り替えるので、減耗 300 は売上原価に含まれる（返品分 +150 と相殺された純額 −150 が効く）。6990 棚卸減耗損は seed するが `retail.close_month` は使わない（「帳簿棚卸高で振替 ＋ 棚卸減耗損 / 商品」の分離表示は手仕訳）。製品が減耗損を自動で分けるか。
5. **三分法の月次振替**: 初月は「商品 / 期末商品棚卸高」だけ、翌月から「期首商品棚卸高 / 商品」が加わる。同じ月の 2 回目は何もしない。過去の月を後から締めるのは拒否（期首・期末の連鎖が崩れるため）。
6. **カード売上の後日入金と手数料（未対応）**: カード会社（ext.retailKind = card_company）からの入金で売掛金 8,760 を消し込み、手数料を支払手数料に計上する処理はスコープ外（`retail.card_settlement` は未実装）。入金は payment で手作業、手数料は手仕訳。製品にカード会社別の精算機能があるか。
7. **会社設定の順序（導入手順のひっかけ）**: l10n/jp の seed が `tax.price_includes_tax = false`（税抜入力）を先に書くため、`pack.apply retail`（force なし）は「会社が既に値を持つキーは上書きしない」規則で税込入力の既定を**書かない**（`settings.kept`）。レジ締めは常に税込で計算するので本台本の数字は変わらないが、手入力の売上請求書の既定は税抜のまま。小売の会社は `pack.apply { name: 'retail', force: true }` か設定画面で true にする。

## 制限（スコープ外）
POS 連携、バーコード読取（JAN は ext に保持し検索できるだけ）、複数店舗（レジ締めの倉庫は既定の倉庫でなければ submit を拒否）、カード会社の入金と手数料、返品の在庫戻し、ポイント、適格簡易請求書（レシート）の発行【未確認: 小売業のレシートの記載事項の出典は未取得】。
