# 業界カタログの選定と業務境界

2026-09-12 / `feat/workforce-platform`。実装仕様は [industry-catalog.md](../specs/industry-catalog.md)、利用者の台本は [付録G](../manual/appendix-g-industry-catalog.md)。

## 選定の根拠

公的な区分を参照し、物品・契約・人数・時間・設備・現場など異なる業務単位を扱う15の入口を選んだ。順位は売上高・就業者数・事業所数の順位ではなく、主要区分をまたぐ実装上の選択である。全産業の網羅や、個別企業の産業分類判定を提供するものではない。

一次資料は総務省の [日本標準産業分類（2023年7月改定）検索](https://www.e-stat.go.jp/classifications/terms/10?op=search) と、総務省統計局の [令和6年経済センサス‐基礎調査 産業分類](https://www.stat.go.jp/data/e-census/2024/pdf/sanngyou.pdf)（分類構成・目次、PDF11・15ページ）を2026-09-12に確認した。後者は経済センサス用の分類なので、ここでは大分類との対応に限って参照する。対応表は当プロジェクトの解釈であり、統計機関による製品認定ではない。

## 共通に再利用する部分

追加10業界は、履行案件の受付・開始・完了・一度だけの請求・取消・実績集計を `modules/industry-operations` の factory で共有する。各パックは独立した伝票テーブルと、業界の実列・整合条件・品目種別・数量単位・請求期日の設定・台本を所有する。汎用JSONに業界名だけを保存する方式ではない。

金額はDecimal、数量は業界別の固定単位、通貨はJPYである。個数・人数・泊数は整数、支援時間・受託工数は0.25時間単位、一式案件は1。`<pack>.due_days` は0〜365日の支払猶予日数で、卸売45日、製造・建設・物流・クリニック・専門サービスは30日、その他は0日を初期値にする。既存設定は通常の適用で保存し、forceでも案件の進捗・入力値は上書きしない。

売上請求・税率解決・税丸め・仕訳・入金消込は既存モジュールを使う。案件が保存する税抜単価と明示税区分を請求明細へ転記する。案件レポートの履行金額は税計算前・未丸めであり、会計売上、利益、売掛残高とは別物である。履行完了したが未請求の案件も実績に含める。

## 業界固有の境界

- 卸売: 一案件一品目・一度の納品だけ。納品ロットは参照文字列であり、ロット別在庫や追跡の台帳ではない。納品の実績確定時には在庫を移動せず、既存の売上請求確定時に、会社の自動出庫設定が有効なら既定倉庫から出庫する。分納・返品・配送計画は含まない。
- 製造: 顧客から受けた加工仕事の受注個数を、合格数＋不合格数と照合する。合格数だけを請求するサービス品目。部材入庫・BOM・工程計画・仕掛品・製造原価・製品入庫を作らない。
- 建設: 独立した一工区を完了率100%で検収する。出来高途中請求・進行基準会計・工事原価・安全書類・許認可は扱わない。
- 運輸物流: 一件の一般貨物配送について、全個口の配達証跡を確認する。申告重量はkg入力、料金は合意した一式額。配車・運行管理・危険物や温度管理・運賃自動見積は扱わない。
- 宿泊: 到着日と出発日の日差を泊数にする、一客室の滞在実績。部屋参照は自由なコードであり、空室管理・重複予約防止・OTA・法定宿泊者名簿は含まない。
- クリニック: 法人健診の契約参照と実施人数に限る事務用入口。個人の診断・検査結果・患者記録・レセプト・保険診療請求を入力しない。一般の sales 請求を医療請求ソフトと呼ばない。
- 介護: 保険外生活支援の契約同意参照、支援場所参照、提供確認者の役割・記録参照だけ。保険給付・ケアプラン・要介護認定・医療記録は対象外。
- 教育: 団体向け一講座の契約・出席・人数請求。学籍・成績・教材在庫・月謝自動請求を含まない。
- 専門サービス・IT受託: 合意した成果物と顧客が受け入れた工数を請求する。従業員の労働時間そのものではなく、勤怠・給与・原価・プロジェクト損益と自動連動しない。
- 美容: 一回の施術メニュー・担当参照・完了確認を管理する。予約枠の競合・顧客カルテ・アレルギーなどの情報・回数券残高は扱わない。

医療・介護を含め、サンプルの標準税区分は架空演習用であり、各実取引の税務判断を表さない。実取引では契約内容に応じて税区分・料金を確認して設定する。今回の15入口の追加は、規制業務全体や海外会計への対応を意味しない。
