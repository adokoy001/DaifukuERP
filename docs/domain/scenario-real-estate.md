## 手順
1. **11-01** 期首 JE0: 元入金 500,000 → Dr 1100 普通預金 500,000 / Cr 3000 元入金 500,000。4 契約を確定（T1→T2→T3→T4 の順で CTR-2026-000001..4）。確定済みで終了していない契約があるので 4 部屋とも `occupied`（T2 は 11-11 入居予定の成約済み）。
2. **11-01** T1 は既存入居者なので `contract.generate_invoices { period: '2026-11', contractId: T1, submit: true }`（move_in は開始月 = 2026-04 を請求してしまう）→ INV-2026-000001。
3. **11-01** `real_estate.move_in { T3, depositReceivedDate: '2026-11-01' }` → INV-2026-000002（家賃＋礼金）、敷金 200,000 受領。`real_estate.move_in { T4 }` → INV-2026-000003。T3 入金 220,000（INV-2026-000002 に消込）。
4. **11-05** T1 入金 60,000（INV-2026-000001）。
5. **11-10** `real_estate.move_in { T2, depositReceivedDate: '2026-11-10' }` → INV-2026-000004（日割り家賃＋礼金）、敷金 65,000 受領。T2 入金 108,333（INV-2026-000004）。
6. **11-25** 12 月分を一括生成・確定 `contract.generate_invoices { period: '2026-12', submit: true }` → INV-2026-000005..8（契約番号順）。
7. T4 は 11 月分も 12 月分も入金しない。

導出:
- **請求日**: 契約モジュールは前払い（advance）の請求書を「対象月の billingDay」で日付づける。11 月分 = 11-01、12 月分 = 12-01。**12 月分は 11-25 に作るが請求日は 12-01**（生成日は業務日付ではない）。T2 の 11 月分は 11-10 に作るが請求日は 11-01（契約開始 11-11 より前。モジュールの規則をそのまま使う — 制限 3）。
- **支払期日**: partner の条件（31 日締め・当月・31 日）→ 11-01 の請求は 11-30 締め → 当月 30 日 = 11-30、12-01 の請求 → 12-31。
- **T2 の日割り**（ひっかけ 2）: 11 月は 30 日、入居 11-11〜11-30 は両端含めて 20 日 → 係数 20/30。65,000 × 20 ÷ 30 = 43,333.33… → 契約の端数処理 切捨て → **43,333**（単価を先に円に丸め、数量 1）。礼金 65,000 は日割りしない。税区分は住宅 → どちらも非課税、税 0、合計 108,333。
- **T3**（ひっかけ 4）: 家賃 100,000 と礼金 100,000 はどちらも事務所 → 課税 10%。1 枚の請求書の同じ税率の行をまとめて 1 回丸める: (100,000 + 100,000) × 0.10 = 20,000（端数なし）。この金額では行ごとに丸めても 10,000 + 10,000 = 20,000 で差は出ない。台本で確認するのは構造（仮受消費税の仕訳が税率ごとに **1 行** 20,000）。端数が出る例: 家賃・礼金が各 100,005 なら税率ごと 200,010 × 0.1 = 20,001 → 20,001、行ごと 10,000.5 → 10,000 × 2 = 20,000（1 円差。sales の golden テストの範囲、本台本ではアサートしない）。
- T4: 8,000 × 0.10 = 800 → 8,800。
- 12 月分は全月（係数 1）。T3 100,000 × 0.1 = 10,000、T4 800。

**判断（spec AC-8: 12 月分を 11-25 に作ったとき 11 月の集計に入るか）: 入らない。11 月は課税売上 208,000・税 20,800 が正しく、spec の対案「316,000・31,600」は誤り。**
1. システム上の発行日は請求書の日付で、契約モジュールは 12 月分を **12-01** に日付づける（11-25 は生成した時刻にすぎない）。集計表は仕訳日で集計し、売上の仕訳日 = 請求日なので、発行日基準で 12 月分は 12 月に入る。
2. 法令上も、家賃の資産の譲渡等の時期は「契約又は慣習によりその支払を受けるべき日」で前受けに係る額を除く（消費税法基本通達 9-1-20、docs/domain/real-estate.md#timing、逐語は【未確認】）。12 月分の家賃は 12 月の賃貸の対価で、この台本の支払期日は 12-31。仮に 11 月中に受け取っても前受けであり 11 月の取引ではない。
3. 31,600 は 11/01〜12/05（または 12 月末まで）の累計の仮受消費税で、試算表 11/01〜12/05 の 2200 残高として現れる（上表）。

## ひっかけ（比較用）
1. **住宅非課税・事務所課税・駐車場課税の混在**: 明細に税区分を書かず部屋の用途から既定（101/102 → 非課税、201/P1 → 課税）。誤ると 11 月の課税売上 208,000・非課税 168,333 が崩れる（全部課税にすると税 20,800 → 37,633）。駐車場は住宅に付随し家賃に含まれる場合だけ非課税（No.6226）。優先順位は「明細で明示 > 品目 > 部屋の用途」。
2. **月途中入居の日割り**: 11 月の実日数 30 日で 20/30、切捨て → 43,333。誤答例: 31 日で割る 41,935、11-10 起算で 21 日 45,500、日割りしない 65,000。請求日は 11-01（開始日前）。
3. **敷金（不課税・預り金）と礼金（売上）の区別**: 敷金 265,000 は 2500 預り金で請求書に載せない。礼金 165,000（T3 100,000 課税、T2 65,000 非課税）は売上。敷金を請求書に載せると売上が 265,000 増え、T3 分に税 20,000 が付く。v1 は礼金も家賃と同じ 4200 に乗る（4210 は用意だけ、制限 1）。
4. **同一入居者の家賃＋礼金を 1 枚の請求書で税率ごとに丸め**: T3 の請求書は 1 枚、仮受消費税は税率ごとに 1 行（20,000）。この金額では端数は出ない（上の導出）。
5. **滞納一覧と期日前請求の区別**: 12-05 時点の未入金 252,600 のうち滞納は 8,800 だけ。期日当日（11-30）は滞納ではない。支払条件を取引先の既定（月末締め翌月末払い）のままにすると 11 月分の期日が 12-31 になり、12-05 の滞納一覧が空になる。
6. **更新料（未対応）**: `ext.renewalFee` は記録のみ（既定 0）。更新時の自動請求は無い（spec スコープ外）。請求するなら請求書に明細を足し、税区分は礼金と同じ（住宅 非課税・事業用 課税、No.6225）。

## 台本の後（退去・敷金返還。テスト step 12）
- **12-25** `real_estate.move_out { T2, endDate: '2026-12-31' }` → 契約は active のまま（終了日が今月 1 日より前ではない）、部屋 102 は **occupied のまま**（終了日が過ぎていない）。12 月分は全月請求済みで過不足なし（月末退去）。
- レントロール asOf 2027-01-01: 102 は vacant（入居者なし、募集賃料 65,000 は合計に入れない）→ 合計 168,000 = 課税 108,000 + 非課税 60,000。
- **12-31** `real_estate.return_deposit { T2 の敷金, date: '2026-12-31', amount: '65000', deductionAmount: '22000' }` → Dr 2500 65,000 / Cr 1100 43,000 / Cr 4100 22,000。台帳: returnedDate 12-31、returnedAmount 43,000、deductionAmount 22,000。試算表 11/01〜12/31: 2500 −200,000（T3 分だけ残る）、4100 −22,000、1100 1,153,333 − 43,000 = 1,110,333。控除 22,000 は税区分なし（docs/domain/real-estate.md#deposit-deduction、【未確認】）。
- **2027-01-04** 同じ move_out を再実行 → 契約 ended（12-31 < 2027-01-01）、部屋 102 vacant。
- ガード: 敷金の二重返還・二重受領、同じ契約の二度目の move_in は INVALID_STATE。金額が敷金額と違う返還は VALIDATION（v1 は全額精算）。敷金台帳の受領日・金額の直接変更と受領済み敷金の削除、契約が付いている部屋の削除は INVALID_STATE。部屋の状態を汎用 update で書き換えても契約から導出し直される。

## 制限（v1）
1. 礼金も家賃と同じ 4200 に計上（sales は全明細を `sales.accounts.revenue` 1 科目に転記。4210 は未使用）。
2. 導入前からの契約（T1、2026-04 開始）の過去月を「請求済み」にできない: nextPeriod は 2026-04 のまま、`contract.schedule { period: '2026-05' }` に T1 が due で出る（テストで実測）。
3. 前払いの初回請求書は対象月の billingDay 付け（T2 は開始 11-11 より前の 11-01）。「翌月分を当月 25 日に請求」（前家賃）は表現できない。
4. 退去月を請求済みの後に月途中で退去すると過請求の調整（返金・赤伝）が無い（contract モジュールのスコープ外）。
5. 敷金は一括返還のみ。控除額の税区分・原状回復費の仮受消費税は手で仕訳。
6. 部屋の保存上の状態は「最後に部屋か契約が書かれた時点」の導出値。終了日が過ぎても何も書かれなければ occupied のまま（move_out の再実行や部屋の更新で直る）。レントロールは asOf で都度計算するので正しい。
7. 住宅の 1 か月未満の判定は明細作成時の契約期間で行い、後の contract.end では変えない。更新料の自動請求・管理会社モード（オーナー精算）は未対応。
