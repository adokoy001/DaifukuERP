# ADR-0001: モジュラーモノリス（単一デプロイ・単一DB・境界を静的解析で強制）

- 状態: 採択（2026-09-10）／ 確信度: 高
- 出典: research/02 §1（Shopify Packwerk、Spring Modulith、Outbox）

## 文脈
1人の設計者＋AIエージェント群で数十モジュールを作る。エージェントの変更を安全に受け入れるには「境界がテストで守られている」ことが前提。

## 決定
- 全モジュールを1リポジトリ・1プロセス（api/worker）・1 PostgreSQL にデプロイする。
- 依存は `apps → packs → l10n → modules → kernel` の一方向。`.dependency-cruiser.cjs` が違反をエラーにする。
- モジュール間は (a) 依存先モジュールの公開 index 経由の同期呼び出し、(b) outbox 経由のイベント、のいずれか。3段以上の同期連鎖は再設計の合図。
- モジュール間 FK は「依存先モジュールのテーブルへ」のみ許可（依存グラフは非循環）。

## 帰結
+ CI が境界違反を機械的に落とすので、エージェントのドリフトが構造には及ばない。
− 単一 DB は将来のサービス抽出・テナント別 DB 化の最大摩擦点。

## 最強の反論
Medusa 2.0 型「モジュール間 FK 全面禁止＋Link テーブル」を徹底しないと、結局は分散モノリス以下の密結合になる。→ Phase 2 の H3（コア無改変で業種パック）で検証し、破綻したら FK 禁止へ強化する。
