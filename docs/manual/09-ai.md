# 09 AI から使う（技術者向け）

商流・銀行・申告準備のactionと依存関係は [統合構造](../architecture/commerce-finance.md)、操作は [付録L](appendix-l-commerce-bank-filing.md) を参照してください。銀行候補の提示だけで消込を確定せず、取込/振込出力/申告資料の確認には対象・金額・根拠を人が確認する段階があります。ファイルを出力しても送金済み・提出済みとは報告しません。結果不明時は同じキーと内容で再試行し、別依頼で重複を作らないでください。

MFA登録済み利用者はパスワードだけでは起動できません。保護された環境変数で `DAIFUKU_MFA_CODE`（現在のTOTPまたは未使用回復コード）と `IDENTITY_ENCRYPTION_KEY` を設定します。回復コードは一回だけ使えます。会社/セッション/MFAの失効は接続後も再確認します。[認証の運用境界](../operations/enterprise-identity.md) を参照してください。

## 考え方: すべての操作は「アクション」

大福帳の業務操作は、すべて名前の付いた **アクション**（例 `sales_invoice.create`、`sales_invoice.submit`、`accounting.trial_balance`、`real_estate.move_in`）として定義されています。一つのアクション定義から、次の三つが自動で作られます。

- REST API: `POST /actions/<アクション名>`
- MCP ツール: 名前の `.` を `_` に置き換えたもの（例 `accounting_trial_balance`）
- 画面: 一覧・フォーム・レポート（v0.1 の画面が呼ぶのは台帳の基本操作とレポート、請求書の表示だけ）

入力の検査・権限・監査ログは、どこから呼んでも同じです。2026-09-11 のデモ環境では 229 のアクションがあり、MCP ツールも 229 個でした（内部専用のアクションは公開されません）。**画面にボタンの無い操作**（逆仕訳、年度の開設、入居・退去、家賃請求の作成、小売の月次締め、テンプレートの適用など）は、ここで説明する方法で実行します。

## MCP サーバを起動して接続する

MCP サーバ（`apps/mcp`）は標準入出力（stdio）で動きます。API サーバとは別のプロセスで、DB に直接接続します。

| 環境変数 | 必須 | 意味 |
|---|---|---|
| `DATABASE_URL_OWNER` / `DATABASE_URL` | ○ | `.env` から自動で読まれる（作業ディレクトリとその 3 階層上まで探す） |
| `DAIFUKU_EMAIL` / `DAIFUKU_PASSWORD` | ○ | エージェントが代理する利用者。その利用者のロールで動く |
| `DAIFUKU_AGENT_ID` | | 監査ログに残るエージェント名（既定 `mcp-agent`） |
| `DAIFUKU_COMPANY_ID` | | 会社（既定はその利用者の既定の会社） |
| `DAIFUKU_STORAGE_DIR` | | 添付の保存先（既定 `.data/storage`） |

起動コマンド（リポジトリの外からでも動くよう `-C` でディレクトリを指定）:

```sh
DAIFUKU_EMAIL=admin@example.com DAIFUKU_PASSWORD=password \
  pnpm -s -C /path/to/erp-experiment --filter @daifuku/mcp start
```

**`-s`（silent）を必ず付けてください。** 付けないと pnpm が `> @daifuku/mcp start` という行を標準出力に書き、MCP の通信路に JSON でない行が混ざります（2026-09-11 に SDK のクライアントで確認: エラーを報告しつつ接続は続いたが、厳密なクライアントでは失敗しうる）。

Claude Code に登録する例（**未検証**。コマンドの形は上と同じ）:

```sh
claude mcp add daifuku -e DAIFUKU_EMAIL=admin@example.com -e DAIFUKU_PASSWORD=password \
  -- pnpm -s -C /path/to/erp-experiment --filter @daifuku/mcp start
```

設定ファイル（`mcpServers` 形式）で書く例（**未検証**）:

```json
{
  "mcpServers": {
    "daifuku": {
      "command": "pnpm",
      "args": ["-s", "-C", "/path/to/erp-experiment", "--filter", "@daifuku/mcp", "start"],
      "env": { "DAIFUKU_EMAIL": "admin@example.com", "DAIFUKU_PASSWORD": "password", "DAIFUKU_AGENT_ID": "claude" }
    }
  }
}
```

接続すると、ツール一覧（説明は英語と日本語、`mutates: yes/no`、読み取り専用のツールには `readOnlyHint`）と、リソース `daifuku://meta`（全体のメタデータ）・`daifuku://entities/<台帳名>` が見えます。エラーは `isError: true` と `{code, message, hint, details}` で返るので、エージェントは `hint` を読んで入力を直せます。MCPもAPIと共通の実行環境設定を使い、`DAIFUKU_PACKS` の選択に従ってテンプレートを読み込みます。

## REST API の呼び方

```sh
# 1. MFA未登録の合成利用者でログインしてトークンを得る（12 時間有効）
TOKEN=$(curl -s -X POST http://localhost:3000/auth/login -H 'content-type: application/json' \
  -d '{"email":"admin@example.com","password":"password"}' | jq -r .token)

# 2. アクションを呼ぶ: POST /actions/<名前>、本文は入力の JSON
curl -s -X POST http://localhost:3000/actions/accounting.trial_balance \
  -H "authorization: Bearer $TOKEN" -H 'content-type: application/json' \
  -H 'x-agent-id: my-agent' \
  -d '{"from":"2026-10-01","to":"2026-10-31"}'
```

- `x-agent-id` を付けると監査ログに `agent` として残ります（エージェントから呼ぶときは付けてください）。
- 会社を切り替えるときは `x-company-id: <会社ID>` を付けます。
- 台帳の基本操作には短い形もあります: `GET /api/<台帳>?search=&limit=&offset=&orderBy=field:asc&where=<JSON>`、`GET /api/<台帳>/<id>`、`POST /api/<台帳>`（明細は `{"lines": {"<明細台帳>": [...]}}`）、`PATCH /api/<台帳>/<id>`（`{"patch": {...}, "expectedVersion": n}`）、`DELETE /api/<台帳>/<id>`、`POST /api/<台帳>/<id>/submit|cancel|amend`、`GET /api/<台帳>/<id>/audit`、`GET /api/<台帳>/<id>/related`（関連記録。参照先・参照元・訂正元・訂正版を台帳ごとに最大 50 件、超えたら `more: true`）。
- 関連記録は全台帳のアクション `<台帳>.related`（MCP ツール `<台帳>_related`、入力 `{"id": "..."}`）でも読めます。読めない台帳は結果に含まれません。辿り方は [データと処理経路](../architecture/runtime-and-data.md#関連記録の読取) にあります。
- マスタの CSV 取込（[spec](../specs/csv-import.md)、[ADR-0028](../adr/0028-import-port.md)）: `POST /api/<台帳>/import`（= `POST /actions/<台帳>.import`、MCP では `<台帳>_import`）。本文は `{"rows": [{"<項目名か日英ラベル>": "<文字列>"}], "mode": "dry-run" | "execute", "onExisting": "skip" | "update" | "error", "keyField"?: "<一意な項目>", "atomic"?: true}`。セルはすべて文字列（金額も `"1280.50"`）、空欄は指定なし。最大 5,000 行・2 MB・異なる列 500（超えると 400 / 413）。結果は `{mode, committed, keyField, summary: {created, updated, skipped, errors}, rows: [{line, status, id?, messages?}], notices}` で、`line` は 1 始まりのデータ行番号。`messages[]` の `code` は kernel のエラーコード、または `invalid_value`・`ref_not_found`・`ref_ambiguous`・`exists`・`immutable`・`unchanged`・`database`（データ・制約の SQL エラー）。対象は伝票・明細と、取込しないと宣言されたマスタ（在庫台帳・在庫残高・証憑）を除くマスタで、create 権限（`update` 指定時は update も、キーの列があれば read も）が必要。システムが設定する項目・`id` などの内部の列・追加項目（`ext.<key>`、キー、ラベル）の列は無視され、`notices` に理由付きで返ります。それ以外の不明な列は取込全体が 400 です。キーや参照のセルが `$ctx.` で始まる行は `invalid_value` になります。見出しの雛形は `GET /api/<台帳>/import-template.csv?lang=ja|en`。
- 証憑の検索（[spec](../specs/evidence-search.md)）: `attachment.evidence_search`（MCP `attachment_evidence_search`）は `{"txnDateFrom"?, "txnDateTo"?, "amountFrom"?, "amountTo"?, "partnerId"?, "kind"?, "superseded"?: "include" | "exclude" | "only", "incomplete"?: true, "limit"?: 1〜100, "offset"?}` を受け、指定した条件の AND で `{items, total, limit, offset}` を返します（金額は文字列）。各行は保存キーを含まない証憑の項目と、`linked`（リンク先の要約。読めない記録は `readable: false` で番号・名前を含まない）、`supersedes`（差替前の件数）、`incomplete`（取引年月日・取引金額・取引先のどれかが空）。`attachment.history { id }` は差替の履歴を最新版を根とする木で返し（`relation`: `self` / `newer` / `older` / `sibling`、最大 50 行と `truncated`）、差し替えられた版に監査ログの理由・日時・実行者を付けます。ファイル本体は `GET /api/attachments/<id>/download` で 1 件ずつ取得します。証憑の行の見え方は証憑の権限で決まり、リンク先の権限を継承しません（[制限事項](10-limitations.md)）。

  ```sh
  curl -s -X POST http://localhost:3000/api/partner/import -H "authorization: Bearer $TOKEN" \
    -H 'content-type: application/json' -H 'x-agent-id: my-agent' \
    -d '{"mode":"dry-run","onExisting":"skip","rows":[{"取引先コード":"P-001","名称":"大福商事","顧客":"はい","締め日":"20"}]}'
  ```

  エージェントには **必ず `dry-run` で結果を確認してから `execute`** させてください。`dry-run` は本番と同じ検査・フックを実行して巻き戻すので、DB は変わりません。`execute` で失敗した行だけが取り込まれず、`atomic: true` なら 1 行でも失敗すると何も残りません（`committed: false`）。ただし `dry-run` も実行と同じ行ロック・業務ロック（勘定科目なら会社全体の会計期間のロック）を要求が終わるまで持つので、5,000 行の確認（約 19 秒）の間は同じ会社の仕訳の登録や締めが待たされます。勘定科目など会計に関わるマスタは、営業時間中は数百行ずつに分けてください。
- エラーは HTTP ステータスと `{"error": {code, message, hint, details}}`。主なコード: `VALIDATION`（400、`details.issues[].path` に項目）、`NOT_FOUND`（404）、`CONFLICT`（409、同時更新・重複）、`INVALID_STATE`（409、状態として許されない操作）。
- 全エンドポイントの一覧は `GET /openapi.json`、ブラウザで見るなら `/docs`（Swagger UI）。

## `/meta` の見方

`GET /meta`（MCP では `daifuku://meta`）は、ログインした利用者から見えるシステムの全体像です。エージェントには最初にこれを読ませてください。

| キー | 中身 |
|---|---|
| `entities[]` | 台帳。`name`、`label`（ja/en）、`kind`（`entity` / `document`＝状態を持つ伝票）、`fields[]`（型、必須、既定値の有無、選択肢）、`ops`（この利用者に許された操作）、`lines`（明細台帳）、`extFields`（テンプレートが足した項目）、`views` |
| `actions[]` | アクション。`name`、`description`（ja/en）、`mutates`（データを変えるか）、`inputSchema`（入力の JSON Schema）、`resultKind`（`table` はレポート） |
| `modules[]` | モジュールとメニュー |
| `roles` | この利用者のロール |
| `packs[]` | 読み込まれたテンプレートと、この会社に適用済みか（`applied`） |

1 つの台帳だけなら `GET /meta/entities/<名前>`、設定は `GET /meta/settings`。

## エージェントに伝えておくこと

- **確定した伝票は消せません。** `DELETE` や `*_delete` は下書きにしか効かず、確定済みには `INVALID_STATE`（「Cancel the document instead」）が返ります。誤りは `cancel` → `amend`（訂正版の下書き）→ 修正 → `submit` で直します。
- **仕訳は取消もできません。** 手入力の仕訳は `accounting.reverse_entry { id, date? }` で逆仕訳を作ってから正しい仕訳を入れます。請求書・入出金などから自動生成された仕訳は、起票元の文書を取消します。単独の逆仕訳は拒否されます。
- 入金済みの請求書は取消できません。先に入出金を取消します。
- `submit` は帳簿（仕訳・在庫・請求書の残高）を動かします。人間の確認を取ってから実行させてください（v0.1 に承認の仕組みはありません）。
- `serverOwned` / `readOnly` の項目（請求書の `balance` / `status` / `paidAmount` など）は公開入力へ含めません。直接の書換えは拒否されます。入金は `payment` の作成と `submit` で反映させます。
- 画面と同様、保存・削除・確定・取消・訂正では取得時の `expectedVersion` を送って競合を検知してください。取消の `correctionDate` は任意で、空欄ならキーを省略します（元の取引日）。指定した場合はその訂正日を使います。
- 締めた会計期間の日付では確定できません（`INVALID_STATE`、`hint` に再開の方法）。
- 監査ログに残るので、試行錯誤は本番の会社でさせず、デモ用の会社か DB で行ってください。
- 必須の文字列項目に空文字 `""` を送ると受け付けてしまう場合があります（例: `partner.create {"name": ""}` が成功した）。入力は送る前に確かめさせてください。
- **期首残高の取込**（[opening-balances](../specs/opening-balances.md)）は 5 つの更新ツール `accounting_import_opening_balances`・`sales_import_opening_receivables`・`purchase_import_opening_payables`・`inventory_import_opening_stock`・`accounting_reverse_opening_balances` と、読取の `accounting_opening_balance_status` です。入力は `{ fiscalYearId, mode, rows }`（セルは文字列）で、日付は受け付けません（最初の会計年度の期首日の前日に固定）。**必ず `mode: "dry-run"` を先に実行し**、`rows` のエラー・`issues`・`clearingBalance` を人間に見せてから `execute` にさせてください。全件か無かで、1 行でもエラーがあれば何も書きません。直すときは取消と再取込で、`accounting_reverse_opening_balances` は開始仕訳だけを取り消します（期首請求書と期首在庫は各伝票の取消）。要求は 2 MB まで（MCP でも同じ上限）。
