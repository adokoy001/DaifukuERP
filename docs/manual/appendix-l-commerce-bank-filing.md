# 付録 L 商流・銀行・申告準備

[目次](00-index.md) / [日常業務](05-daily.md) / [月次](06-monthly.md) / [現在の範囲](10-limitations.md)

見積・受発注から分納と請求、銀行明細との照合、財務諸表・給与の申告準備へ進む手順です。現在の画面と公開actionに基づく案内です。銀行への送金や行政への電子申告は、この画面から実行しません。

## 入口と準備

| 画面 | パス | 担当と準備 |
| --- | --- | --- |
| 商流・受発注 | `/commerce/trade` | 販売はsales、仕入はpurchasing。取引先・物品・在庫単位・倉庫・勘定/税設定を用意 |
| 銀行連携・消込 | `/finance/banking` | 会社全体のaccounting。自社銀行口座と銀行勘定、振込先を確認 |
| 申告準備 | `/finance/filing` | 会計は会社全体のaccounting、給与はworkforce_payroll。作成者と別の確認者を用意 |

管理者も利用できます。商流が作成する請求・入出庫には、それぞれの既存業務の権限も必要です。銀行・申告準備は会社全体の資料を扱うため、店舗/拠点/本人だけに限定した所属では使えません。会計権限だけで給与の申告資料は表示されません。

会社名を確認してから始めます。画面は権限を定期的に確認し、所属が変わった場合は資料を隠して操作を停止します。通信エラーや版競合が出たときは、最新の原資料と履歴を確認します。処理結果が不明なまま同じ業務を新しい依頼として作り直さないでください。

既存環境には [安全な更新](../operations/setup.md) で移行0014を適用します。新機能のための銀行APIキーや電子申告資格情報の設定はありません。実データのCSV・口座情報・給与資料をソース管理へ置かないでください。

## 見積から受注・出荷・請求

初版はJPY、税抜単価、固定在庫単位の物品取引です。役務、外貨、単位換算、ロット/シリアル、返品専用工程は含みません。

1. 「商流・受発注」の「販売」から「見積を登録」を開き、取引先・日付・品目・数量・税抜単価・税区分を入力します。内容を確認し、見積を確定します。
2. 「確定済みの見積」で「受注へ引き継ぐ」を選び、受注日と希望納期を入力します。作られる受注は下書きです。原資料を開き、明細を確認して確定します。見積を経由しない場合は「受発注を登録」から販売の注文を作成できます。
3. 「注文と残数」で注文番号を選び、「出荷数量を入力」を開きます。倉庫・入出庫日・今回の数量を確認して実行します。空欄または0の明細は今回の処理に含みません。
4. 作成した履行の「請求数量を入力」から、請求日・支払期日・今回請求する数量を入力します。実行すると売上請求書が確定し、会計へ転記されます。
5. 残数明細と未請求明細を確認し、次の出荷・請求へ進めます。入金は従来の入出金画面、または銀行明細からの確認消込で記録します。

例えば10個の受注から6個を出荷し、そのうち4個を請求すると、未出荷は4個、出荷済み未請求は2個です。商品単位の残数を管理し、異なる単位の数量をまとめて足しません。注文の金額は見込額で、請求の税額は請求日の条件で計算します。

出荷で在庫を減らし、請求で同じ在庫を再び減らすことはありません。従来の単独請求による在庫処理も残っていますので、同じ取引を単独請求として重ねて入力しないでください。

## 発注・入荷・仕入請求

1. 「仕入」へ切り替え、「受発注を登録」で購買方向の注文を入力・確定します。
2. 注文番号を選び、「入荷数量を入力」で倉庫・入荷日・今回数量を指定します。分納のたびに別の履行が作られます。
3. 入荷済みの履行から「請求数量を入力」を選び、仕入先請求番号、請求日、支払期日、請求数量を確認します。
4. 仕入請求書の原資料と残高を確認します。支払予定ファイルを作る場合は銀行画面の「振込準備」へ進みます。

入荷で在庫が増え、仕入請求で会計へ転記されます。入荷だけでは会計仕訳を作りません。入荷時の未請求債務や原価差額の配賦、自動の三点照合は含みません。実務上の検収や収益認識の判断も、この数量処理だけで自動認定しません。

## 商流を訂正する

元の履歴を残して、後続から順に取り消します。

1. 銀行照合があれば解除します。入出金が残る請求は、先に経理担当者が整合する入出金取消を行います。
2. 商流画面の「この請求を取消」で訂正日と理由を記録します。請求だけの取消では在庫は戻りません。
3. 入出庫も戻す場合は、履行の請求をすべて取り消してから「履行を取消」を使います。
4. 注文自体の取消が必要なら、後続が整合した状態で注文の原資料から行います。

商流から生成された請求や入出庫を、汎用画面で独立して取消・改訂することはできません。訂正日は元の処理や先に行った取消より前に戻せず、締め済み期間の規則も適用されます。

残りの数量だけを打ち切る場合は「残数を終了」を選び、理由を入力します。既存の履行・請求は残ります。履行済みの未請求分は、注文終了後も請求できます。

## 銀行口座と振込先を登録する

「銀行連携」の「口座設定」で、自社口座に銀行/支店コード、預金種別、口座番号、名義、会計の銀行勘定を登録します。全銀出力には依頼人コードなどの確認情報も必要です。振込先は取引先に対応させ、銀行資料で確認した内容と根拠を保存します。

通常一覧では口座番号を伏せて表示します。修正時は口座番号全体を再入力して確認します。使用済み自社口座の銀行識別情報や勘定を差し替えることはできません。別口座として登録し、不要な旧口座を無効にします。

この登録は振込先の銀行照会や名義の真正性確認を行いません。銀行の正式な案内と照らして入力してください。

## 明細CSVを確認して取り込む

「銀行明細」で自社口座を選びます。初版は銀行各社のダウンロードCSVをそのまま読む方式ではなく、次の指定形式を使います。

```csv
externalId,bookedOn,direction,amount,description
SAMPLE-20260901-001,2026-09-01,receive,11000,架空取引先からの入金
SAMPLE-20260902-002,2026-09-02,pay,6600,架空仕入先への支払
```

`bookedOn` は明細日、`direction` は入金receive/出金pay、`amount` は正の整数円です。`externalId` は口座内で一意となる明細識別子を用意します。銀行の照会番号が日付をまたいで重複し得る場合は、そのまま一意キーとして使わず、安定して同じ明細を識別できる変換を行います。[銀行明細の注意点と仕様](../domain/japan-bank-integration.md)。

1. サンプルとヘッダーを確認し、UTF-8のCSVファイルを選びます。ブラウザーでは256KiB、取込は最大500明細です。金額の桁区切りや通貨記号は付けません。
2. 事前確認を実行し、選択口座、明細日、方向、金額、摘要、重複と合計を確認します。この時点では取込は未確定です。
3. 確認した内容を確定して取り込みます。口座設定や資料が変わった場合は事前確認からやり直します。
4. 明細一覧で未照合の行を確認します。取込だけでは入出金伝票や仕訳を作りません。

同じ識別子・同じ内容の再取込は重複として扱い、増やしません。同じ識別子で金額などが違えば拒否します。取り込んだ明細自体は書き換えず、誤照合は次の解除操作で訂正します。

## 候補を確認して消し込む

未照合明細から候補を開き、取引先・日付・方向・金額と原資料を確認します。金額が近いという理由だけで自動確定しません。

| 選ぶ対象 | 実行される処理 |
| --- | --- |
| 既存の確定済み入出金 | 明細と入出金を関連付ける。新しい仕訳は作らない |
| 未決済の請求書 | 明細金額と残高を検査し、入出金を作成・確定して消込する |

請求書を選んだ場合は入出金の計上日と理由も確認します。既定は明細日です。以前の取消後に再照合する場合は、取消日以降の有効な計上日を指定します。銀行明細の日付は変更されません。再実行中に対象の版や残高が変われば、内容を読み直すまで確定できません。

解除するときは訂正日と理由を入力します。既存入出金への照合なら関連付けだけを外します。この機能が請求書から作った入出金なら、同じ操作で入出金も取り消します。解除済みの旧操作を再送しても、その後の新しい照合を取り消しません。

## 振込ファイルを作成する

1. 「振込準備」で自社口座、振込日、未払の仕入請求、登録済み振込先を選びます。初版は請求ごとの未払残額全体を対象にします。
2. 件数・金額と対象請求を確認してバッチを作ります。この時点で送金や支払伝票は作成されません。
3. バッチを開き、自社口座・依頼人情報、各振込先の銀行/支店・預金種別・口座番号・名義、金額を全体で確認します。
4. 出力形式を選び、確認欄にチェックしてファイルを取得します。初回出力時には残高と原資料の変更を再検査します。
5. 銀行サービスで別途取込・承認・結果確認を行います。Daifuku上の「出力済み」は銀行の受付や実行を意味しません。

全銀は総合振込の120バイト固定長、Shift_JIS、普通/当座口座に限定します。改行なし/CRLFは銀行の指定に合わせます。文字は許可された半角英数・カナ等だけで、長さを超えた名前を黙って切り詰めません。指定CSVはUTF-8・CRLFで、銀行固有形式とは限りません。[SMBCの全銀形式](https://bqa.smbc.co.jp/faq/show/2505?site_domain=web21lite)、[MUFGのバイト・改行仕様](https://web.bizstn.bk.mufg.jp/biz/help/pdf/form_3_1_2_20080512.pdf)。

出力済みバッチの再取得は、保存した形式・改行・同じ内容のファイルです。銀行へ重ねて取り込まないでください。バッチを取り消しても銀行側の依頼は消えません。出力後に変更したい場合は、銀行での受付・取消状況を確認してから社内バッチを整理します。

実銀行APIとの契約・接続や各銀行への取込受入は未検証です。実際の入出金を確認した後に、従来の入出金処理または明細との確認消込で記帳します。

## 会計の申告準備

「申告準備」の「会計・財務諸表」は、一般商工業の単体法人・JPY・税抜帳簿を対象にします。出力対象はHOT010 Ver.3.0の貸借対照表と損益計算書です。国税庁は財務諸表の取込CSVと作成・確認・提出の手順を別々に案内しています。[国税庁の公式案内](https://www.e-tax.nta.go.jp/hojin/gimuka/csv_jyoho4.htm)。

1. 「作成条件・補足情報」を開き、出力仕様・法人名・各勘定科目の財務諸表区分と出力名を設定します。推定した対応をそのまま採用せず、確認根拠を記録して保存します。
2. 対象年度の帳簿を点検し、会計期間を締めます。当年度の損益振替をまだ転記していない状態を対象にします。期首の収益/費用残高も検査されます。
3. 「準備資料を作成」で対象年度、消費税区分と例外項目の確認記録、損益振替前であることを確認します。
4. 「根拠と検算を確認」で貸借対照表・損益計算書・原資料・未解決事項を確認します。科目対応や帳簿を訂正した場合は「最新資料で再作成」します。
5. 作成者と別の担当者が「資料の確認へ」から根拠を記録し、検算と注意事項を確認します。エラーが残る資料は確認完了にできません。
6. 確認済み資料の「ファイルを取得」から「最新の根拠を検査して出力」を実行し、BS/PLの各ファイルを取得します。

出力はShift_JISです。出力できない文字、桁数、未設定の科目対応を勝手に置き換えません。作成後に原資料や設定が変わった場合は、確認済みでも再出力を停止します。過去の資料を残して新しい版を作り、別担当者が再確認します。

この機能は法人税申告書全体、税額計算書、資本変動計算書、個別注記を作成しません。帳簿上の消費税集計を法定納付税額として扱いません。公式ソフトでの取込・不足書類の作成・送信・受付確認は別途必要です。e-Tax実環境での取込受入は未検証です。[実装範囲と一次資料](../domain/japan-tax-filing.md)。

## 給与の申告準備

「給与の申告準備」は2026年の確定給与・年末調整を基に、独自の確認資料を作ります。給与計算月ではなく支払日の属する年で対象を集めます。給与・年調を確定する操作は [付録I](appendix-i-fiscal-and-work-systems.md) を参照してください。

1. 「作成条件・補足情報」で対象年と給与支払者の名称・所在地等を保存します。
2. 各従業員について、確認できた氏名カナ・住所・生年月日・市区町村コード、未払給与額・未徴収税額と確認根拠を入力します。未確認は空欄、0円を確認した項目は0とします。マイナンバーは入力しません。
3. 「準備資料を作成」で全従業員・給与・年末調整の対象範囲を確認します。
4. 根拠と検算で不足資料を点検します。確定給与や年末調整が不足している場合は、元資料を整えて再作成します。当社の給与と前職分は区別して表示・出力します。
5. 作成者と別の給与担当者が資料を確認し、最新根拠の再検査後にCSVを取得します。

出力は **Daifuku独自の給与申告準備CSV** です。公式375/eLTAXへ直接取り込めるCSVや正式な源泉徴収票ではありません。公式ソフト等で必要書類を作成し、別途提出します。「資料確認済み・未提出」や資料取消は、行政への提出・受理・取下げを記録する状態ではありません。[対応する資料と未対応形式](../domain/japan-tax-filing.md)。

## 検証状況

2026-09-13に全gate（単体793件・DB623件等）、0014への移行/導入/復元、通常ブラウザー55件と追加競合3件、認証専用3件が成功しました。商流・銀行・申告の新規画面試験11件では分納/請求、消込/解除、同一ファイル再取得、設定の同時編集、取消や読取失敗後の出力停止を検証しています。測定範囲は [STATUS](../STATUS.md) と [作業記録](../log/2026-09-13-commerce-finance.md) を参照してください。実送金・電子申告は行っていません。
