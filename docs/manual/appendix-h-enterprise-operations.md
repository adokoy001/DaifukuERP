# 付録 H 認証・POS・連結・FCを使う

この章は2026-09-12の企業運営拡張です。旧章で未対応と記載されたSSO/MFA、メール、POS、連結、FCは、以下の限定した範囲を追加しています。[実装仕様](../specs/enterprise-commerce.md) と [認証の導入](../operations/enterprise-identity.md) に上限・復旧範囲を記載しています。

## 認証アプリと組織アカウント

1. 「自分のアカウント」へ進み、「認証アプリを登録」で現在のパスワードを確認します。QRまたは手動キーをアプリに登録し、6桁コードを入力します。
2. 表示された10件の回復コードを安全な場所へ保管します。表示は一度だけです。全端末からログアウトするため、再ログイン時に認証アプリか未使用回復コードを使います。
3. 組織SSOは、運用者が接続先を設定した後、「組織アカウントを紐付け」で本人確認し、組織の認証画面へ移動します。紐付け後はログイン画面の組織ボタンを使えます。MFA登録済みならSSOでも追加確認します。

設定変更では現在のパスワードと、登録済みならMFAが必要です。メールアドレスの一致だけでは既存アカウントへ紐付けません。SSO紐付け後もパスワードを保管してください。全員MFA強制、SSO専用アカウント、すべての回復手段を失った場合の管理復旧は初版に含まれません。

## 招待とパスワード再設定

管理者は「利用者・権限」(`/admin/users`) の「メールで招待」に氏名・メールを入力し、本人確認します。受信者が24時間以内にリンクからパスワードを設定した後、管理者が会社と業務権限を割り当てます。招待だけで管理者や会社所属にはなりません。未受理の招待は同じメールで再発行でき、古いリンクは使えなくなります。

ログイン画面の「パスワードを忘れた方」から再設定メールを依頼できます。メールの30分以内のリンクで新しいパスワードを設定すると全端末のログインが失効します。MFAは解除されません。同じメールが複数組織にある場合は組織IDを指定します。

「配送待ち」は受信済みを意味しません。運用者が暗号鍵・公開HTTPS URL・SMTPを設定し、配送CLIを実行する必要があります。未設定なら未配信と表示します。[設定/メールworker/再試行](../operations/enterprise-identity.md) の手順を参照してください。

## Square POSの導入

POS画面 `/commerce/pos` は、決済通知の受信と仮勘定への仕訳を扱います。Square決済総額から税率別売上、商品、在庫を推定しません。

1. 会社の勘定科目を確認し、決済の受入側と相手側に使う仮勘定を用意します。POS画面で内部店舗とSquare merchant/locationを登録します。内部店舗は飲食テンプレートの店舗マスタとは別です。
2. 運用者がサーバーの `SQUARE_POS_CONNECTIONS_JSON` に、接続key、tenant/user/company、内部POS店舗UUID `locationId`、Square `merchantId` / `externalLocationId`、正規HTTPS通知URL、署名鍵を設定します。専用利用者には必要な会社所属とPOS/会計の業務権限を与えます。
3. Square側へ `https://導入先/webhooks/square/<key>` を正確に登録します。通知URLと署名鍵は登録値そのものを使い、リバースプロキシのhostから推定しません。raw本文を変形せずAPIへ渡します。
4. 導入先のSquare検証環境で完了決済、返金、重複通知、停止中の再送を確認した後、限定した店舗から導入します。リポジトリの合成試験だけでは実加盟店への接続完了になりません。

通知画面で受信履歴と処理状態、生成仕訳を確認します。未完了通知は履歴だけを保持します。返金が先着した場合は決済待ちに残し、元決済後に再処理します。失敗は内容を変えず再試行し、期間締め等の原因を先に確認します。取消は日付と理由を記録し、元仕訳を反転します。元金額を超える累積返金や同じ外部IDの内容すり替えは拒否します。

原資料日はSquareの取引作成日時を日本時間へ変換した日です。通知受信日へ付け替えません。providerの配信期間を過ぎた未受信資料をAPIから回収する機能はありません。受信の監視と照合を運用手順に含めてください。

## 管理用連結精算表

`/commerce/group` で、同じテナントのJPY会社を選びます。選択する全会社に会社全体の所属と会計資料の閲覧権限が必要です。店舗・拠点だけの所属では連結資料を利用できません。

1. 全社で同じ完全な会計期間を選び、単体試算表を取得します。20会社、各2000勘定/240会計期間/終了日以前のposted明細20000件が上限です。超過時は部分合計を返しません。
2. ゼロ残高を含む全勘定へグループ科目を対応させます。消去/調整は確認済みの根拠と貸借一致の明細を入力します。会社間取引をシステムだけで相殺対象と決めません。
3. 下書きを保存し、単体資料、mapping、消去調整、連結後の貸借を確認します。確定前に各社の対象期間と期首残高へ寄与する過去期間を締め、資料を取り直します。
4. 最新の資料で確定します。元帳や科目の版が変わった下書きは再作成を求めます。訂正は理由付き取消と新しい精算表で記録します。元の単体帳簿は書き換えません。

保存済み資料も表示のたびに全社の権限を再確認します。所属を失うと過去snapshotからも詳細を読み取れません。出力されるのは管理用精算表であり、法定連結財務諸表、連結範囲の判定、資本連結、持分法、のれん、税効果、外貨換算は含まれません。

## フランチャイズ精算

`/commerce/franchise` で契約、確認売上、月次精算を管理します。accounting権限に加え、本部請求はsales、加盟店支払はpurchasingなど、既存伝票の操作権限が必要です。

1. 取引先・請求品目・勘定・税設定を準備し、契約に有効期間、請求/支払の立場、税込/税抜売上基準、料率、定額、端数規則と課税区分を登録します。
2. 月次売上は承認済み資料と照合した税込/税抜額、資料番号、説明を保存します。資料の金額をPOSの決済総額から自動変換しません。参照番号を書いても既存伝票の自動集計/照合は行いません。
3. 精算額と根拠を確認して確定し、生成した請求書へ進みます。同じ契約/月の二重操作で請求を重複させません。
4. 実際の入金/支払を確認して残額の決済を記録します。取消はFC精算から支払→請求の順で行い、別経路の未整理入出金が残る場合は先に対応します。

月全体が有効な契約の正の精算料に限定します。月途中の定額按分、ゼロ額請求、相手会社への両側記帳、全オープンアカウント相殺は含めません。使用済み契約の改変は拒否し、将来の条件は新しい契約コードで登録します。

## 検証の読み方

2026-09-12時点で認証は合成OIDC/JWKS、検証付きTLS SMTP、ブラウザーの実操作で確認しています。POS・連結・FCのこの操作説明は仕様/コードから整理したものです。個別DB/adapter試験と統合ブラウザー/gateの最終結果は [現在地](../STATUS.md) と作業記録を確認してください。Entra/Googleの実アカウント、Square実加盟店、実SMTP事業者との接続は未検証です。
